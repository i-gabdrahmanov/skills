# 1.5 — Pixso → канон: краски, типографика, токены стилей

**Этап:** 1 · **Зависит от:** 1.3 · **Статус:** done
**Спека:** §7.2 (Краски, Типографика), §6.5, §6.3 (style/font/color) · **INV:** B13 (тексты), основа B18 ·
**QG:** U2, F1

## Зачем
Verify сравнивает цвета, шрифты, радиусы и тени с допусками в 2 единицы — значит, канон обязан
нести их точно и в одной форме для всех источников.

## Что сделать
- Масштаб каналов определяется ОДИН раз на файл (в образце r,g,b — 0..255, a — 0..1); цвет →
  `rgba(…)`, альфа до 3 знаков; невидимые краски (`visible:false`, нулевая непрозрачность)
  пропускаются; несколько заливок — верхняя видимая; image-fill → kind=image.
- Градиент → CSS-gradient со всеми stop'ами; per-corner radius (`rectangle*CornerRadius`) — массив
  только при различии углов; обводка → border (`strokeWeight`, `strokePaints`, `strokeAlign`,
  `border*Weight` по сторонам); тень (`effects` DROP_SHADOW: offset, radius, spread, color) → одна
  строка CSS box-shadow; opacity.
- Типографика: `fontFamily`, `fontSize`, `fontStyle` → вес числом (Regular 400, Medium 500,
  Semibold 600, Bold 700…) и italic по имени; `lineHeightNumber/Unit` (PIXELS/PERCENT/auto);
  `letterSpacingNumber/Unit` (PERCENT → доля размера); `textAutoResize` → hug; цвет текста — из
  заливки узла.
- Слоты `component.content` (из 1.4) получают `font` и `color`: из текстового узла мастера с
  учётом оверрайдов цепочки (`fillPaints: []` в записи оверрайда — не «нет цвета», а наследование от
  стиля/мастера: проверить на образце), чтобы build выбирал caption/value по типографике, а не по
  порядку. Предикаты видимой заливки/обводки уже в `ingest/paint.py` — использовать их.
- Токены: `inherit{Fill,Text,Stroke,Effect}StyleID` → имя из `localStyleMap`
  («Static/T&I/Base/Primary», «Text/B1») в `style.tokens`/`font.token`; значения, которых узел
  не несёт, берутся из стиля; значение узла сильнее токена.

## Готово, когда
- `test_paints_typography.py`: на фикстуре — шрифт SB Sans Text, размеры и веса числами, цвета
  rgba, токены у узлов со ссылками на стиль, тень корня модалки одной строкой; синтетика: масштаб
  0..1 vs 0..255 в одном файле не смешивается, градиент со всеми stop'ами, радиус-массив только
  при разных углах, процентный трекинг → доля.

## Результат
`daiver/ingest/style.py` (класс `Styler`, `detect_color_scale`, `overlay`), правки `ingest/pixso.py` и
`ingest/materialize.py`; `test_paints_typography.py` (62). Правила выведены по данным образца и сверены
с его картинкой (docstring `style.py`, README фикстуры); тесты мутационно проверены (масштаб, альфа, порядок
углов, пустой список оверрайда, проценты, токены — каждое ловится).
- **Канон образца.** Корень — `background rgba(255, 255, 255, 1)`, `radius 16`, `border {1, rgba(31, 20, 51, 0.12),
  inside}`, `shadow` одной строкой из двух слоёв; шапки — `radius [16, 16, 0, 0]`, блок действий — `[0, 0, 16, 16]`
  (порядок углов CSS: tl, tr, br, bl; отсутствующий угол = 0). Слоты `content` получили `font` и `color`: заголовок
  `Fixture Sans 20/600, lineHeight 24, letterSpacing -0.5, token Headline/H2`, `rgba(31, 20, 51, 1)`; описание
  `13/400, rgba(31, 20, 51, 0.55)`; подпись главной кнопки белая.
- **Единые правила.** Масштаб каналов — один раз на файл по ВСЕМ цветам (стили, эффекты, stop'ы, записи
  оверрайдов); эффективная альфа краски — меньшая из `color.a` и `opacity` (они дублируют друг друга: 0.12/0.12);
  невидимые и нулевые краски пропускаются; вес шрифта числом (`Semibold` → 600, `Bold Italic` → 700 + italic),
  неизвестное имя не угадывается (без `weight`, имя в `stats.styles.unknownFontStyles`, предупреждение одно);
  line-height/letter-spacing в px, проценты — доля размера шрифта, нулевой трекинг не пишется.
- **Токены.** `tokens` (fill/text/stroke/effect) на узле и `font.token` у текста — только если стиль найден в
  `localStyleMap` и узел реально показывает то, что стиль красит; стиль, которого в экспорте нет (у корня образца
  три библиотечных: fill/stroke/effect), имени не даёт — токен не выдумывается, различные id считаются в
  `stats.styles.unresolvedStyles`. Значение узла сильнее стиля; чего узел не несёт — берётся из стиля.
  Отклонение от текста задачи: токены лежат на узле (`tokens`), как в схеме 1.1, а не в `style.tokens`.
- **Оверрайды.** Пустой список краски в записи оверрайда — «не переопределено», а не «нет заливки» (у заголовка
  шапки образца так, а на картинке цвет есть); у самого узла пустой список — настоящее «нет». Новый
  `inheritFillStyleID` без собственной краски в записи отбрасывает устаревшую краску мастера (её даёт стиль).
  То же правило применено к материализации 1.4 (`paints` корня) и к анатомии local.
- **Остальное.** image-fill → `kind=image` без `background` (для frame/rect/vector; инстанс остаётся инстансом);
  вектор — цвет в `color`; эллипс — радиус половины короткой стороны; иконка (1.4) несёт только `component`;
  `DROP_SHADOW`/`INNER_SHADOW` → `box-shadow` (inner — `inset`), размытие слоя/фона не тень (счётчик
  `effectsDropped`); обводка по сторонам (`border*Weight`) сильнее `strokeWeight` и схлопывается в число, если
  стороны равны; `opacity` узла <1 → `style.opacity`.
- **Не проверено данными (допущения названы):** порядок нескольких заливок (образец — не более одной на узел;
  берётся первая видимая, как у детей «topmost first», число таких узлов — `counts.multiFill` + предупреждение);
  направление линейного градиента (из `startPt/endPt`, иначе без угла, `counts.gradientAngleUnknown`; заливочных
  градиентов в образце нет, есть только 4 угловых у обводок); процентные единицы шрифта (в образце только
  PIXELS); image-fill (в образце нет); стили обводки/эффектов как записи `localStyleMap` (в образце только FILL
  и TEXT). Нужен образец с этими случаями — в README «Нужно от пользователя».
