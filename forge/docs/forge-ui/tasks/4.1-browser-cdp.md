# 4.1 — Браузер: поиск Chromium и CDP-клиент на stdlib

**Этап:** 4 · **Зависит от:** — · **Статус:** done
**Спека:** §14.2 (`daiver_capabilities`), §20.5 (без загрузок) · **INV:** F11, A8 · **QG:** N8

## Зачем
Verify меряет настоящую страницу. В оригинале — playwright-core; у нас Python stdlib, поэтому свой
тонкий клиент Chrome DevTools Protocol к браузеру, найденному на машине.

## Что сделать
- `daiver/browser/find.py`: порядок — env `CHROMIUM_EXECUTABLE_PATH` > `verify.browserPath` /
  `browserChannel` конфига > стандартные пути (macOS: Google Chrome/Chromium.app; Linux: chromium,
  chromium-browser, google-chrome; Windows: Program Files). Ничего не скачивать и не ставить.
- `daiver/browser/cdp.py`: запуск headless (`--headless=new --remote-debugging-port=0
  --user-data-dir=<tmp> --no-first-run --no-default-browser-check --hide-scrollbars
  --force-device-scale-factor=1`), порт из `DevToolsActivePort`; WebSocket на stdlib (HTTP Upgrade,
  маскирование, фрейминг, фрагментация, ping/pong); JSON-RPC CDP (id/method/params, события);
  создание target и attach; домены Page, Runtime, Emulation, Input, DOM; таймауты; гарантированное
  закрытие процесса и удаление профиля.
- Инструмент **`daiver_capabilities()`**: `{browser:{found, path, version, source}, node, typescript,
  playwright, vision}` + предупреждения; `found:false` — цикл verify не стартует.

## Готово, когда
- `test_cdp.py`: приоритет поиска на фейковых исполняемых; кодек WebSocket (маска, фрагменты,
  большой payload); интеграционный — запуск, `data:`-страница, `Runtime.evaluate(1+1)`, закрытие
  без хвостов процессов (skip с причиной, если Chrome нет); N8 — нет браузера → остановка с
  объяснением, никаких загрузок.

## Результат
Браузер для проверки страницы без внешних пакетов: поиск Chrome/Chromium, свой клиент WebSocket и протокола DevTools, запуск headless во временном профиле с гарантированной уборкой, инструмент `daiver_capabilities`. Прогнано и против настоящего Chrome 155 (macOS), не только против фейка.
Код: `skills/forgeui/scripts/daiver/browser/{__init__,find,ws,cdp}.py`, `daiver/proc.py`, `daiver/capabilities.py`, запись в `daiver/tools.py`; правки `config.py`, `init.py`, `plan_contract.py` (зачем — ниже). Тесты: `skills/forgeui/scripts/test_cdp.py` (**177 тестов**), `test_daiver_config.py` (+6), `test_plan_contract.py` (+1 нетто); реестры в `hooks/` (`EXPECTED_TOOLS`, списки свободных инструментов).

- **`find.py` — где браузер.** Порядок: переменная `CHROMIUM_EXECUTABLE_PATH` → `verify.browserPath` → `verify.browserChannel` (chrome | chrome-beta | chrome-dev | chrome-canary | chromium | msedge | msedge-beta | msedge-dev | msedge-canary) → стандартные места (macOS `/Applications` и `~/Applications`; Windows Program Files, Program Files (x86), LocalAppData; Linux `/usr/bin`, `/opt`, `/snap`; порядок: macOS и Windows — Chrome, затем Chromium; Linux наоборот, как в задаче) → PATH. Первое ЗАДАННОЕ решает: заданное, но битое (файла нет, каталог, нет права на запуск, имени нет в PATH, неизвестный или не установленный канал) — `found:false` с названной причиной, а не молчаливый переход к другому браузеру. Принимается и пакет `.app` macOS вместо бинарника, и голое имя команды. «Найден» = файл есть и исполняем. Версия без запуска браузера, где можно (`Info.plist` пакета macOS, каталог версии рядом с `chrome.exe`), иначе `--version` с таймаутом 10 с. Ничего не скачивается и не ставится; Edge в поиск по умолчанию НЕ входит — только явным каналом или путём. `blocked_answer(reason)` — готовый останов N8 (`skipped`, `blocked: no-browser`, `reason`, `supply`, `nextStep` с запретом ставить браузер).
- **`ws.py` — клиент WebSocket (RFC 6455) на `socket`.** Вынесен из `cdp.py` отдельным модулем, чтобы кодек проверялся сам по байтовым примерам RFC §5.7 и §1.3. Рукопожатие (без `Origin`: Chrome отвергает чужой; любой неверный ответ — отказ, включая неверный `Accept` и непрошеные расширения; кадр в одном сегменте с ответом не теряется), маска свежим ключом `os.urandom` на каждый клиентский кадр (пересчёт целыми числами: 5 МБ за ~6 мс), длины 7/16/64 бита, фрагментация в обе стороны, ping → pong, close с эхом кода, предел размера по ЗАГОЛОВКУ (128 МБ), строгий разбор нарушений (RSV, opcode, маска сервера, управляющий кадр длиннее 125 байт или фрагментированный, старший бит длины, UTF-8, продолжение без начала) с закрытием кодом 1002/1007/1009, таймаут посреди кадра не теряет принятые байты. Только `ws://` и только loopback (адрес пира сверяется после соединения); `wss://` не поддержан.
- **`cdp.py` — протокол и процесс.** `Connection` (синхронный JSON-RPC: id/method/params, ответы, события в ограниченной очереди, `wait_event`, обработчики в цикле чтения, таймауты, запоздавший ответ отбрасывается; ответ с НЕИЗВЕСТНЫМ id, не-JSON, двоичное сообщение и «не ответ и не событие» — `CdpProtocolError` и закрытие соединения, а не ожидание таймаута; падение или закрытие вкладки роняет вызовы к ней сразу). `Page` (target + плоская сессия): `navigate` (ждёт `load` своего `loaderId`, `NavigationError` с текстом браузера), `evaluate` (значение по значению, исключение — `JsException`, зависший скрипт обрывает сам браузер), `screenshot`, `set_viewport`, `emulate_media`, `query_selector` / `element_box` (DOM), `click` / `insert_text` (Input), `send(метод, параметры)` для остального; диалоги страницы закрываются сами. `Chrome.launch` (временный профиль 0700, порт 0 из `DevToolsActivePort`, `Browser.setDownloadBehavior: deny`), `Chrome.new_page`, `close` (просит выйти, затем убивает ВСЮ группу процессов и удаляет профиль; повтор — пустая операция), `launch_or_skip` → `(Chrome, None)` либо `(None, ответ blocked: no-browser)`: на «браузера нет» исключения нет. Уборка при сбое запуска, `atexit` и SIGTERM хозяина (если обработчик не чужой); реестр живых браузеров держит сильные ссылки. Адреса — `check_url`: http, https, `data:`, `about:blank`, `file:` только внутри названных каталогов (скриншот `file:///etc/…` иначе читал бы любой файл).
- **`proc.py` — процессы в группе.** `popen_group` (своя сессия), `kill_group` (SIGTERM → SIGKILL всей группе, лидер забран; повторный вызов после успешной уборки ничего не шлёт — номер группы мог достаться чужому процессу; группу вызывающего не трогает никогда), `group_alive`. Windows (`taskkill /F /T`) — по документации, не проверено. Общий помощник: им воспользуется dev-сервер 4.9 (заметка в файле задачи).
- **`daiver_capabilities`** (`capabilities.py`, запись в `tools.py`): `ready`; нет браузера — сразу за ним `blocked: no-browser`, `supply`, `nextStep`; `browser` {found, path, version, product, source, detail | reason}, `node`, `typescript` (пакет `typescript` в `node_modules` репо или родителей — так его ищет node), `playwright` (`@playwright/test` репо: объявлен / установлен / версия — вход e2e-гейта 5.5), `vision` {enabled, note} (по `verify.vision`), `warnings` (браузер старше Chrome 109; битые `verify.browser*`). Только читает, сессию браузера не открывает (версия — из пакета или коротким `--version`); в `phase_tools` не входит (свободный, как `daiver_status`) — решено в `test_branches_registry.FREE` и `test_inline-phase-guard.FREE_TOOLS`.
- **Зачем правки файлов вне `browser/`.** `config.py`: ключи `verify.browserPath` / `verify.browserChannel` (задача: «env > `verify.browserPath` / `browserChannel` конфига > стандартные пути»); читаются строго — не строка или неизвестный канал дают предупреждение и `None`, а не догадку. `init.py`: две строки-комментария в шаблоне конфига (в спеке §5.1 они есть закомментированными); сами ключи по умолчанию не пишутся. `plan_contract.py`: в README стояло «минимальный частный поиск… 4.1 заменит» — частный `find_browser` убран, пункт контракта `browser` зовёт `browser/find.py` с блоком `verify` конфига, поэтому проверка на plan-time и запуск на verify-time ищут браузер ОДНИМ кодом (раньше они могли разойтись); сигнатура `PC.find_browser() → (путь, источник | причина)` сохранена, вопрос `ask` теперь называет и `verify.browserPath`. Цена: поиск требует исполняемый файл, поэтому фейковый браузер в `test_plan_contract.Base` стал `chmod 755`, а прежний тест раскладок платформ (он патчил `PC.sys` / `PC.shutil`) заменён проверкой делегирования и тестом ключа конфига — раскладки Windows / macOS / Linux теперь в `test_cdp.FindBrowser` на фейковых исполняемых.
- **Факты по настоящему Chrome 155 (macOS, проверено тестами `RealChrome*`).** Старт за ~1 с; `DevToolsActivePort` — две строки `порт\n/devtools/browser/<uuid>` без перевода строки в конце; все флаги принимаются; UA `HeadlessChrome/155.0.0.0`; `Browser.setDownloadBehavior: deny` принят (само скачивание не пробовалось: проверка писала бы на диск пользователя); `Emulation.setDeviceMetricsOverride` даёт точные `innerWidth/innerHeight` и `devicePixelRatio` 1; `Emulation.setEmulatedMedia` держит светлую схему и `reduce` независимо от темы системы; с `--hide-scrollbars` полос нет; PNG снимка — ровно размер viewport (и размер `clip`); клик по центру border box (`DOM.getBoxModel`) срабатывает, `Input.insertText` вставляет кириллицу; `alert` / `confirm` / `prompt` закрываются сами (`confirm` → false, `prompt` → null), страница не замирает; `ERR_CONNECTION_REFUSED` приходит как `errorText`; зависший `while(true){}` обрывается `Runtime.evaluate timeout` ответом `Execution was terminated` (код -32000, `CdpCommandError`) за заданное время, вкладка остаётся рабочей; http-страница с локального сервера и `file://` внутри названного каталога открываются; порт отладки НЕ доступен по нелокальному адресу машины (адрес у машины есть — проверка выполнялась, не пропущена); внешний `kill -9` группы даёт `CdpDisconnected` за секунды; после `close` нет процессов с путём профиля (включая рендереры), профиль удалён, порт закрыт. Шум stderr macOS (`CVDisplayLinkCreateWithCGDisplay failed`) безвреден.
- **Решения там, где задача и спека свободны.** Транспорт — WebSocket по порту, как велит задача (не `--remote-debugging-pipe`: пайп чистил бы за умершим хозяином надёжнее, но задача называет сокет и `DevToolsActivePort`). Клиент синхронный и однопоточный: нет гонок, тесты детерминированы. Ответ с неизвестным id — нарушение, а не «пропустим»: странное поведение не прячется за таймаутом. Адрес страницы называет только вызывающий; умолчаний нет. «Найден» требует права запуска. Каналы `msedge*` и пути Edge — только явно. Флаги запуска — фиксированный список `BASE_ARGS` (пинится целиком тестом). Viewport, масштаб 1 и media (`light`, `reduce`) задаются вкладке, а не флагами окна. Локаль и часовой пояс не фиксируются (спека их не называет).
- **Мутационная проверка** (одноразовые скрипты: копия пакета в `mut41-*`, одна сломанная строка, прогон затронутых классов; репозиторий не правился). Первый прогон — 63 мутанта (WebSocket 15, протокол / страница / адреса 14, запуск и уборка 10, группы процессов 5, поиск 8, `daiver_capabilities` 6, настоящий Chrome 2, ключи конфига 3): убито 59. Выжили 4: (1) умолчание `Page.emulate_media` (`new_page` передаёт своё) — дыра, добавлен тест умолчаний; (2) проверка пути в файле порта — фейковый сервер принимал любой путь, а Chrome отвечает 404: теперь фейк проверяет путь, а тест ждёт дописывания файла; (3) повторный `close()` — прикрыт вторым слоем (`kill_group` помечает уборку), тест теперь запрещает любой вызов уборки; (4) тот же мутант, что (1), с селектором настоящего Chrome — недостижим через `new_page`, закрыт мутантом `real-media-newpage`. Второй прогон — 19 новых мутантов (умолчания и окружение запуска, stderr, размер окна, вид JSON на проводе, фильтр сессий, изоляция обработчиков, запись диалогов, таймаут `evaluate`, очистка lifecycle, закрытие вкладки при сбое, проверка живости в `wait_event`, потеря неполного кадра при таймауте, EOF посреди кадра, `fin` фрагментов, постоянный ключ маски, отправка после таймаута, заголовок Origin) плюс повтор выживших — убиты все. Итого 82 из 82; эквивалентных не осталось. Мутанты `kill_group` оставляли процессы-«спящие» (что и должен был поймать тест) — убраны вручную.
- **Инварианты.** INV-F11 (не ставить, не скачивать, не запускать самому; только найденный), INV-A8 (ничего не загружается наружу; картинки смотрит агент) и QG N8 закрыты тестами `NoDownloads`, `StopAnswer`, `Capabilities`; ссылки в матрицу инвариантов внесёт X.1.
- **Отклонения** — две новые строки README плана (`daiver_capabilities` и «запуск браузера и страницы»); строки про §12.3 `browser` и `phase_tools` обновлены.

**Не проверено данными.**
Только на фейковом сервере и фейковых исполняемых (против настоящего Chrome не сверялось):
- кодек и разбор нарушений WebSocket (фрагментация, ping/pong, close с кодами, RSV, маска сервера, UTF-8): настоящий Chrome так не говорит; опора — байтовые примеры RFC и независимый кодировщик сервера;
- аварии вкладки и отсоединение (`Inspector.targetCrashed`, `Target.detachedFromTarget`, `Target.targetCrashed` / `targetDestroyed`), диалог `beforeunload`, чужие и запоздавшие ответы, мусор в потоке, переполнение очереди событий;
- сбои запуска (процесс умер сразу, порт не открыт, файл порта дописывается, на порту не DevTools, браузер игнорирует `Browser.close`, потомок переживает лидера), `atexit`, SIGTERM хозяина, чужой обработчик SIGTERM — на скрипте-подделке браузера;
- раскладки Windows и Linux, каналы Chromium / Edge / Canary / Beta / Dev, пакет `.app`, `--version` на Linux — на файлах во временном каталоге;
- разбор вывода `--version` (настоящий Chromium, Edge, Chrome на Linux) — на скриптах-подделках; на macOS версия берётся из `Info.plist` и совпала с `Browser.getVersion` настоящего Chrome.

Нигде не проверено: Windows (пути, `taskkill /T`, права), Linux (раскладка; snap-Chromium в confinement может не видеть профиль во временном каталоге — запуск завершится тайм-аутом с хвостом stderr, обход: `temp_root` в домашнем каталоге), Chrome старше 109 (нет `--headless=new`), настоящий Chromium и Edge, запуск под root и в контейнере (`--no-sandbox` задаёт вызывающий через `extra_args`), https со самоподписанным сертификатом (`NavigationError`; `--ignore-certificate-errors` — решение вызывающего, по умолчанию нет), корпоративные политики и антивирус, SIGKILL самого хозяина (браузер и `$TMPDIR/forgeui-chrome-*` остаются), `wss://`, действие `Browser.setDownloadBehavior: deny` на страницу, которая скачивает, влияние `--font-render-hinting=none` и `--disable-gpu` на метрики текста против обычного Chrome (сверять в 4.2 / X.4), как слабая модель читает `blocked` / `supply` / `nextStep` и не идёт ли за `npx playwright install` (хука на установку браузера в shell модели нет — только текст ответа; хук — кандидат в отдельную задачу).
