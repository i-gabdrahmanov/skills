# 4.5 — DS-гейт: компоненты, пропсы, токены

**Этап:** 4 · **Зависит от:** 4.3, 2.3 (сканер TSX — общий с 4.7) · **Статус:** done
**Спека:** §14.4.5 · **INV:** C13, B17 (проверка), A2 · **QG:** U16 (часть)

## Зачем
Экран может совпасть с макетом по пикселям и при этом быть собран мимо библиотеки: свой Button
вместо библиотечного, запрещённое значение пропа, захардкоженный цвет вместо токена.

## Что сделать
`daiver/verify/ds_gate.py`:
- Идентичность: имя компонента из React fiber vs резолюция плана → `DS_COMPONENT_MISSED` /
  `DS_COMPONENT_WRONG`. Отсутствующий fiber сверяется ДО обвинения: разметка согласна с планом
  (Label поверх `<label>`) → dismissal; исходники рендерят компонент → MISSED снимается в dismissal
  с остаточным риском вслух; исходников нет → MISSED стоит.
- Урезанный скан кода по outputs build-state (imports, JSX-использование, значения пропсов,
  deprecations; сканер TSX — тот же node-хелпер, что в 4.7) → `DS_PROP_WRONG` (проп вне контракта
  цитирует запись требования) / `DS_DEPRECATED` (из прозы details — своего компонента).
- Токены: литерал там, где в макете привязан токен → `DS_TOKEN_MISSED` / `DS_OFF_SCALE`; ссылка
  на токен — молчание.
- Честность: нет карты резолюций — проверка идентичности «не исполнялась», а не угадана; план с id
  другого кадра — degrade; fiber вне опубликованных — молчание; namespace-импорт (`<Ui.Button>`)
  принимается, одноимённый самодельный — нет; нет документа требований / нет JS среди outputs /
  нечего держать против → `ran:false`; каждая находка несёт `rule`.

*Контракт 2.3:* документы требований читать `ds_lookup.load(root)` (поверх `ds_requirements.load_pair`; те же отказы `blocked: library-source-unreachable`, устаревание по
`library.source`/`scanPaths`), значение варианта «принимается» — `ds_lookup.accepted_value(prop, usedValues, value)` (enum — только `options`; boolean — true/false; иначе — `usedValues`);
второго правила чтения контракта не заводить.

## Готово, когда
- `test_ds_gate.py` на синтетике (план + снапшот с фейковыми fibers + outputs): каждый код и его
  dismissal-двойник; `ran:false` в трёх честных случаях.

## Результат
DS-гейт: чистая функция `ds_gate.run(design, impl, matched, plan, lib, sources, colors=None, colors_file=None, react_found=None)` → `{ran, reason?, parts{identity, code, tokens}, findings, dismissals, degraded, stats}` и `ds_gate.gather(root, track, frame)` — чтение с диска (требования ДС через `ds_lookup.load`, `plan.json`, исходники outputs build-state, карта цветов; чего нет — в `notes`/`libProblem`, а не выдумано). Инструмента MCP нет — его даст 4.6. Код: `skills/forgeui/scripts/daiver/verify/{ds_gate,tsx_scan}.py`. Тесты: `skills/forgeui/scripts/test_ds_gate.py` (**55 тестов**: каждый код и его двойник, три честных `ran: false`, сверка отсутствующего fiber, скан исходников, `gather` на настоящем треке с планом и build-state).

- **Скан исходников — на Python, без node** (отклонение от «тот же node-хелпер, что в 4.7»): `tsx_scan.scan_source` поверх готовых блоков 2.2 (`ds/lex`, `ds/value`, `ds/csf.collect_imports`) отдаёт импорты, JSX-использование с литеральными значениями пропсов и номером строки (константы файла разрешаются: `size={S}`; выражение — `dynamic`; spread — флаг), цветовые литералы (в строках, шаблонах, JSX и стилевых файлах без комментариев; запасное значение `var(--x, #fff)` помечено). Код-гейт 4.7 может опереться на него и добавить node-проход.
- **Коды и двойники.** WRONG — fiber называет другой опубликованный компонент (twin: неуверенная пара); MISSED — fiber нет, после сверки «до обвинения» (twin: разметка согласна с планом `<label>`; исходники рендерят компонент — снятие с остаточным риском вслух; twin: неуверенная пара); PROP_WRONG — проп вне закрытого контракта / литерал вне `options` enum / не булево (twin: контракт не закрыт; значение статически не известно); DEPRECATED — компонент или проп из `details.deprecations` СВОЕГО компонента (twin: план выбрал именно этот компонент); TOKEN_MISSED — литерал цвета токена из макета в исходниках (twin: запасное значение в `var(--…, …)`); OFF_SCALE — литерал в пределах 8 на канал от цвета токена. Каждая находка несёт `rule`.
- **Честность.** `ran: false` с причиной и без находок: нет требований ДС / нет JS/TS в outputs / нечего держать против. Идентичность отдельно не исполняется без решений-компонентов в плане и без fiber на странице (`parts.identity.ran: false` с причиной); чужие id в плане — `degraded`, известные записи работают. Fiber вне опубликованных — молчание. Namespace-импорт принимается, одноимённый самодельный (импорт из другого пути) — нет.
- **Допущения, не проверенные данными** (README → «Отклонения»/«Нужно от пользователя»): `onX`/`data-*`/`aria-*`/`key`/`ref`/`className`/`style`/`children` не считаются пропами вне контракта; значения kind≠enum/boolean не проверяются (`usedValues` — словарь, а не запрет); токены ищутся по ВСЕМ исходникам outputs, а не по узлу (сопоставление строки кода с узлом — код-гейт 4.7); `href="#add"` и подобные не цвета (эвристика по имени атрибута); допуск OFF_SCALE 8; при отсутствии JS-файлов гейт не исполняется вовсе (спека одновременно говорит «ran:false» и «нет sources → MISSED стоит» — взято первое).
- **Мутационная проверка** (одноразовый скрипт): 30 мутантов (опубликованность fiber, имя без регистра, три сверки до обвинения, неуверенная пара, путь импорта, namespace, propsClosed, виды значений, динамика, фильтры пропсов, deprecated, fallback, порог и канал OFF_SCALE, файл цветов, непарные узлы, degraded, react, три честных ran:false, цвет в комментарии, граница hex) — убиты все. Первый прогон: 2 выживших (тест на границу OFF_SCALE, якорь `#add`) — дописаны.
