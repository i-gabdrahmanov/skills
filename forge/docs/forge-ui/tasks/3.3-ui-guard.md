# 3.3 — Хук ui-guard: запреты daiver форсятся кодом

**Этап:** 3 · **Зависит от:** 2.6 · **Статус:** done
**Спека:** §18.6 (слой F) · **INV:** F1, F2, F5, F12, C8, C9 · **QG:** N1, N3, N6, N9, N12

## Зачем
В daiver эти запреты — текст GIGACODE.md, модель может их пропустить. В forge-ui — `exit 2`.

## Что сделать
`hooks/ui-guard.py` по образцу `tech-guard.py` — noop вне namespace `forgeui`; ошибка импорта и
внутренний сбой в живом прогоне forgeui → deny (fail-closed):
- **Чтение:** `read_file`/`grep_search` и shell-читатели (`cat`, `head`, `tail`, `less`, `jq`,
  `python -c …open`) запрещены для `*.canonical.json`, `visual-requirements.pixso*.json`,
  `visual-requirements.json|html` и любого файла, чья голова — сигнатура Pixso DSL
  (`{"dsl":{"converterVersion"`), где бы он ни лежал (экспорт до pull). Подсказка в отказе —
  `daiver_outline`/`daiver_section`/`daiver_source_nodes`.
- **Запись кода:** в `project.outputDir` (из `.daiver/config.yaml`) — только на шаге `ui-build`;
  на `ui-verify` правка = переоткрытие `ui-build` (подсказка как в sod-enforcer).
- **Подпись:** запись на `ui-build` — только при согласии `ui-plan-<KEY>` с `bound_sha256`, равным
  sha256 текущего `plan.lock.json` (как tech-guard с `change-plan.json`).
- **Инлайн-SVG:** запись `.tsx/.jsx/.vue/.ts/.js/.html` с `<svg` в outputDir — deny, кроме
  помеченного плейсхолдера арта.
- Проводка: `settings.hooks.json` — обе write-цепочки (после tech-guard) и read-матчер; нумерованные
  цепочки в FORGE.md; ростер `hooks/DEPLOY.md`; таблица хуков в обеих копиях SKILLS-REGISTRY;
  `test_import_failclosed.BLOCKING_HOOKS`; `preflight.ESSENTIAL_HOOKS`.

## Готово, когда
- `hooks/test_ui-guard.py`: каждый запрет и его разрешённый двойник; noop вне forgeui; fail-closed
  на сломанном импорте; `test_docs_hooks_consistency` зелёный; evals N1, N3, N6, N9, N12 в
  `hooks/evals/run-evals.py`.

*Заметка (2.6).* Подпись плана проверять НЕ хешем файла `plan.lock.json`: lock — производный артефакт, файл мог отстать от плана (правка plan.json руками его не
пересобирает). Верная проверка — `daiver.plan_contract.signature_state(root, track, story_spec)` (только читает): согласие `ui-plan-<KEY>` с `bound_sha256` = sha256 lock'а, СОБРАННОГО из
текущих артефактов (требования кадров, plan.json, resolution-report.md, ui-plan.md), и файлы на диске им равны; состояние `ok` | `open` | `stale` с причиной в `detail`. Вызов недёшев
(перечитывает канон и вердикты): кешировать по mtime артефактов. Подпись НЕ зависит от готовности контракта (нет браузера на машине — план не «не подписан»), поэтому охранять запись кода
нужно именно ею, а не `gate_problems`. Устаревшее согласие снимает писатель (`daiver_plan_contract`), хук его не снимает.

*Заметка (3.2).* `ui_gate.py build` подпись плана НЕ перепроверяет (гейт сборки читает секции и запускает `project.buildCommand`): запись кода охраняет именно этот хук, через `signature_state`. Бриф `ui-build` ЧИТАЕТ `plan.md`
кадра, `.daiver/config.yaml` и файлы `project.conventions` — запрет чтения касается только канона и сырых экспортов, `plan.md` не трогать. Единственный легальный `<svg>` в коде — помеченный плейсхолдер арта (`data-art-placeholder`,
«ART MISSING: <slug>.svg»), который выдаёт `daiver_svg_assets(moduleDir)`. `buildCommand` запускает сам процесс `ui_gate.py` (не Bash-вызов модели): хуки видят `python3 …/ui_gate.py build` и `record_gate.py`; ручной `npm run build`
при самоисправлении красного билда (§13.8) — обычный Bash-вызов роли dev.


## Результат
Хук **`hooks/ui-guard.py`** (PreToolUse; вне прогона `forgeui` — noop, внутри — fail-closed), тесты **`hooks/test_ui-guard.py`** (76), evals **N1, N3, N6, N9, N12** (28 проверок в `hooks/evals/run-evals.py`: набор 35 → 63),
проводка (`settings.hooks.json` — обе write-цепочки после `tech-guard`, read-группа и отдельная группа `read_many_files`; `FORGE.md` — ростер и нумерованные цепочки; `hooks/DEPLOY.md`; обе копии `SKILLS-REGISTRY.md`; `README.md`
и `docs/pipeline-technical.md` — число и таблица хуков; `test_import_failclosed.BLOCKING_HOOKS`; `preflight.ESSENTIAL_HOOKS` + пин «не подключён — preflight красный»), правка `state-write-guard.py` (ниже), бриф `SKILL.md` («Что НЕ делать»,
+3 строки), заметки в 3.4, 4.8, 5.5, 6.4, X.4. `test_docs_hooks_consistency` зелёный.

- **Четыре запрета, у каждого — разрешённый двойник в тесте.** (1) *Чтение* (N3, N12): `read_file` / `grep_search` / `read_many_files` и shell-читатели не пускаются к `*.canonical.json`, `visual-requirements.pixso*.json`,
  `visual-requirements.json|html` и к любому файлу с головой Pixso DSL, где бы он ни лежал (пробелы и BOM не мешают; обёртка `{"dsl":…}` необязательна — движок принимает и тело без неё); имя, на которое указывает ссылка, считается; FIFO не
  открывается. Двойники: `plan.md`, `ui-plan.md`, `config.yaml`, `track.yaml`, исходники, обычный JSON, а в shell — перечисление и измерение (`ls`, `stat`, `wc`, `file`, `du`, `test`, контрольные суммы, `find` без `-exec`).
  (2) *Запись кода* (C8, N9): любая запись в `project.outputDir` (из `.daiver/config.yaml`; без регистра, через ссылки, `rm`/`mv`/`touch` тоже правка) — только на `ui-build`; на `ui-verify`, в завершённом прогоне и до сборки — отказ,
  а на `ui-verify` и после конца — с готовой командой переоткрытия `update.py … --step-id ui-build --status pending`. Двойники: docs/ задачи, `.daiver/`, `ground/`, пути вне outputDir, переоткрытый `ui-build`. (3) *Подпись* (C9): запись на
  `ui-build` — только при `plan_contract.signature_state == ok`; отказ — «верни `failed`, план подписывает человек на ui-design», без подсказки, как выписать согласие. Двойники: подписанный план, новая подпись после пересборки.
  (4) *Инлайн-svg* (N1, N6): `<svg` и `data:image/svg+xml` в `.tsx/.jsx/.vue/.svelte/.ts/.js/.mjs/.cjs/.html` в outputDir — отказ (формы записи: Write/Edit/`edits`/NotebookEdit, shell-heredoc, `tee`, `python -c`); двойники — компонент
  библиотеки, `<svg-icon>`, `<Svg />`, помеченный плейсхолдер арта.
- **Факты по данным образца «Modal».** Голова сырого экспорта — `{"dsl":{"converterVersion":"2.2.13","dslVersion":"2.1.15",…` (минифицирован, одна строка, 490 КБ); бриф `ui-design` кладёт экспорт в `.daiver/inbox/<кадр>.dsl.json`, поэтому
  по голове хук обязан узнавать его и там, и под любым именем. `signature_state(root, track, None)` на подписанном «Modal» даёт `stale`, а с резолвером `ui-spec.md` стори (`tools._story_specs`, тот же, что у `ui_gate.py design`) — `ok`:
  дайджест плана включает деградацию `specs`, поэтому хук обязан передавать тот же резолвер (иначе запретил бы запись при законной подписи; тест пинит оба ответа). `signature_state` на «Modal» — 4 мс; хук целиком ≈ 30 мс на вызов
  (запуск интерпретатора), первый вызов с пересчётом подписи ≈ 50 мс. `daiver_svg_assets(moduleDir)` выдаёт плейсхолдер арта как **`<div data-art-placeholder="<slug>" …>ART MISSING: <slug>.svg</div>`**, а не `<svg>`: в штатном потоке
  `<svg` в коде не бывает вовсе (заметка 3.2 называла плейсхолдер `<svg>`), исключение для помеченного `<svg>` оставлено страховкой; маркер и slug сверяет тест с живой `svg_assets.placeholder()`.
- **Решено там, где задача свободна.** Shell — закрытый список «безопасных» команд (`ls`, `stat`, `wc`, …): всё остальное, что называет канон или сырой экспорт, — отказ, в том числе `cp`/`mv`/`echo >`/`rm`; кладёт выгрузку в репо человек.
  Поиск по каталогу отказывает только ВНУТРИ `.daiver/` (если в поддереве под glob-фильтром есть защищённый файл); поиск от корня репо — нет (иначе недоступен любой grep по проекту). `read_many_files`: шаблоны сверяются с файлами `.daiver/` по правилам
  рантайма (`*` не пересекает `/`, точка в имени не мешает `**`), по диску их не раскрываем — Python glob и оболочка скрытые каталоги пропускают, рантайм нет. Порядок проверок записи: шаг → подпись → svg (фундаментальное первым:
  без подписи собирать нечего). Подпись: вердикт кешируется в `ground/statements/forgeui/<KEY>/ui-guard-cache.json`; ключ — sha256 снимка stat'ов (размер, mtime, **ctime**, inode) всех входов: `.daiver/**`, журнал согласий, `ui-spec.md` стори,
  зарегистрированные спеки и файлы страницы, код движка и сам хук (правка с теми же размером и mtime после `touch -r` оставляет новый ctime — тест). Шаги и «шаг проверки → шаг для переоткрытия» хук берёт из реестра веток
  (`BR.BRANCHES["forgeui"]`), не копирует. Плейсхолдер-`<svg>` принимается только с `data-art-placeholder="<slug>"`, подписью `ART MISSING: <slug>.svg` с тем же slug и без нарисованного внутри (title/text/tspan/desc).
- **Правка `state-write-guard.py` (одна строка шаблона + тест) нужна именно этой задаче**, а не 3.4: кеш подписи — единственный файл, по которому ui-guard решает «подпись действительна», и подложенный моделью `ok` снял бы проверку подписи
  так же, как подложенное согласие. Шаблон `ground/statements/<skill>/<feature>/ui-guard-cache.json` закрывает Write/Edit, редирект, `cp`/`mv`, `python -c open` и удаление; остальные пункты 3.4 (запись `.daiver/**`, `plan.md`, …) не тронуты.
- **Отклонение от спеки** — строка README («§18.6 слой F … форсит хук ui-guard»).
- **Мутационная проверка** (одноразовые скрипты: копия дерева, правка текста хука; репозиторий не правился): 44 мутанта правил и 1 мутант `preflight` — каждый убит настоящим падением теста. С первого прогона выжили два (ветка не обязана быть в реестре; `_exempt`
  не проверялся при широком `outputDir`) — получили тесты (реестр без `forgeui` теперь ломает импорт ВНУТРИ try; широкий `outputDir: "."` не захватывает control-plane и документы). Потеря функции под `except` (каждая функция хука по очереди теряет имя →
  NameError → «ошибка проверки»): 44 функции хука (все) по очереди теряют имя — выжило 0, в том числе `_active_ui_run`, чьё исключение глотает ветка «noop вне прогона» (тогда падали бы все запреты); сбой внутри прогона даёт отказ, а не пропуск.

**Не проверено данными (боевых прогонов и экранов нет):**
- как слабая модель (GLM 5.3 Flash) читает отказы и берёт ли замену `daiver_outline` / `daiver_section` / `daiver_source_nodes` или ищет обход (копию, чтение кусками, `python -c`);
- настоящие имена параметров читающих инструментов форка GigaCode (приняты `file_path` / `path` / `absolute_path` по соглашению соседних хуков), есть ли в форке `read_many_files`;
- время хука на большом экране (на «Modal» — 4 мс на `signature_state`; кеш и пересчёт на большом каноне не измерены) и параллельные хуки на живой сессии;
- ложные отказы shell на команды, называющие канон только именем в тексте (grep по имени файла, сообщение коммита); `cd dir && …`, переменные в пути, поиск от корня репо, сырой экспорт вне `.daiver/` внутри такого поиска — не ловятся;
- рукописный `.svg`-файл в outputDir и CSS data-URI не проверяются (правило — про кодовые файлы); `createElementNS` и другие способы нарисовать svg кодом — тоже;
- Windows: ссылки, пути, ctime как время создания (подгонку mtime кеш там не ловит).
