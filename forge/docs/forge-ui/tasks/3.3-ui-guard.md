# 3.3 — Хук ui-guard: запреты daiver форсятся кодом

**Этап:** 3 · **Зависит от:** 2.6 · **Статус:** todo
**Спека:** §18.6 (слой F) · **INV:** F1, F2, F5, F12, C8, C9 · **QG:** N1, N3, N6, N9, N12

## Зачем
В daiver эти запреты — текст GIGACODE.md, модель может их пропустить. В forge-ui — `exit 2`.

## Что сделать
`hooks/ui-guard.py` по образцу `tech-guard.py` — noop вне namespace `forgeui`; ошибка импорта и
внутренний сбой в живом прогоне forgeui → deny (fail-closed):
- **Чтение:** `read_file`/`grep_search` и shell-читатели (`cat`, `head`, `tail`, `less`, `jq`,
  `python -c …open`) запрещены для `*.canonical.json`, `visual-requirements.pixso*.json`,
  `visual-requirements.json|html` и любого файла, чья голова — сигнатура Pixso DSL
  (`{"dsl":{"converterVersion"`), где бы он ни лежал (экспорт до pull). Подсказка в отказе —
  `daiver_outline`/`daiver_section`/`daiver_source_nodes`.
- **Запись кода:** в `project.outputDir` (из `.daiver/config.yaml`) — только на шаге `ui-build`;
  на `ui-verify` правка = переоткрытие `ui-build` (подсказка как в sod-enforcer).
- **Подпись:** запись на `ui-build` — только при согласии `ui-plan-<KEY>` с `bound_sha256`, равным
  sha256 текущего `plan.lock.json` (как tech-guard с `change-plan.json`).
- **Инлайн-SVG:** запись `.tsx/.jsx/.vue/.ts/.js/.html` с `<svg` в outputDir — deny, кроме
  помеченного плейсхолдера арта.
- Проводка: `settings.hooks.json` — обе write-цепочки (после tech-guard) и read-матчер; нумерованные
  цепочки в FORGE.md; ростер `hooks/DEPLOY.md`; таблица хуков в обеих копиях SKILLS-REGISTRY;
  `test_import_failclosed.BLOCKING_HOOKS`; `preflight.ESSENTIAL_HOOKS`.

*Заметка (2.6).* Подпись плана проверять НЕ хешем файла `plan.lock.json`: lock — производный артефакт, файл мог отстать от плана (правка plan.json руками его не
пересобирает). Верная проверка — `daiver.plan_contract.signature_state(root, track, story_spec)` (только читает): согласие `ui-plan-<KEY>` с `bound_sha256` = sha256 lock'а, СОБРАННОГО из
текущих артефактов (требования кадров, plan.json, resolution-report.md, ui-plan.md), и файлы на диске им равны; состояние `ok` | `open` | `stale` с причиной в `detail`. Вызов недёшев
(перечитывает канон и вердикты): кешировать по mtime артефактов. Подпись НЕ зависит от готовности контракта (нет браузера на машине — план не «не подписан»), поэтому охранять запись кода
нужно именно ею, а не `gate_problems`. Устаревшее согласие снимает писатель (`daiver_plan_contract`), хук его не снимает.

*Заметка (3.2).* `ui_gate.py build` подпись плана НЕ перепроверяет (гейт сборки читает секции и запускает `project.buildCommand`): запись кода охраняет именно этот хук, через `signature_state`. Бриф `ui-build` ЧИТАЕТ `plan.md`
кадра, `.daiver/config.yaml` и файлы `project.conventions` — запрет чтения касается только канона и сырых экспортов, `plan.md` не трогать. Единственный легальный `<svg>` в коде — помеченный плейсхолдер арта (`data-art-placeholder`,
«ART MISSING: <slug>.svg»), который выдаёт `daiver_svg_assets(moduleDir)`. `buildCommand` запускает сам процесс `ui_gate.py` (не Bash-вызов модели): хуки видят `python3 …/ui_gate.py build` и `record_gate.py`; ручной `npm run build`
при самоисправлении красного билда (§13.8) — обычный Bash-вызов роли dev.
