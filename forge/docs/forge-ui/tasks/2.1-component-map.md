# 2.1 — Карта компонентов: lookup и append

**Этап:** 2 · **Зависит от:** — · **Статус:** done
**Спека:** §5.2, §10.5 (append), §13.5 п.4 · **INV:** B17, C7, F9, D3 · **QG:** U7, N7

## Зачем
Командная база знаний «узел макета → компонент библиотеки». Попадание в правило — вердикт high
без чтения библиотеки; импорт берётся из карты дословно, а не сочиняется.

## Что сделать
`daiver/component_map.py`; инструменты **`daiver_map_lookup(figmaName, variants?)`** и
**`daiver_map_append(track, rule)`**:
- Правила: точное имя (регистр и разделители не важны), regex `/…/` с захватами `$1`, список
  имён (many-to-one), `outcome` component | local | ignore | icon; `props` из вариантов;
  per-rule `import` (path, named, default с шаблоном `{name}`).
- Ответ lookup: `{outcome, component, props, import:{statement, path}, rule}`; `statement` готов к
  вставке дословно (`import { Badge } from "@your/ui";`). Иконки — из своего пакета
  (`icons.import.path`, обёртка `wrapper.component` + `nameMap`), не из основного; local/ignore —
  без импорта; пути нет вообще — `import: null` (основной пакет не угадывается).
- Append: только при согласии `ui-map-<KEY>` (запись в `ground/approvals.jsonl` с провенансом
  `record_approval` — проверяет движок через `forge_events.approval`); правило без match/outcome —
  отказ; комментарии файла сохраняются (вставка текстом в блок `rules:`); файл никогда не
  заменяется целиком; автономный прогон не пишет карту (7.1).

## Готово, когда
- `test_component_map.py`: lookup по каждому виду правила; statement дословный; иконки из своего
  пакета; local/ignore без импорта; нет пути → null; append сохраняет комментарии и порядок;
  append без согласия — отказ (N7); кривое правило — отказ одним сообщением.

## Результат
`daiver/component_map.py` (чтение, `lookup`, `append`), в `tools.py` — `daiver_map_lookup(figmaName, variants?)` и
`daiver_map_append(track, rule, dryRun?)`, строки в `EXPECTED_TOOLS`, абзац про карту в брифе, `test_component_map.py` (103 теста).
Мутационно проверено 20 правил (одноразовый скрипт, monkeypatch в памяти) — все пойманы; мутант «у компонента нет пути — берётся пакет
иконок» сначала выжил (проверялся только случай «пути нет нигде»), добавлен тест.
- **Данные образца.** Схема карты из спеки §5.2 читается ДОСЛОВНО (4 пробела отступа, комментарии, flow-списки, `default: true` вместе с
  `named`) без единой проблемы — `SpecSample` держит её как есть. Инстансы экрана «Modal» называются по ОПРЕДЕЛЕНИЮ: `component.figmaName` —
  «Modal Header» (×2, варианты `{Steps: OFF}`) и «Modal Action» (`{Variant: Default}`); имя слоя («Steps=OFF», «Variant=Default») — строка
  вариантов, компонент не называет, поэтому карта сопоставляется с `figmaName`, а не с именем узла. 20 определений образца дают 19 различных
  имён (у двух общее «Spinning Loader»); у всех 19 разные ключи (`Icon24` ≠ `Icon16`, «Tech_Icon24» ≠ «Icon24», «Stroke / Arrows / Small_Left»),
  и все 19 кладутся в карту подряд, по одному «да» на правило (`RealSample`).
- **Ключ имени** (§6.4 figmaName: case/separator-insensitive): NFKC → casefold → только буквы и цифры. «Modal Header», «modal-header»,
  «ModalHeader», «MODAL_HEADER», «Modal / Header» — одно имя; цифры значимы; кириллица и «й» в разложенной форме работают.
- **Решено там, где спека свободна.** Приоритет: точное имя/список выигрывает у любого regex независимо от места в файле (частное сильнее
  общего), regex — по порядку, первый сработавший; одно имя в двух правилах — дубликат (тот же результат) или конфликт (другой) — явная
  ошибка и при чтении файла, и при append; точное имя может уточнять regex. Regex — `/…/` с флагом `i` (других нет), ищется в имени как
  есть (регистр захватов `$1…$9` сохраняется), без `i` чувствителен к регистру; в списке имён regex не допускается. Поля по исходу: component
  (нужен component), local (component необязателен), ignore (только match), icon (нужен icon); чужое поле — ошибка, а не молчаливо
  проигнорированное. Схема закрыта (опечатка в ключе — проблема); все нарушения правила и карты называются ОДНИМ сообщением; битая карта не
  применяется (lookup и append отказывают, пока человек её не исправит), нет файла — промах с отсылкой к `daiver_init`. Ответ lookup:
  `{hit, outcome, component, [icon], props, import:{statement, path}|null, [importNote], rule:{index, kind, match}, confidence:"high"}` — ≤ 40
  строк в `indent=1` (пин); «нет пути» — `import: null` + `importNote`, пакет не подставляется ни из `library.import` в иконки, ни из
  `icons.import` в компоненты. Файл карты — `.daiver/` + `library.mapFile` конфига; вне `.daiver/` нельзя.
- **Импорт дословно (B17).** Статус строит код: `import { Badge } from "@your/ui";`; `named` ≠ имени компонента → `import { Named as Badge }
  from …`; `default: true` → `import Badge from "…";` (`named` либо опущен, либо равен имени — как в примере спеки; иначе проблема);
  `{name}` в `import.path` — имя компонента; составное `Form.Item` импортирует корень `Form`; захваты работают в `component`, `icon`,
  значениях `props`, `import.path`, `import.named` (итог проверяется ПОСЛЕ подстановки: «Foo Bar» или `button` — отказ, а не код). Пути —
  только bare specifier: относительные зависят от файла вставки. Иконки: из `icons.import.path`; с `wrapper` — `component` = обёртка,
  `props.name` = имя в наборе; `nameMap` отвечает за имена БЕЗ правила, явное правило сильнее.
- **Append (N7, F9).** Порядок: проверка трека → проверка правила и дубликатов/конфликтов → замок `ground/component-map.lock` → согласие
  `ui-map-<KEY>` (`forge_events.approval`: провенанс record_approval, строка, дописанная мимо писателя, не считается) → запись → трата
  согласия (`revoke_approval`): одно «да» — одно правило, как у rollback и override. Кривое правило, дубликат, конфликт и сбой записи
  согласие НЕ тратят. Вставка — текстом в конец блока `rules:`: комментарии, пустые строки, порядок, CRLF, BOM, стиль отступа и тире файла
  сохраняются, `rules: []` из шаблона `daiver_init` становится блоком с сохранением своего комментария; поток в одну строку не
  переписывается (отказ). Результат перед записью разбирается заново и сверяется (прежние правила и блоки `library`/`icons` не изменились,
  добавлено ровно принятое) — расхождение = отказ, файл не тронут; запись tmp + `os.replace`. Нет файла — append его не создаёт.
  `dryRun` (сверх сигнатуры задачи — строка в README): проверка и YAML без согласия и без записи, чтобы человек видел правило в том виде, в
  каком оно ляжет в файл. Сквозная цепочка проверена с настоящим `record_approval.py`: без цитаты и с цитатой без слова согласия он
  отказывает (класс `ui-map` из `CONSENT_PREFIXES`), с «да, …» пишет согласие, второе правило требует второго «да».
- **Автономный прогон** карту не пишет (D3): в нём некому дать согласие (цитату сверяет gate-guard). Явный отказ по режиму `run.json` — 7.1
  (заметка там); здесь режим не читается.
- **Не проверено данными (допущения).** Образца боевой карты нет — выведено из текста спеки: механика `import` (`default`, `{name}`,
  `named` ≠ имени — спека называет, но не раскрывает), регистр regex, роль `variants` (принимается и проверяется, в сопоставлении НЕ участвует:
  props задаёт правило; спека связи не описывает), `wrapper.nameMap` как таблица имён без правила и `<Icon name>` как форма обёртки,
  составные имена и запрет относительных путей. Согласие привязано к ключу `ui-map-<KEY>`, а не к тексту правила (record_approval умеет
  привязку только к файлу): защищают `dryRun` и одноразовость; хеш правила в согласии — если боевой прогон покажет подмену. Реальный клиент
  (GigaCode) не гонялся — JSON-RPC-сессия в тесте. `icons.fallback` читается и проверяется, применять его будет резолв (2.5).
