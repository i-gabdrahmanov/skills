# 2.1 — Карта компонентов: lookup и append

**Этап:** 2 · **Зависит от:** — · **Статус:** todo
**Спека:** §5.2, §10.5 (append), §13.5 п.4 · **INV:** B17, C7, F9, D3 · **QG:** U7, N7

## Зачем
Командная база знаний «узел макета → компонент библиотеки». Попадание в правило — вердикт high
без чтения библиотеки; импорт берётся из карты дословно, а не сочиняется.

## Что сделать
`daiver/component_map.py`; инструменты **`daiver_map_lookup(figmaName, variants?)`** и
**`daiver_map_append(track, rule)`**:
- Правила: точное имя (регистр и разделители не важны), regex `/…/` с захватами `$1`, список
  имён (many-to-one), `outcome` component | local | ignore | icon; `props` из вариантов;
  per-rule `import` (path, named, default с шаблоном `{name}`).
- Ответ lookup: `{outcome, component, props, import:{statement, path}, rule}`; `statement` готов к
  вставке дословно (`import { Badge } from "@your/ui";`). Иконки — из своего пакета
  (`icons.import.path`, обёртка `wrapper.component` + `nameMap`), не из основного; local/ignore —
  без импорта; пути нет вообще — `import: null` (основной пакет не угадывается).
- Append: только при согласии `ui-map-<KEY>` (запись в `ground/approvals.jsonl` с провенансом
  `record_approval` — проверяет движок через `forge_events.approval`); правило без match/outcome —
  отказ; комментарии файла сохраняются (вставка текстом в блок `rules:`); файл никогда не
  заменяется целиком; автономный прогон не пишет карту (7.1).

## Готово, когда
- `test_component_map.py`: lookup по каждому виду правила; statement дословный; иконки из своего
  пакета; local/ignore без импорта; нет пути → null; append сохраняет комментарии и порядок;
  append без согласия — отказ (N7); кривое правило — отказ одним сообщением.
