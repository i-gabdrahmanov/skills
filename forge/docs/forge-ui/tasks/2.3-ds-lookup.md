## Зачем
Детерминированный шортлист кандидатов вместо «модель читает библиотеку и выбирает на глаз».

## Что сделать
`daiver/ds_lookup.py`; инструменты:
- **`daiver_ds_inventory()`** — список компонентов из КОММИТНУТОГО контракта (никогда не
  пересканирует); вызывается ОДИН раз на трек до резолва; источник не отвечает →
  `blocked: library-source-unreachable` до старта резолва.
- **`daiver_ds_lookup(figmaName, variants?, textSlotKeys?, limit?)`** — нормализация имён (camelCase
  и разделители рушатся одинаково); ранжирование — код: точное имя — максимум; близкое имя
  (вхождение, общие части) — с кредитом объявленных вариантов; значение варианта, которое компонент
  принимает, — баллы; наличие текстовых слотов — баллы; малый бонус за документированность
  сторями; равные баллы — по имени (никогда по порядку вставки); limit 5 (1..20). Пустой список —
  настоящий ответ («в библиотеке нет» → local).
- **`daiver_ds_details(components[≤10])`** — описание, дефолты, deprecations, примеры сторей (JSX)
  для 1–2 финалистов.

## Готово, когда
- `test_ds_lookup.py`: перемешанный вход → тот же порядок; точное имя побеждает; пустой список —
  `[]` без ошибки; details > 10 — отказ; inventory читает файл, а не сканирует.
