# 4.7 — Код-гейт: исходники модуля против макета

**Этап:** 4 · **Зависит от:** 4.3, 3.1 · **Статус:** done
**Спека:** §14.5 · **INV:** C29, F4 · **QG:** U18, N13

## Зачем
Второй детерминированный свидетель без браузера: читает собственные исходники модуля, даёт
file:line и защищает от ложного MISSING.

## Что сделать
- Node-хелпер `daiver/assets/tsx-scan.mjs` (`typescript` фронт-репо), React-адаптер в три прохода:
  scan (imports, top-level определения, литеральные таблицы `mocks.ts`: `as const`, цепочки
  `MOCKS.x.y`, индексация, разрешимые шаблоны); вход на секцию (неиспользуемый компонент =
  смонтированный, default export побеждает, неоднозначность — предупреждение); обход JSX
  (intrinsic → frame, единичный статический текст → text-лист, локальные компоненты ИНЛАЙН со
  сплайсом детей на `{children}`, защита от циклов, кап глубины, компоненты пакетов — чёрные ящики с
  идентичностью/литеральными пропсами/контентом слотов, `.map` по разрешимому массиву размножается
  с привязкой параметра).
- Маркеры динамики — ВНЕ дерева (матчер их не читает): `repeated`, `conditional`, `dynamic-text`
  (текст → unverified copy), `unresolved-import` (MISSING рядом → unverified content).
- `daiver/verify/code_compare.py` + инструмент **`daiver_code_compare(track, frame?, iterationDir)`**:
  allowlist — outputs build-state (+ `mocks.ts`); модель кода формы канона (`code:<sectionId>/<путь>`,
  несколько секций под `code:root`); тот же матчер; проверки только text·content·coverage (ничего
  числового). Reconcile: узел макета сматчен страницей → dismissal «рендерится кодом вне сканлиста»;
  нет в обоих деревьях → `corroborated`; маркеры → dismissed/demoted; `matchRate < 0.5` →
  `treeRecognized:false`, дефектов не эмитит. Дедуп с DOM-гейтом по id (измеренное побеждает).
  Артефакты `code-model.json`, `code-findings.json`, `code-defects.json`, `code-summary.json`.
- Гейт `code`: fail — только blocking code-дефекты; skipped — Vue/Svelte, нет build-state, исходники
  пропали, конфиг противоречит файлам (файлы сильнее), дереву не доверяет — всегда с причиной.
- Ссылка в редактор: `{file,line,column}` → `verify.editorUrlTemplate` (абсолютный путь, сегменты
  URL-encoded, 1-based); `designLocations` дают DOM-дефектам ту же ссылку через пары.

## Готово, когда
- `test_code_compare.py` на фикстуре React-модуля (только разбор TS, без сборки; skip без node):
  инлайн локальных компонентов, `.map`, маркеры, reconcile → corroborated, `treeRecognized:false`,
  дедуп с DOM, Vue → skipped с причиной, editor-ссылки.

*Заметка (3.1).* Allowlist — `outputs` секций из `build-state.json`: пути от корня проекта, отсортированы, без повторов; у `stale`-секции остаются от прежней сборки; `mocks.ts` в outputs может быть, а может и нет (гейт добавляет его
сам). Читать состояние — `build_state.load_state(root, path, track, frame)`: файла нет → `None` («нет build-state» → гейт `skipped`), повреждённый файл → `BuildStateError` (отказ с причиной, а не «пустой»). Несуществующий путь
из outputs код-гейт молча пропустил бы — поэтому его ловят `warnings` инструментов и `gate_problems`; проверка `build_state.missing_outputs(root, sections)` показывает форму обхода.

*Заметка (3.2).* У секции без кода (`noCode: true`, статус `done`) НЕТ `outputs`: allowlist собирается из секций с `outputs`, а пустые `outputs` именно у `noCode`-секции — не «исходники пропали». Оболочку экрана (корневой компонент
из «Оболочка над секциями» плана) пишет ПОСЛЕДНЯЯ секция порядка плана: файл оболочки лежит в её `outputs`. `mocks.ts` создаёт пролог шага, в `outputs` секций он может не входить (гейт добавляет его сам).

*Заметка (4.3).* Код-гейт получает пары из `compare-summary.json` (формат `pairs[]` — см. результат 4.3); `treeRecognized` считай по тому же `matchRate`/MIN_MATCH_RATE (`match.MIN_MATCH_RATE` = 0.5 — одна константа на оба гейта).

*Заметка (4.5).* Готов Python-скан исходников `verify/tsx_scan.py`: `scan_source(rel, text)` → импорты, JSX-использования (тег, строка/колонка, пропсы: литерал / dynamic, spread), цвета; `resolve_tag(tag, imports)`. Он не строит дерево JSX с инлайном локальных компонентов — это работа 4.7 (node-хелпер или расширение Python-скана на тех же `ds/lex`/`ds/value`). Литералы цветов 4.5 ищет по всем outputs; привязка строки кода к узлу макета — за этим гейтом.

## Результат
Код-гейт без браузера: инструмент **`daiver_code_compare(track, frame?, iterationDir)`** (запись в `daiver/tools.py`, владелец — шаг `ui-verify` в `phase_tools`). Читает файлы `outputs` build-state (+ `mocks.ts` рядом), строит дерево формы канона (`code:root` → `code:<секция>` → `code:<секция>/<путь>`), сверяет с макетом тем же матчером, проверяет только text · content · coverage, пишет `code-model.json`, `code-findings.json`, `code-defects.json`, `code-summary.json` в папку итерации. Код: `skills/forgeui/scripts/daiver/verify/{jsx_tree,code_compare}.py`; правки `match.py` и `check.py` (ниже). Тесты: `test_code_compare.py` (**45 тестов**: адаптер, сверка, `run` на настоящем треке со build-state), `test_match.py` (57, +3 режима кода, +3 про корень и опечатки), `test_check.py` (61, `rules`, слот по порядку).

- **React-адаптер на Python, без node** (отклонение от «node-хелпер `tsx-scan.mjs`»): `jsx_tree.build(files, sections)` поверх блоков 2.2 (`ds/lex`, `ds/value`) и скана 4.5. Три прохода как в спеке: scan (импорты, определения компонентов, таблицы `mocks.ts` — цепочки, индексы, шаблоны, разрешимые целиком), вход секции (неупомянутый компонент смонтирован; default export побеждает; неоднозначность — warning), обход JSX (intrinsic → frame/text/vector/image; локальные компоненты — инлайн с подстановкой пропсов и сплайсом `{children}`; пакетные — чёрный ящик `instance` с литеральными строковыми пропсами в `component.textProps` и слотами-детьми; `.map` над разрешимым массивом размножается с привязкой параметра; защита от циклов, потолок глубины).
- **Маркеры динамики — вне дерева**: `repeated`, `conditional` (`&&`, тернарник, несколько `return`), `dynamic-text` (выражение, слова которого неизвестны; смешанный «Итого: {n} позиции» — один текст без слов; динамический проп пакетного компонента — слоты этого экземпляра не судятся), `unresolved-import`.
- **Сверка** (защита от ложного MISSING): пары DOM-гейта из `compare-summary.json` рядом (`pairs[{design,impl}]`, `defectIds[]`) → узел, сматченный страницей, — dismissal «вне сканлиста», отсутствующий в обоих деревьях — `corroborated`; **нет сводки DOM — MISSING `unconfirmed`: улика, не дефект** (иначе без браузера любой компонент вне сканлиста блокировал бы «чисто»); `unresolved-import` рядом → unverified content, `dynamic-text` → unverified copy, `conditional` → расхождение не судится; matchRate < 0.5 → `treeRecognized: false`, дефектов нет (`skipped` с причиной). Дедуп: `id = sha1(code|designId|implId|prop)[:12]`, у MISSING implId не входит; id из `defectIds` DOM-гейта не повторяется.
- **Вердикт**: `fail` — только блокирующие (critical) дефекты кода; `skipped` — Vue/Svelte, нет build-state, исходники пропали, дерево не узнано — всегда с причиной; конфиг (`project.framework`) против файлов — файлы сильнее, warning. Леджер `code-tree / code-structure / code-text / code-reconcile`. Редакторская ссылка `{file,line,column}` → `verify.editorUrlTemplate` (абсолютный путь, сегменты URL-кодированы, 1-based); `designLocations` дают DOM-дефектам ту же ссылку через пары.
- **Что пришлось поправить в матчере и проверках** (находки на модели кода, все пинятся тестами): (1) спуск корня больше не заходит в одинокий текстовый/значковый лист — корень макета рамка (настоящий баг и для DOM: страница из одного заголовка); (2) `match(..., descend_root=False)` — режим кода: корень пара с `code:root`, инлайн-компонент — прозрачная обёртка, чёрный ящик пакета — компонент; (3) опечатка в тексте спаривается по сходству (≥ 0.6) жадно, в том числе под прозрачным фреймом и при неравном числе соседей (раньше — только по позиции при равном числе: `anchor: textSimilar` вместо `position`); (4) `instance` и `component.textProps` у модели страницы — содержимое; (5) `check(..., rules=…)` — код-гейт зовёт только structure · text · slots; (6) слот-оверрайд, которому нашёлся непарный текст в том же числе, — SLOT_TEXT независимо от сходства («Сохранить» → «Отменить»).
- **Мутационная проверка** (одноразовый скрипт): 32 мутанта (unconfirmed, пары DOM, три маркера, планка доверия, дедуп и состав id, блокировка, область меток корня, режим кода, кодирование ссылки, Vue, конфиг, mocks, сплайс детей, map, цикл, default, маркеры, наибольший JSX, textProps, шаблоны, индексы, спуск корня, прозрачность, instance, слот по порядку) — убиты все. Первый прогон: 4 выживших (демотирование динамики, default-вход, mocks, лишние правила): три дописаны тестами, четвёртый (все правила вместо трёх) эквивалентен — лишнее отфильтровывается по кодам.

**Не проверено данными.** Боевых модулей и сводок DOM нет: доля ложных MISSING на реальном модуле (хуки, условный рендер через вызовы, `React.memo`/`forwardRef`, компоненты из алиасов `@/…` — считаются пакетом, а не локальным модулем); формат `compare-summary.json` (его пишет 4.6 — читается терпимо); уровни `critical` у кода-дефектов; поведение слабой модели на `status: skipped` / `unconfirmed`.
