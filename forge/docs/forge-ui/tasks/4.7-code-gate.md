# 4.7 — Код-гейт: исходники модуля против макета

**Этап:** 4 · **Зависит от:** 4.3, 3.1 · **Статус:** todo
**Спека:** §14.5 · **INV:** C29, F4 · **QG:** U18, N13

## Зачем
Второй детерминированный свидетель без браузера: читает собственные исходники модуля, даёт
file:line и защищает от ложного MISSING.

## Что сделать
- Node-хелпер `daiver/assets/tsx-scan.mjs` (`typescript` фронт-репо), React-адаптер в три прохода:
  scan (imports, top-level определения, литеральные таблицы `mocks.ts`: `as const`, цепочки
  `MOCKS.x.y`, индексация, разрешимые шаблоны); вход на секцию (неиспользуемый компонент =
  смонтированный, default export побеждает, неоднозначность — предупреждение); обход JSX
  (intrinsic → frame, единичный статический текст → text-лист, локальные компоненты ИНЛАЙН со
  сплайсом детей на `{children}`, защита от циклов, кап глубины, компоненты пакетов — чёрные ящики с
  идентичностью/литеральными пропсами/контентом слотов, `.map` по разрешимому массиву размножается
  с привязкой параметра).
- Маркеры динамики — ВНЕ дерева (матчер их не читает): `repeated`, `conditional`, `dynamic-text`
  (текст → unverified copy), `unresolved-import` (MISSING рядом → unverified content).
- `daiver/verify/code_compare.py` + инструмент **`daiver_code_compare(track, frame?, iterationDir)`**:
  allowlist — outputs build-state (+ `mocks.ts`); модель кода формы канона (`code:<sectionId>/<путь>`,
  несколько секций под `code:root`); тот же матчер; проверки только text·content·coverage (ничего
  числового). Reconcile: узел макета сматчен страницей → dismissal «рендерится кодом вне сканлиста»;
  нет в обоих деревьях → `corroborated`; маркеры → dismissed/demoted; `matchRate < 0.5` →
  `treeRecognized:false`, дефектов не эмитит. Дедуп с DOM-гейтом по id (измеренное побеждает).
  Артефакты `code-model.json`, `code-findings.json`, `code-defects.json`, `code-summary.json`.
- Гейт `code`: fail — только blocking code-дефекты; skipped — Vue/Svelte, нет build-state, исходники
  пропали, конфиг противоречит файлам (файлы сильнее), дереву не доверяет — всегда с причиной.
- Ссылка в редактор: `{file,line,column}` → `verify.editorUrlTemplate` (абсолютный путь, сегменты
  URL-encoded, 1-based); `designLocations` дают DOM-дефектам ту же ссылку через пары.

## Готово, когда
- `test_code_compare.py` на фикстуре React-модуля (только разбор TS, без сборки; skip без node):
  инлайн локальных компонентов, `.map`, маркеры, reconcile → corroborated, `treeRecognized:false`,
  дедуп с DOM, Vue → skipped с причиной, editor-ссылки.

*Заметка (3.1).* Allowlist — `outputs` секций из `build-state.json`: пути от корня проекта, отсортированы, без повторов; у `stale`-секции остаются от прежней сборки; `mocks.ts` в outputs может быть, а может и нет (гейт добавляет его
сам). Читать состояние — `build_state.load_state(root, path, track, frame)`: файла нет → `None` («нет build-state» → гейт `skipped`), повреждённый файл → `BuildStateError` (отказ с причиной, а не «пустой»). Несуществующий путь
из outputs код-гейт молча пропустил бы — поэтому его ловят `warnings` инструментов и `gate_problems`; проверка `build_state.missing_outputs(root, sections)` показывает форму обхода.

*Заметка (3.2).* У секции без кода (`noCode: true`, статус `done`) НЕТ `outputs`: allowlist собирается из секций с `outputs`, а пустые `outputs` именно у `noCode`-секции — не «исходники пропали». Оболочку экрана (корневой компонент
из «Оболочка над секциями» плана) пишет ПОСЛЕДНЯЯ секция порядка плана: файл оболочки лежит в её `outputs`. `mocks.ts` создаёт пролог шага, в `outputs` секций он может не входить (гейт добавляет его сам).

*Заметка (4.3).* Код-гейт получает пары из `compare-summary.json` (формат `pairs[]` — см. результат 4.3); `treeRecognized` считай по тому же `matchRate`/MIN_MATCH_RATE (`match.MIN_MATCH_RATE` = 0.5 — одна константа на оба гейта).
