# 1.8 — Outline и section

**Этап:** 1 · **Зависит от:** 1.1, 1.7 · **Статус:** done
**Спека:** §9 (9.1–9.3), §16 (nodeUrl), §20.4 (outline: maxTextLen 80, MAX_UNPROVEN 60,
MAX_ABSOLUTE_CHILD_IDS 20) · **INV:** B1, B10, B11, B12, F2 · **QG:** U4, F7, N3

## Зачем
Канон большого экрана — 35–45 тыс. токенов, его никто не читает целиком. Resolve планирует по
дайджесту (в 5–6 раз легче), build получает секции, ограниченные по байтам.

## Что сделать
`daiver/outline.py`; инструменты **`daiver_outline(track, frame?, weightBudget?)`** и
**`daiver_section(track, frame?, sectionId)`**:
- Бюджет: аргумент > `workflow.weightBudget` > 24000 (минифицированные байты поддерева); границы
  секций выбирает код (descend-and-partition), порядок документа сохраняется, лист больше бюджета —
  `oversize` целиком, не режется; при большом бюджете — корень целиком.
- `sections[]`: `{id, name, kind, figmaName?, weight, nDescendants, depth, path, hash}` (hash —
  subtree_hash 1.1).
- Компактное дерево: kind/name/weight/nChildren; текст усечён до 80 без эллипсиса; box — только
  у абсолютных; layout/size — где есть.
- `unproven[]`: контейнеры с абсолютными детьми (называя ИХ детей, до 20) и узлы с кандидатами
  layoutHints; один абсолютный ребёнок-overlay — не попадает; двойная причина — дважды; кап 60 с
  честным счётчиком отброшенного; полностью объявленный макет — пусто.
- `goalImage` — путь или null с подсказкой; `nodeUrlTemplate` (Pixso — подмена item-id; Figma —
  node-id через дефис; параметра нет — добавить; путь внутри инстанса — ссылка на инстанс; нет
  URL — голый id; адрес не выдумывается).
- Section: `section` (мета), `ancestors` (flex-контекст цепочки root→parent), `node` (полное
  поддерево ≤ бюджета); понимает ровно те id, что выдаёт outline; неизвестный — ясная ошибка.
  Дельты состояний/ревизий — 6.2/6.3.

## Готово, когда
- `test_outline.py`: секции ≤ бюджета, разрез детерминирован, хеши и buildOrder стабильны между
  прогонами (F7), outline на синтетическом большом экране ≥ 4× легче канона, приоритет бюджета
  аргумент > конфиг > дефолт, unproven по правилам, неизвестный sectionId → ошибка.

## Результат
`daiver/outline.py`, инструменты `daiver_outline` и `daiver_section` в `tools.py` (в `_check_args` добавлен тип `number`), строка в
`EXPECTED_TOOLS`, `test_outline.py` (99 тестов). Мутационно проверено 51 правило в копии дерева: все ловятся (один мутант — вес
дайджеста в символах вместо байтов — сначала выжил, закрыт тестом с кириллицей).
- **Данные образца.** «Modal» (4 узла, 3101 Б) целиком влезает в бюджет: одна секция — корень, её `hash`/`weight` равны `rootHash`/`weight`
  из `daiver_normalize` (`0ccf768ee9d7`, 3101); unproven пуст — экран полностью объявлен; при бюджете 1500 корень режется на три
  инстанса (659 / 1063 / 886 Б) в порядке документа, при 500 — три oversize-листа; шаблон ссылок берётся из `frameUrl`, который записал pull
  (`…?item-id={id}`). Строки дайджеста образца пинятся дословно. Большого экрана в образце нет — см. «Не проверено данными».
- **Что делает.** Секции — descend-and-partition по весу из `canon.weights` (веса и хеши не пересчитываются): узел ≤ бюджета — секция
  целиком (`≤`, пин на границе в байт), тяжелее — спуск к детям в порядке документа, лист тяжелее — `oversize` целиком, не режется;
  меньший бюджет даёт разрез мельче, но тот же (каждая мелкая секция лежит в крупной). Бюджет: аргумент > `workflow.weightBudget` >
  24000; аргумент — положительное конечное число, битое значение конфига → дефолт и предупреждение в ответе. Ответ outline: `stats`,
  `sections[]`, `legend`, `outline`, `unproven[]` (+ `unprovenDropped`), `goalImage` + `goalImageNext`, `nodeUrlTemplate`; секция
  несёт `oversize`/`occluded`, где они верны (`occluded` наследуется от предка). `daiver_section` отдаёт `section` (та же мета),
  `ancestors` (root → parent), `node` (полное поддерево ≤ бюджета, у oversize-листа — целиком) и понимает ровно id секций outline при
  том же бюджете; чужой id — отказ, который называет, что брать (узла нет / он внутри секции X / он разрезан на секции …); корень,
  тяжелее бюджета, целиком не отдаётся (N3). Детерминизм (F7): разрез и хеши не зависят от порядка ключей и от `PYTHONHASHSEED`
  (тест гоняет два процесса); правка листа меняет хеш только секции, которая её содержит.
- **unproven** строится по КАНОНУ, а не по `stats.layout` (там список обрезан до 20 и его нет при `layout.infer: off`): рамка без
  `layout` с ≥ 2 детьми (`absolute-children`: `count` и до 20 id детей строкой через запятую) и узел с `layoutHints`
  (`layout-hints`: `w=fill h=fill main=space-between grid=high columns=4`). Молчат: одиночный ребёнок (оверлей), объявленный или
  доказанный контейнер (в том числе с pinned-детьми), всё под `occluded`, анатомия библиотечного инстанса (но подсказка на самом
  инстансе остаётся), инстансы и арты. Двойная причина — две записи (сначала дети). Кап 60 в порядке документа, `unprovenDropped` —
  честный остаток, `stats.unproven` — полное число. Тест гонит `ingest/layout.py` на дереве с отказом и сверяет множества: отказавшие
  контейнеры = записи outline, доказанные и оверлей молчат, подсказка оверлея-фона попадает.
- **goalImage** — путь от корня репо (картинка кадра, прикреплённая `rasterPath`) или `null`, подсказка кодом: картинка нужна только
  для группировки контейнеров из unproven; при `verify.vision: off` — «не открывай»; нет контейнеров с абсолютными детьми —
  «не нужна»; нет картинки — «не угадывай, сначала `daiver_source_nodes`, остальное спроси». **nodeUrlTemplate** — Pixso: подмена
  `item-id`, Figma: `node-id` (id с дефисом), нет параметра — добавляется (`?`/`&`, фрагмент сохраняется), путь внутри инстанса
  (`A;B/C`) ведёт на инстанс A, `inferred:`/`dom:`/`code:` ссылки не имеют, нет URL — `null` и голый id (`node_url` для кода 4.x/5.3).
- **Решения там, где спека свободна.**
  Секция — узел, соседи в одну секцию не склеиваются (у склейки нет ни id, ни хеша поддерева): 60 панелей по 2.8 КБ при бюджете
  24000 дают 60 секций, а не восемь по 22 КБ — план (2.6) должен это знать.
  Дерево отдаётся строками «`id kind "name" [<figmaName>] <вес>B n=<детей> … box=x,y,w,h <раскладка> w= h=`» (одна строка = узел,
  отступ = глубина), а не вложенными объектами: MCP печатает `json.dumps(indent=1)`, и объект узла раскрывается в десяток строк —
  дерево из объектов оказалось по транспорту лишь в 1.1–1.2× легче канона, строки — в 2.6–3.8× (на тех же экранах). Поля — те же:
  kind/name/weight/nChildren, текст — первые 80 символов без эллипсиса, box — только у узлов, у которых он есть в каноне, layout/size —
  как в каноне (нет `align.cross` — значит нет в строке, это не `start`). Сверх спеки в строке: `<figmaName>` у инстанса (имя слоя
  инстанса — строка вариантов «Steps=OFF», по ней компонент не опознать), `art=<slug>`, `occluded`. Структурное дерево — `light_tree`
  (для кода следующих задач). Кроме `legend` ответ ничего о формате не требует знать.
  Потолок дерева (в спеке его нет): дерево получает остаток четверти канона после остальных частей ответа, но не меньше бюджета
  секции; не помещается — сначала свёртка простых листьев (text/rect/vector/icon/image), потом нижних уровней целиком; узлы с
  непоказанными детьми помечены `folded`, ответ называет `folded {leaves, depth, hiddenNodes}`. Мерка — минифицированные байты ответа,
  вес считается в байтах UTF-8. Измерено на синтетике из узлов образца (169 КБ, 60 панелей на дизайн-системе): ответ в **4.5×** легче
  канона (в MCP-печати `indent=1` — 4.1×), все 120 инстансов остались в дереве; текстовый экран (154 КБ) — 6.9×; стена тяжёлых
  инстансов (134 КБ) помещается без свёртки, 6.2×; канон 34 КБ (чуть больше бюджета) — 2.9× и без свёртки: «≥ 4×» — свойство больших
  экранов. Цепочка из сотен вложенных рамок (отступ растёт с глубиной) сворачивается, а не раздувает дайджест.
  `ancestors` — `id, kind, name, figmaName, tag, box, layout, size, style, tokens` предков: оболочка над секциями ни в одну секцию не
  входит, и без её стиля её не из чего собрать (спека: «flex-контекст»).
- **Отклонения (строки в README):** дерево `outline` — строки, не вложенные объекты; потолок дайджеста и лестница свёртки; необязательный
  `weightBudget` у `daiver_section`; `ancestors` с `style`/`tokens`.
- **Не проверено данными (допущения, образца нет).** Большого экрана в образце нет: границы секций, лёгкость дайджеста, число секций и
  unproven доказаны синтетикой из настоящих узлов образца (копии его инстансов с content-слотами) и маленькими построителями; как
  выглядят 130–150 КБ реального канона, неизвестно — вес дайджеста и «≥ 4×» подобраны по синтетике. Форма строки дайджеста и потолок —
  наши решения; как их читает GLM 5.3 Flash — проба боевого прогона (X.4). Свёртка идёт целыми уровнями (шаг глубины может скрыть
  много). Ссылки: Pixso `item-id` — по спеке (URL образца обезличен), Figma `node-id` с дефисом — по тексту спеки, образца Figma нет.
  Состояния и ревизии (`state`/`baseline`, дельты секций) — 6.2/6.3. Образец — README → «Нужно от пользователя».
