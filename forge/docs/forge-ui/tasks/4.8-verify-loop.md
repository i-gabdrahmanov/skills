# 4.8 — Цикл verify: состояние, запись, решения, verify-report.md, шаг ui-verify

## Зачем
Цикл заканчивает пользователь: чисто или стоп. Память цикла — на диске, номера итераций в голове не
считаются, решения человека исполняются дословно.

## Что сделать
- `daiver/verify/state.py`; инструменты:
  - **`daiver_verify_state(track, frame?)`** — открывает итерацию: номер, `iterationDir`
    (`verify/iter-N/`, не перезаписывается), `priorReview` (Fix plan прошлой или null), `goalImage`,
    `missingArt`, `warnStalling` (с `warnAfterVerifyIterations`), `history`, `implementation`
    (url/open/devCommand, 4.9), `mode`; итерация исполнена, но не записана → `unrecordedIterations`
    и инструкция записать СЕЙЧАС; повтор до записи номер не двигает.
  - **`daiver_verify_state_record(track, frame?, iteration, gates{compare, code, visualDiff, review,
    e2e}, diffPercent, reviewReport?, reviewSkipped?, defects, decision?, fixed?, declined?)`** →
    `clean`, `blocking`, `progress` (`stalled`: не лучше прошлой; регресс — тоже stall). Ровно пять
    имён гейтов; `diffPercent` — проценты 0–100, как вернул дифф.
  - Правило clean: блокируют только не-noise Critical/Major из deterministic-зон; vision — никогда;
    pre-existing (scope change) — нет; регрессия — да; hard gate fail — не clean; любой другой
    failed-гейт — не clean; skipped e2e/review — не мешает; code fail — блокирует, skip — нет.
- `verify-decisions.json` (разбор): версия схемы (чужую — отказ); решение замораживает снимок
  дефекта (значения сдвинулись → REOPENED с заметкой); переформулировка сама не переоткрывает;
  неизвестные id названы; reviewer переносится; пустая note не переносится; файл одного кадра в его
  папке, позже `decidedAt` выигрывает.
- `verify-report.md` — один на трек: frontmatter outcome (`track, outcome clean|defects-remaining,
  iterations, defectsRemaining, mode, frames{}`), `## frame:` по истории: статусы гейтов, matchRate,
  diff %, вердикт обзора, фиксы и отказы, ссылка на report.html, непрогнанные гейты и почему, всё
  нерешённое, кто закончил цикл; непроверенные кадры названы.
- `ui_gate.py verify`: последняя записанная итерация clean ИЛИ решение stop при согласии
  `ui-accept-<KEY>` (итог defects-remaining честно в отчёте).
- Бриф `ui-verify`: итерация = state → screenshot → compare (hard) → code → [дифф → обзор → e2e] →
  record → путь отчёта пользователю → вопрос через `pending_questions`: clean — готово; иначе
  блокирующие пункты (severity, задуманный фикс, file:line, прогресс, FIXED/NOT FIXED/REGRESSED,
  warnStalling, отклонённые раньше — не переспрашивать) → «чинить всё / пункты / стоп». Фикс —
  переоткрытие `ui-build` с согласованными пунктами дословно; стоп — сразу, без «последней правки».
- **Контракт для статуса (1.10):** лестница `daiver_status` читает `verify-state.json` → `history[]` (пустой список допустим), у последней записи `clean` (bool, обязателен) и `blocking` (число или список, необязателен); clean ⇔ последняя запись чистая и все секции `done` — не ломать.

## Готово, когда
- `test_verify_state.py`: нумерация и `unrecordedIterations`; повтор до записи идемпотентен; матрица
  правила clean; инварианты файла решений; формат verify-report.md; гейт verify (clean / stop с
  согласием / без согласия — нет).
