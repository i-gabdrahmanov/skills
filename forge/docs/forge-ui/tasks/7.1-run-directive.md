# 7.1 — Директива и прогон: run.json, режимы, blocked с supply

**Этап:** 7 · **Зависит от:** этап 4 · **Статус:** done
**Спека:** §15.1–15.3, §15.5, §15.6, §20.3 · **INV:** B22, C38, D2, D3, D5, D7, D10, E1–E8, G8 ·
**QG:** U11, S12, P5

## Зачем
forge-ui должен уметь работать без человека (таск-лист внешнего оркестратора, headless): все вопросы
заданы на плане, а всё, что без человека не решить, — именованная остановка, а не догадка.

## Что сделать
- Инструмент **`daiver_directive(line)`** (превью разбора, ничего не пишет). Грамматика: префикс
  `forge-ui:` (алиас `daiver:`) `track=<KEY> [frame=<url>|file=<path>] [frame.<имя>=<url>…]
  [specs=<path>[,…]] [url=<url>] [url.<имя>=<url>…] [state.<имя>=<кадр>…] [revision[.<имя>]=<url>…]
  [sources[.<имя>]=<пути>] [scope=change|page] [until=resolve|build|verify] [from=plan]
  [mode=autonomous|interactive]`. Malformed — назван дословно, НИКОГДА не чинится: неизвестный ключ;
  ни frame, ни file для кадра без требования; `mode = autonomous` (пробелы); `autonomous=true`;
  `mode=auto`; `from=plan` вместе с `frame=`; недопустимый scope; revision рядом с frame= того же
  кадра; revision при from=plan; `state.x=x`; `state.main=…`. Ссылка state на кадр, которого строка
  не называет, — предупреждение. Нет `mode=` ≠ interactive: дефолт директивы — autonomous
  (`workflow.embeddedMode`); нераспознанное значение автономию не дарует никогда.
- Инструмент **`daiver_run(track|directive, finish?, blocked?)`**: открытие — ключи, mode+источник
  (строка > embeddedMode > workflow.mode), `startsAt` (build при from=plan или готовом плане;
  resolve при требовании без плана; track при макете в директиве; verify для собранного; done для
  чистого), политика (подпись плана: есть — ok, нет — `blocked: plan-unsigned`, отклонение D9),
  кадры; запись `run.json` (кто начал, режим и источник, директива дословно). Blocked — полный список
  §20.3 с `supply` (кто что даёт). Закрытие — outcome из ЗАПИСАННОЙ истории verify: clean |
  defects-remaining | blocked:<причина> | never-run; `until=` → never-run честно. Устаревший рекорд
  (начат директивой, а за клавиатурой человек) закрывается и открывается заново.
- Запреты автономии кодом (D3): `daiver_init`, `daiver_map_append`, `daiver_verify_report` в
  автономном прогоне отказывают; конфиг и карту не пишет `state-write-guard` (3.4).
  *Заметка (2.1):* сейчас `daiver_map_append` в автономии не пишет только потому, что некому дать согласие `ui-map-<KEY>`; явный отказ по
  режиму `run.json` добавить в `component_map.append` / `t_map_append` (режима в движке карты нет).
- Вход: `/forge forge-ui: track=… mode=autonomous` — бриф распознаёт директиву и зовёт `daiver_run`;
  headless — `--allowed-tools` (INSTALL.md §4) плюс MCP forge-ui.

## Готово, когда
- `test_run_directive.py`: S12 — таблица валидных и каждой malformed-формы; таблица startsAt;
  blocked с supply; outcome закрытия из истории; until → never-run; устаревший рекорд.

*Заметка (2.6).* `daiver_plan_contract` не отдаёт поле `directive` из §12.3 (грамматику строки задаёт эта задача); готовая строка для `from=plan` пока лежит только в `ui-plan.md`
(«Строка задачи»: `forge-ui: track=<KEY> from=plan`) и появляется, когда контракт готов. У каждого блокирующего пункта контракта есть `blockedReason` (§20.3; `no-browser` — наше добавление) —
`blocked: plan-incomplete (<id…>)` собирается из `blocks`, `blocked: plan-unsigned` — по `signed:false`; ответ контракта уже несёт оба в поле `blocked`.

*Заметка (3.4).* `run.json` охраняет `state-write-guard` (запись/удаление моделью — deny, пишет только `daiver_run`). `daiver_run` и `daiver_directive` вызывает оркестратор до шагов (разбор директивы, открытие/закрытие прогона): в `phase_tools` их не добавлять, список
свободных `PhaseToolsRegistry.FREE` (`hooks/test_branches_registry.py`) — пополнить. Запреты автономии (`daiver_init`, `daiver_map_append`) — отказ движка по режиму `run.json`; хук `state-write-guard` закрывает только запись файлов руками.

*Заметка (6.4).* Ключи директивы `sources[.<имя>]=<пути>` и `scope=change|page` ложатся в поля кадра `sources` / `scope` манифеста (`daiver_track_manifest`, `TR.SCOPES`); недопустимый scope — malformed. `no-sources` спеки — это `REASONS["sources"]` контракта плана (`plan_contract.chk_sources`), база страницы — пункт `baseline` (`plan-incomplete`, захват — три вызова в `<кадр>/baseline` ДО правок, `page_base.capture_problem`). В автономии пропуск базы (`baselineSkip`) моделью не выписывается: это слова человека — без них останов `blocked`, а не тихий пропуск.

## Результат

Инструменты **`daiver_directive(line)`** (превью, ничего не пишет) и **`daiver_run(track | directive, finish?, blocked?)`** — оба свободные (вызывает
оркестратор до шагов). Код: `daiver/directive.py` (разбор и сверка с треком), `daiver/run.py` (открытие, закрытие, `run.json`, `mode_of`,
`BLOCKED` с supply, `refuse_autonomous`); режим из записи читают `verify/state.py` (`mode`, `modeSource`, `run`), `verify/report_html.py`,
`status.py` (`tracks[].run`); запреты D3 — `init.init` и `component_map.append` (кроме `dryRun`). Бриф `SKILL.md` §0 — «Прогон — второй ход».
Тесты: `test_run_directive.py` (**32**); реестры инструментов в `hooks/test_daiver_mcp.py`, `test_branches_registry.py`, `test_inline-phase-guard.py`;
потолок брифа `test_ui_design_brief.MAX_FILE_LINES` 360 → 365.

- **Разбор.** Префикс `forge-ui:` (алиас `daiver:`), пары `ключ=значение` через пробел. Malformed — каждое нарушение дословно, с самим токеном:
  неизвестный ключ (`autonomous=true`, `devCommand=…`), три формы пробелов вокруг «=», пустое значение, повтор ключа, нет `track=`, недопустимые
  mode / scope / until / from / имя трека или кадра / не http(s)-адрес / путь с «..»; `from=plan` с `frame`/`file`/`revision`; `revision` рядом с
  `frame` того же кадра; `state.x=x`; `state.main=…` (и `state.<первичный>=…` под настоящим именем — при сверке с треком); ключ кадра, у которого
  требования нет ни в треке, ни в строке (сверка `check_against`). Предупреждения: `state.<кадр>=<экран>`, где экран строка не называет;
  `scope=` без `sources=`. Ключи без суффикса — о первичном кадре (`main` строки = первый кадр трека); `frame.main=` — то же, что `frame=`.
- **Режим** (E1–E3): `mode=` строки > `workflow.embeddedMode` (директива; мусорное значение — дефолт autonomous с предупреждением конфига) >
  `workflow.mode` (человек). Записан в `run.json` (`mode`, `modeSource`, `startedBy`, строка дословно), читается назад `mode_of`; закрытый прогон
  режим не держит.
- **Открытие.** Ключи строки код кладёт в манифест сам (url → `implementation.url`, url.<кадр>, state.<кадр> → stateOf + role state, sources,
  scope, specs) — у кадров, которые уже есть; ключи кадров без записи в треке — `pending`, их допишет повторное открытие той же строкой после
  pull. Ключ, который манифест не принимает, — malformed, ничего не записано. `track-conflict` (D7): у кадра другая ссылка, ссылка уже у другого
  кадра или выгрузка `file=` даёт другое требование (тот же slim, что у pull) — ни перезаписи, ни слияния ключей; `revision=` — pull, не
  конфликт. `startsAt`: track (строка несёт макет, которого нет) / resolve / build / verify / done по нижней ступени кадров; без требования —
  `no-requirement` (в том числе `file=` без ссылки на кадр: pull без неё не строит ссылки на узлы). Контракт плана (только чтение) — при
  `from=plan` (оба режима) и при старте с build/verify/done: не готов — `plan-incomplete (<id…>)`, не подписан при `from=plan` или автономной
  сборке — `plan-unsigned`. `policy` — подпись (satisfied-by-signature | pause | blocked: plan-unsigned), резолв, verify (reportHtml, decision
  human | triage, остановы, потолок `maxVerifyIterations` в автономии, `warnAfter` у человека), until.
- **Blocked** — запись открытого прогона с `blocked` и `supply` (§20.3 полностью + `no-browser`, `spec-unapproved`), её закрывает `finish`.
  Автономия на проекте без конфига — запись `not-initialized` (каталог трека создаётся, конфиг — нет), и `daiver_init` отказывает, пока прогон
  открыт; человек без конфига — `startsAt: init`, ничего не пишется.
- **Записи** (E8): та же строка (или снова человек) — тот же прогон (`resumed`, `n` не растёт, повтор без изменений не пишет); открыт прогон
  директивы, а начинает человек — прежний закрывается `closedBy: stale` с исходом из истории; другая строка — `superseded`. Времени в записи нет.
- **Закрытие** (C38, D10): исход из `verify-state.json` кадров: blocked (аргумент или записанный при открытии) → `blocked:<причина>` + supply;
  `until=resolve|build` → never-run; хоть один кадр не проверен → never-run; все последние итерации чистые → clean; иначе defects-remaining с
  числом блокирующих. `note` — заметка для чекбокса, `checked` — отметить ли. Повторное закрытие ничего не пересчитывает (`alreadyClosed`).
- **D3**: `daiver_init` и запись в карту (`daiver_map_append` без `dryRun`) отказывают при открытом автономном прогоне любого трека;
  `daiver_verify_report` в нём `rendered: false` (так в §15.4: «не рендерится» — триаж вместо отчёта, 7.2).
- **Мутационная проверка** (одноразовый скрипт, monkeypatch): 13 мутантов (пробелы, неизвестный ключ, from=plan, state самого себя, сверка с
  треком, дефолт режима директивы, конфликт трека, until, исход defects→clean, подпись в политике, закрытый как открытый, запрет D3, supply) —
  убиты все.

**Не проверено данными** (таск-листа внешнего оркестратора и headless-прогона нет): как слабая модель передаёт строку дословно и не «чинит» её;
настоящие строки задач команды (длина, ключи, кадры) — грамматика выведена из §15.2; headless `--allowed-tools` с MCP forge-ui (INSTALL.md §4)
не прогонялся; поток «директива → pull → повторное открытие той же строкой» проверен только на синтетике.
