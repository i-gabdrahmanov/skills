# 4.3 — Матчинг макет ↔ страница

**Этап:** 4 · **Зависит от:** 1.1, 4.2 · **Статус:** done
**Спека:** §14.4.2, §20.4 (`MIN_MATCH_RATE` 0.5, `LOW_MATCH_RATE` 0.9) · **INV:** C26 · **QG:** U15, F2

## Зачем
Прежде чем сравнивать свойства, надо понять, какой элемент страницы — это какой узел макета.
Неверная пара делает все дальнейшие дефекты вымыслом.

## Что сделать
`daiver/verify/match.py` (одинаково для dom- и code-моделей):
- Якоря по убыванию силы: текст (нормализованный; уникальный на обеих сторонах — единственный
  самостоятельный сигнал; textProps компонента = его текст), компонент (figmaName без учёта
  регистра/разделителей), позиция (тот же сматченный родитель, тот же индекс), геометрия (только
  тай-брейкер), роль (text↔text, frame↔block, instance↔component; несовпадение блокирует пару,
  но два инстанса спариться могут всегда).
- Ограничения: сверху вниз (дети — только внутри сматченного родителя: пять одинаковых карточек
  не перелинкуются); один-к-одному по убыванию score; консистентность вложенности; обёртки страницы
  (`body > div#root`) — узел макета может спариться на 1+ уровня глубже.
- План — мост имён: резолюции читаются из всех трёх носителей (карта по id, resolution рядом с id,
  пары соседей); имя — из своего поля, kind-слово отличается по форме (заглавная vs тег), не по
  allowlist; ignore пропускается, local остаётся; без плана — порядок соседей.
- Смарт-правила: пустой контрол узнаётся по краске; составная ячейка — по слотам при одном неверном
  символе; React-обёртка компонента — не соперник; текст не спаривается с боксом; корневая пара —
  спуск мимо покрывающей обёртки до рамки/краски; хром приложения вне РЕГИОНА (граница — слова и
  виджеты пар) — не EXTRA, а `stats.outsideRegion`.
- Выход: пары + MISSING (стабильный id, ветка — одной строкой; содержимое компонента, нарисованного
  одним узлом, не называется; пустая рамка не MISSING), EXTRA (только контент; анонимная обёртка —
  нет), ORDER (виноват сдвинувшийся). `matchRate` — только по видимому контенту; < 0.5 — hard gate
  fail; < 0.9 — один MISSING на несвязанное поддерево; пары низкой уверенности — числовые правила
  пропускаются со счётчиком.

## Готово, когда
- `test_match.py` на синтетических деревьях по каждому правилу: карточки-близнецы, обёртки
  страницы, мост имён через план, хром вне региона, ORDER с правильной виной, hard gate.

*Заметка (3.2).* Узлы под корнем, решённым `ignore` (секции с `noCode: true` в `build-state.json` и вложенные `ignore` плана), на странице НЕ строятся: матчер и гейты не должны считать их отсутствие дефектом (MISSING). Решения по
узлам — `plan.json` → `sections[].nodes[]`; список секций без кода — `plan.no_code_sections(plan)`.

## Результат
Матчер «узел макета ↔ элемент страницы» — чистая функция без диска и браузера: `match(design, impl, plan=None)` (конверты канона или корни) → `pairs`, `missing`, `extra`, `order`, `hardGate`, `lowMatchRate`, `stats`. Код: `skills/forgeui/scripts/daiver/verify/match.py` (одинаков для dom- и code-моделей); инструмента MCP в этой задаче нет — его даст 4.6 (`daiver_verify_compare`). Тесты: `skills/forgeui/scripts/test_match.py` (**53 теста**, по правилу на группу: якоря, ограничения, корневая пара, мост плана, находки, гейты, добивающий проход, настоящий канон «Modal»).

- **Выход.** `pairs[]` — `{design, impl, anchor, confidence, score}`: anchor ∈ `root | text | plan | component | textOverlap | paint | position`; `confidence: low` у пар по краске, перекрытию < 0.8 и позиции — у них числовые правила 4.4 пропускаются со счётчиком (`stats.lowConfidence`). `missing[]` — `{id (= id макета), kind, branch (одна строка), contentCount, ancestor}`; `extra[]` — `{id, kind, tag?, text? | component?, contentCount}`; `order[]` — `{id, impl, parent, designIndex, implIndex}`; `stats` — `designContent, matchedContent, matchRate, unmatched, pairs, lowConfidence, missing, extra, order, outsideRegion, ignored, implContent, rootImpl`. Всё детерминировано: ничья score — порядок макета, затем документа; вход не меняется.
- **Якоря и веса** (константы `SC_*`, не из спеки — подобраны синтетикой): текст 100 (+20 уникальный на обеих сторонах), мост плана 70, компонент 60, перекрытие текстов поддеревьев ≤ 50, краска 30, позиция 10, геометрия ≤ 5 (только тай-брейк: относительный бокс внутри пары-родителя и размер). Пара принимается при сумме содержательных якорей ≥ 25. Роль блокирует пару уже при выдаче кандидатов.
- **Сверху вниз.** Дети ищутся в поддереве сматченного родителя (с развёрнутыми обёртками страницы); несматченный фрейм макета «прозрачен» — его дети ищутся в той же области; пары одного уровня не вложены друг в друга на странице. Корневая пара — спуск по цепочке «единственный ребёнок, покрывающий родителя, без краски и текста»; ветвление или краска — стоп.
- **Мост плана** — `read_plan(plan, known_ids)`: три носителя (карта по id, запись `{id, component|resolution}`, пары `[id, имя]`); имя — из СВОЕГО поля, kind-слово отличается формой (заглавная первая буква). Читает форму нашего `plan.json` (`sections[].nodes[]`); `ignore` — узел и поддерево выпадают из макета (не MISSING, не в matchRate), `local` остаётся.
- **Данные образца «Modal» показали три вещи.** (1) Инстансы макета — листья: текст лежит в `component.content` слотах, а страница рисует его текст-детьми. Поэтому тексты страницы внутри сматченного инстанса, названные его слотами, — «покрытые» (не EXTRA), а подпись инстанса для перекрытия берётся из слотов. (2) Имя слоя инстанса — строка вариантов («Variant=Default»): метка для MISSING берётся из `component.figmaName`. (3) Два «Modal Header» с одним именем компонента различаются только текстами слотов — перекрытие их различает (`RealModal`). Боксов у настоящего канона нет почти ни у кого (они у абсолютных) — геометрия молчит, и это штатно.
- **Решения там, где спека свободна** (строки README → «Отклонения»): добивающий проход по позиции (при равном числе соседей одной роли, пары `low`; тексты — только при сходстве ≥ 0.6, иначе страница с чужими текстами и теми же счётами набрала бы matchRate 1 и обошла hard gate); `LOW_MATCH_RATE` понят как «MISSING с общим сматченным предком — одна запись»; регион и допуск `REGION_TOL = 4` px; ORDER — наибольшая неподвижная подпоследовательность (ничья: больше «на своих местах», затем раньше в макете; > 600 соседей — упрощённо).
- **Мутационная проверка** (одноразовый скрипт, репозиторий не правился): 19 мутантов (вложенность, область поиска, ближайшая позиция, ORDER, регион, пороги, схожесть текстов, покрытые слоты, форма имени, слияние MISSING, спуск корня, прощение символа, обёртка-не-соперник, краска, регистр имён и текстов, геометрия, имена в ветке) — убиты все. Первый прогон выжил на 4: область поиска, роль, прощение символа, регистр текста — дописаны тесты; проверка роли оказалась дублем (роль блокирует при выдаче кандидатов) — убрана.
- **Скорость.** 200 карточек по 8 узлов (≈ 4000 узлов страницы): 0.08 с.

**Не проверено данными.** Всё на синтетике и на одном настоящем каноне «Modal» (3 инстанса): веса и порог перекрытия 0.5; допуск региона 4 px; поведение на большом экране без боксов; доля пар `low` на реальных страницах (иконки без имён спариваются только позицией); слияние MISSING; как матчер ведёт себя на странице с чужим дизайн-системным DOM (имена компонентов фибера часто не совпадают с figmaName — тогда держится текст и мост плана). Минифицированные имена компонентов (prod-сборка) — перекрытие текстов, не имена.
