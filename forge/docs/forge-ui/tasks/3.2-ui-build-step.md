# 3.2 — Шаг ui-build: пролог, правила сборки, гейт

**Этап:** 3 · **Зависит от:** 2.6, 3.1 · **Статус:** todo
**Спека:** §13.1, §13.2, §13.5 (правила 1–14), §11.3, §13.8 · **INV:** A9, B9, B17, B18, C11–C17, C20,
C39, F4, F5, F8, F18 · **QG:** P1 (часть)

## Зачем
Сборка экрана строго по подписанному плану и измеренным значениям макета, в стиле проекта, с
проверяемым итогом (сборка проекта зелёная).

## Что сделать
- Бриф `ui-build` (субагент, роль dev):
  - Пролог ОДИН раз на трек: прочитать каждый файл `project.conventions` (они сильнее примеров
    forge-ui); карта цветов; пустой `mocks.ts`. Для page-изменений пролога нет (6.4).
  - Цикл: `daiver_build_state` → по `next`: `set in_progress` → `daiver_section` → строить ТОЛЬКО
    это поддерево → `set done` с outputs и hash; дальше — следующий кадр (6.1).
  - Правила: стек из конфига; local-композиция из анатомии, library-инстанс — чёрный ящик с
    content; пропсы сверены с источником библиотеки (дефолты не передавать, набор не расширять);
    импорты — дословно из карты/ds_lookup, иконки — из своего пакета; иконка — только компонент
    библиотеки, иначе `icons.fallback`; арт — `daiver_svg_assets(moduleDir)`, нет файла —
    плейсхолдер; раскладка 1:1 (direction/gap/padding/align/wrap, fill/hug/px, box → absolute);
    корневой px-размер кадра не хардкодится, внутренние px — точно; цвета → переменные только по
    ТОЧНОМУ значению; local-компоненты → `outputDir/local/`; тексты макета → `mocks.ts` и
    defaultProps, не в разметку; семантика по `tag`; occluded не строится; спеки: States/Events/
    Validations подключают логику, «Данные» решают типизацию (пути из спеки, иначе моки и
    `onX`-пропсы, `// TODO(forge-ui): wire business logic`).
- Движок: **`daiver_color_tokens()`** (дополнение к спеке — арифметика в коде, INV-A1): разбор
  `styling.colorsFile` (less/scss/css-переменные) → карта «точное значение → переменная»
  (нормализация регистра и короткого hex); близкий цвет не угадывается.
- `ui_gate.py build`: все секции done, stale нет, outputs существуют, затем `project.buildCommand`
  (таймаут, хвост вывода в ответе); не компилируется — субагент чинит сам (§13.8), гейт красный.

## Готово, когда
- Бриф обновлён; `test_color_tokens.py` (точное совпадение, нормализация hex, нет совпадения →
  None); `test_ui_gate_build.py` (заглушка buildCommand: зелёная/красная, stale-секция → не готово).

*Заметка (2.6).* Решения по узлам секции сборка берёт из `plan.json` → `sections[id].nodes[]`: `{component, props}` | `{resolution: local, local?: имя}` | `{resolution: ignore}`
(узлы без записи — простая разметка по канону); оболочка над секциями — `tree` (контейнеры с дайджестом раскладки; секции в нём — ссылки `{section: id}`); раскладка: принятые hints
лежат в `layout.decisions[]` (`apply` → `hints` обязательны для сборки, `keep-px` → px остаётся, `group` → ряд/колонка из названных детей с `gap`/`gaps` и `box`, посчитанными кодом),
непринятые из канона не применять. Общие local-компоненты — `locals[]` (`shared: true`, `creator` — секция, которая создаёт файл в `outputDir/local/`). Токены/цвета без токена — `design`.
Сверку цветов с `project.styling.colorsFile` план НЕ делает — это `daiver_color_tokens` этой задачи. Бриф `ui-build` не должен называть `daiver_plan_sign` (его нет) и обязан
сверять `weightBudget` плана с аргументом `daiver_section`.

*Заметка (3.1).* Цикл — инструменты `daiver_build_state` / `daiver_build_state_set` (`daiver/build_state.py`, формат и правила — в докстринге модуля). `next` — объект `{sectionId, name, status, outputs?}` (у stale `outputs` — файлы
прежней сборки: правка на месте), `weightBudget` ответа — бюджет для `daiver_section`, `nextStep` уже несёт готовый вызов. Переходы держит код: `done` только из `in_progress`, `in_progress` только для `next`, `done` требует `outputs`
(пути от корня проекта; голое имя файла, `..`, каталог — отказ; несуществующий путь — `warnings`, они повторяются в каждом `daiver_build_state`) и `hash` — `section.hash` из `daiver_section`; чужой hash — отказ, настоящий в отказах
не называется (бриф не должен советовать «возьми hash из ошибки»). `ui_gate.py build` берёт готовый читатель `build_state.gate_problems(root, track, frame)` (нет состояния / не сверено с планом / секции не done / outputs не на диске;
план против макета — отказом с лечением) и добавляет `buildCommand`; в `ui_gate.py` он пока не подключён. Секция, чей корень решён `ignore`, ничего не строит, а `outputs` обязателен — тупик, решить по боевому плану.
