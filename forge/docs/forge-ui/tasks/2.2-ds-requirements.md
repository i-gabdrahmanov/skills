# 2.2 — Требования дизайн-системы из сторей/исходников

**Этап:** 2 · **Зависит от:** — · **Статус:** done
**Спека:** §5.3, §20.4 (DS-скан: MAX_FILES 5000, MAX_FILE_BYTES 512 КБ) · **INV:** A5, A6 · **QG:** U8, S4

## Зачем
Когда у библиотеки нет storybook-MCP, контракт компонентов (пропсы и допустимые значения) и
описания строятся один раз и коммитятся: модель не читает библиотеку напрямую (INV-A2).

## Что сделать
- Только при `library.source` ∈ stories | sources; при storybook-mcp — отказ «не строится» (сервер
  и есть требования, производная копия протухла бы).
- Node-хелпер `daiver/assets/ds-scan.mjs`: запускается `node` фронт-репо, `typescript` берёт из
  репо (`createRequire(<repo>/package.json)`); разбирает CSF1/2/3, `storiesOf`, `*.stories.mdx`,
  MDX-доки, `.d.ts`; сливает CSF+MDX; JSDoc `@deprecated` (+ замена); usedValues — значения из
  args сторей; import — bare specifier (из сторей); число документированных конфигураций.
- `daiver/ds_requirements.py` + инструмент **`daiver_ds_requirements()`**: пишет
  `.daiver/design-system-requirements.json` (КОНТРАКТ: компонент → пропсы → допустимые значения,
  usedValues, import, счётчик сторей; без прозы) и `.details.json` (КАК ИСПОЛЬЗОВАТЬ: описание
  компонента, описания и дефолты пропсов, deprecations, стори как JSX-примеры).
- Ноль компонентов → ошибка («сканпути неверны: bundled dist/*.js без .d.ts и сторей сигнатур не
  несёт»), не продолжение с пустым контрактом. Нет node/typescript — именованный отказ.

## Готово, когда
- `test_ds_requirements.py` на fake-DS фикстуре (`fixtures/fake-ds/`: CSF3, CSF2, storiesOf, MDX,
  .d.ts): контракт и детали по составу; storybook-mcp → отказ (S4); ноль компонентов → ошибка;
  нет node на машине — skip с причиной.

## Результат
Инструмент **`daiver_ds_requirements(check?, engine?)`** (`tools.py`, строка в `EXPECTED_TOOLS`), движок `daiver/ds_requirements.py` (скан → слияние →
документы → валидаторы → атомарная запись; `build`, `check`, `load_pair`, `validate_*`, `dumps`), разбор — пакет `daiver/ds/` (чистый Python:
`lex` лексер JS/TS/JSX, `value` статические значения + JSX-элементы, `csf` CSF1/2/3 + CSF Factories + storiesOf, `decl` interface/type/enum/
компоненты `.d.ts` и исходников, `typeast` упрощённые типы, `mdx`, `interp` тип → kind/options и argTypes, `merge` слияние), необязательный
node-движок `daiver/assets/ds-scan.mjs` + `daiver/ds_node.py`, фикстура `fixtures/fake-ds/`, `test_ds_requirements.py` (113 тестов, 3 пропускаются
без typescript), абзац в брифе `SKILL.md`. Текст предупреждения `ds-requirements-missing` теперь называет инструмент (запись из 1.10).
Мутационно проверено 34 правила (одноразовый скрипт, исходники подменялись в памяти) — все пойманы; два выживших мутанта (связь MDX только по
`Meta of`, import-путь только из имени `declare module`) дали тесты, а правило «тип `*Attributes` внешний» удалено как избыточное и вредное
(объявленный в сканируемых файлах `FooAttributes` должен разворачиваться; неразрешённое имя и так открывает набор).

**Движки. Основной — Python, без node.** Спека и план закладывали node + typescript репо как парсер; здесь он необязателен: `engine: python` (по
умолчанию) работает где угодно, `engine: node` — явный запасной ход на typescript из `<repo>/node_modules` (`createRequire(<repo>/package.json)`).
Молчаливого отката нет: нет node или typescript — названный отказ, документ пишет `source.scanner` (`py/1` | `node/1`). Хелпер читает файлы сам и
возвращает sha256 прочитанных байтов — не совпал с хешем Python, скан отклоняется. MDX всегда читает Python. **Паритет доказан на фикстуре и на 5
наборах конструкций поверх неё** (CSF Factories, storiesOf через переменную, export-списки, enum/условные/шаблонные типы, `memo/observer`,
`declare module`): факты двух независимых реализаций совпали побайтно, документы — тоже (кроме `scanner`); прогон — с
`FORGEUI_TEST_TYPESCRIPT=<каталог пакета typescript>` (я гонял на typescript 5.0.4), без переменной эти тесты пропускаются с названной причиной.

**Контракт документов — на него опираются 2.3 (ds_inventory/ds_lookup/ds_details) и 4.5 (DS-гейт).** Читать — только `ds_requirements.load_pair(root)`
→ `(contract, details, problems)`: пара либо валидна и согласована, либо `problems` названы и документов нет (2.3: пустой/битый → `blocked:
library-source-unreachable`; не пересканировать). Оба файла — JSON, ключи по алфавиту, массив скаляров в строку; коммитятся.
```
design-system-requirements.json
  daiver  {version, role: "ds-requirements", doc: "contract", schema: 1}
  source  {librarySource: stories|sources, scanPaths: […], scanner: py/1|node/1, sha256: <64 hex>, files: N, skipped: [{path, reason}]}
  components  {"<Имя как в коде>": {
      title: "Группа/Компонент"|null, taxonomy: ["Группа"…] (title без последнего сегмента), stories: N (документированных конфигураций),
      props: {"<проп>": {kind, from, options?, required?}},     propsClosed: bool,
      usedValues: {"<проп>": [скаляры]},  usedCapped?: ["<проп>"],
      import: null | {path: "<bare specifier>", named: "<имя>"} | {path, default: true} }}
design-system-requirements.details.json
  daiver  {…, doc: "details"}   source {sha256: <тот же>}
  components  {"<Имя>": {description: str|null, docs: str|null (проза MDX), props: {"<проп>": {description?, default?}},
      deprecations: [{target: component|prop, name, message, replacement: str|null}], examples: [{name, jsx}]}}
```
- `kind` ∈ enum | boolean | string | number | node (слот: ReactNode/ReactElement) | function | object | array | other (типизирован, не классифицирован) |
  unknown (о типе ничего). `options` — ровно у `enum`, непустой список без повторов (скаляры; порядок как в источнике). `from` — что победило: `types` (TS) →
  `argTypes` → `usage` (вид по значениям); узкие `options` из argTypes применяются поверх TS-`string`/`number`. `required` — только `true`.
- **`propsClosed: true`** — набор пропсов выведен из полностью разобранного TS-типа (без внешних `React.*Attributes`, без индексной сигнатуры, всё
  разрешилось). **Только тогда проп «вне контракта» — нарушение (DS_PROP_WRONG)**; у компонентов из одних сторей набор неполон по построению (`false`).
  Значение вне `options` — нарушение только у `kind: enum`; `usedValues` — подтверждённый реальный словарь, не запрет.
- `import` — только bare specifier, взятый из импортов сторей/MDX (самый частый) либо из имени `declare module "pkg"`; относительный путь и алиас
  (`@/…`, `~/…`) не берутся → `null` (2.1: основной пакет не угадывается, спросить пользователя или `library.import` карты).
- `details` у компонента может не быть: ключ отсутствует — `hasDetails: false`. Deprecations структурные: компонент (`@deprecated` на объявлении) и
  пропы (`@deprecated` на члене), `replacement` вынут из текста («Use `X` instead», «replaced by X», «prefer `X`»), иначе `null`.
- Имена компонентов — как в коде (регистр сохранён); нормализацию имён для lookup делает 2.3 сама.
- Хеш `source.sha256` — sha256 строк `<путь>\t<sha256 содержимого>\n` по возрастанию пути; у пары одинаков. `check()` → `ok | stale | invalid | missing |
  not-needed | unconfigured` (stale — изменились файлы библиотеки, `scanPaths` или `library.source`). Пересборка — повторный вызов инструмента: те же
  байты, если ничего не менялось (`changed: false`).

**Что разбирается (допущения — по знанию Storybook/TypeScript, образца боевой ДС нет).** CSF3 (`satisfies/as`, мета через константу, `args/argTypes/name/
render/parameters`), CSF2 (`Template.bind`, `Name.args/argTypes/storyName/parameters =`, spread `…Name.args`), CSF1, CSF Factories (`meta.story({…})`
— по тексту, не проверено), storiesOf (цепочка и через переменную, `addParameters({component})`), `includeStories/excludeStories` (массив или
регулярка), `__namedExportsOrder`; MDX: `<Meta title component of args argTypes>`, `<Story name args argTypes>`, проза без ESM/JSX-блоков/комментариев
(блоки кода остаются), привязка прозы: `Meta of={X}` → файл → его компоненты, `component`, `title`, сосед «тот же каталог и имя до первой точки»,
иначе предупреждение; декларации: interface (слияние объявлений, extends, `Omit/Pick/Partial/Required/PropsWithChildren/PropsWithoutRef/
RefAttributes` разворачиваются, внешние типы открывают набор), type, enum (в том числе литеральные алиасы и enum как options), компоненты
(`FC/ForwardRefExoticComponent/MemoExoticComponent/ComponentType`, функциональный тип, `function`, `class extends Component`, в исходниках ещё
стрелка с типом пропсов/JSX, `forwardRef<T,P>`, `memo/observer`), `declare module`. Значения: константы файла, enum, spread, `as const`,
`Object.keys/values`; невычислимое (вызовы, стрелки, шаблоны с `${}`) остаётся маркером `opaque`, неразрешённое имя — `ref`, JSX-значение — `jsx`;
список `options` с невычислимым элементом контрактом не становится. Примеры (details) — JSX историй (`{...args}` подставляется атрибутами args,
`children` из args — в тело) либо синтез из args; ≤ 8 на компонент, ≤ 600 знаков; usedValues ≤ 24 на проп, строки ≤ 40 знаков, `children` исключён.

**Решено там, где спека свободна.** Режим `stories` читает stories, MDX и `.d.ts`; `sources` — ещё `.ts/.tsx` (не тесты и не `.d.ts`); `.js` исходники
не читаются (без типов пропсов не вывести). Пропускаются вложенные `node_modules/.git/.daiver/storybook-static/coverage` и точечные каталоги, если
они не названы в `scanPaths` явно (библиотека, поставленная пакетом, указывается как `node_modules/@x/ui/dist` — это работает); симлинк за пределы
репо не раскрывается (`outside-repo`), в документ не попадают пути машины. Один компонент — одно имя: повторы сливаются, разные `title` — предупреждение.
Сбой разбора одного файла (структурные исключения) не валит скан — `parseErrors` и предупреждение; баги кода (`NameError`…) падают громко.
Время: файл у потолка (512 КБ) разбирается за 0.2–0.4 с.

**Отклонения от спеки** (строками в README плана): (1) основной разбор — Python, node необязателен; (2) протухание определяется хешем (спека: «система не может»);
(3) `MAX_FILES` — отказ, не обрезка, плюс `MAX_TOTAL_BYTES` 32 МБ сверх §20.4; (4) deprecated берётся структурно из `details.deprecations`, а не из прозы
(§14.4.5); (5) аргументы `check` и `engine` сверх сигнатуры `daiver_ds_requirements()`.

**Не проверено данными.** Всё разобрано по синтетической `fake-ds`: форматы stories/MDX/деклараций корпоративной ДС (CSF-версия, как заданы `options` и
`control`, где живёт описание, как пишут `@deprecated`, есть ли `.d.ts` в `dist/`, как устроены экспорты и import-пути) — допущения; CSF Factories и
шаблонные/условные типы — по тексту. Реальный MCP-клиент (GigaCode) не гонялся — JSON-RPC-сессия в тесте. Как слабая модель читает ответ инструмента и
формулировки отказов — проба боевого прогона (X.4). Время скана на настоящей библиотеке (тысячи файлов) не мерено.
