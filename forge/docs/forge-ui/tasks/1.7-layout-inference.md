# 1.7 — Вывод раскладки (макеты без auto-layout)

**Этап:** 1 · **Зависит от:** 1.3 · **Статус:** done
**Спека:** §8 (8.1, 8.2), §20.4 (`LAYOUT_TOLERANCE` 1 px, `GAP_JUMP` 1.3) · **INV:** B8 · **QG:** U3, F6

## Зачем
Макет без auto-layout приходит абсолютными x/y. Скопировать — значит получить модуль из
абсолютных div, который пиксельный гейт пропустит, а жить с ним нельзя. Normalize выводит
раскладку и доказывает её реплеем.

## Что сделать
`daiver/ingest/layout.py`, включается `layout.infer` (off/false — выключено):
1. Стек с равным ритмом → column (row) c gap и padding; порядок — по позиции.
2. Cross-ось: center — только если центрирование воспроизводит рамку; общая нижняя кромка → end;
   одинаковая высота и start → без align.
3. Одиночный абсолютный ребёнок → padding родителя.
4. Ритм с округлением: 10 и 11 px — один gap; настоящий разрыв — нет.
5. Две величины зазора → синтетические группы (контейнер, которого нет в макете) с id
   `inferred:<члены>` — re-pull их сохраняет; третья величина вкладывается, а не сплющивается
   (разделительный зазор > группирующего в 1.3 раза).
6. Решётки: одинаковый зазор в обе стороны → одна wrapping row (короткая последняя строка тоже);
   разные зазоры — вложенные ряды; колонка полновесных блоков — не wrapping row.
7. Отказы: перекрытия; контейнер с собственным auto-layout (и pinned-дети); ребёнок вне
   контейнера; выпирание за край; cross-позиции не start/center/end.
- Доказательство: раскладка принимается, только если реплей ставит КАЖДОГО ребёнка на его бокс
  ±1 px; иначе дети остаются абсолютными и узел — в `unproven`. Синтетическая группа — настоящий
  элемент-обёртка. `layout.inferred: true`.
- layoutHints — только КАНДИДАТЫ (применяет resolve, 2.5): `h:fill`/`w:fill` (ребёнок покрывает
  контейнер), `grid` (ряд равновеликих; после wrapped-lattice — high), `main:space-between`
  (только прижатые к обоим краям).
- На макете с настоящим auto-layout ничего не делает.

## Готово, когда
- `test_layout_inference.py` на синтетике по каждому правилу и отказу; F6: реплей сходится ±1 px
  ко всем детям, необъяснимый контейнер остаётся absolute + hints, повторный normalize побайтно
  стабилен, id синтетических групп стабильны.

## Нужно
Реальный полноэкранный кадр без auto-layout — образец модалки целиком на auto-layout.

## Результат
`daiver/ingest/layout.py` (`infer_layout`, `summary`; константы `LAYOUT_TOLERANCE` 1 px и `GAP_JUMP` 1.3 живут здесь), проводка в
`ingest/pixso.py` (`normalize_doc(..., infer_layout=False)`; `Converter.rects` — экранные прямоугольники узлов в потоке чужой
раскладки, у которых `box` нет) и `ingest/normalize.py` (читает `layout.infer` конфига; в ответ — короткая сводка `layout`, список —
в `stats.layout` канона); `test_layout_inference.py` (80). Ключ `layout.infer` уже был в `config.py` (по умолчанию on, off/false
выключают, прочее — предупреждение и дефолт) — не менялся. Мутационно проверено 52 правила в копии дерева: 51 ловится, один мутант
эквивалентен (`<=` вместо `<` у границы допуска, который и так считается как «допуск + EPS»); по ходу найдены и закрыты дыры тестов
(равенство зазоров у переноса, «обе кромки» у fill, допуск полос, допуск кластеров зазоров), избыточная проверка начала строк
удалена (её целиком судит реплей), мёртвый параметр `tight` убран (бокс группы — объединение членов, её padding выходит нулевым сам).
- **Данные образца.** «Modal» целиком на auto-layout: контейнеров без `layout` с детьми в нём нет (корень и три инстанса объявлены),
  модуль не меняет ничего — канон побайтно тот же с `layout.infer` on и off, `stats.layout` и подсказок нет (пин-тест). Реального
  полноэкранного кадра без auto-layout нет: каждое правило §8.1 и каждый отказ доказаны синтетикой (маленькие деревья канона и
  «лендинг» 1280×800 на DSL для F6). Доказательство проверяет ВТОРОЙ, независимый движок прямо в тесте (`abs_rects` заново считает
  прямоугольники по одному лишь канону и сверяет их с боксами макета ±1 px — «moves nothing»).
- **Что делает.** Над ГОТОВЫМ каноном (после 1.4–1.6) рамка без `layout` (не `occluded`, не чёрный ящик библиотечного инстанса, не
  обёртка адаптера `inferred:…`, не инстанс) становится рядом, колонкой или решёткой. Принимается ТОЛЬКО если реплей ПРОДУКТА (layout,
  порядок детей и группы — как они лягут в канон) ставит каждого ребёнка на его бокс ±1 px; иначе ничего не пишется, дети остаются
  абсолютными, а контейнер попадает в `stats.layout.unproven` (`{id, reason, detail}`; причины overlap, outside, overflow, cross,
  rhythm, replay, no-box, no-geometry; в списке ≤ 20, остальное — честный `dropped`). Принятые дети теряют `box` и получают
  недостающую ось `size` числом. `layout.inferred: true`, `stated` не пишется. Объявленный контейнер (в том числе с pinned-детьми) не
  трогается и в unproven не попадает.
- **Решения там, где спека свободна.**
  Порядок — по позиции; дети делятся на полосы по вертикали (перекрытие полос больше допуска — одна строка): одна полоса — row, все
  полосы из одного ребёнка — column, иначе решётка. gap — среднее всех зазоров («10 и 11 — один gap»), дрейф судит реплей: зазоры
  10 и 12 проходят (ошибка ровно 1 px), 10 и 13 — нет. Cross: сначала start, затем end, затем center; align не пишется при общей
  верхней кромке и одинаковой высоте, при разных высотах start пишется явно (иначе умолчание CSS stretch растянуло бы низкого),
  center — только когда общий центр детей совпадает с центром контейнера. Одиночный ребёнок — column и все четыре padding
  (измеренные отступы до кромок; правый и нижний — остаток, а не намерение дизайнера); не вписавшийся одиночный ребёнок — оверлей, в
  unproven не идёт. Группы: зазоры кластеризуются по допуску, самый большой кластер режет последовательность, отрезки из ≥ 2 детей
  становятся группой (kind=frame, name «Group» — автоимя, не кандидат резолва; size hug×hug); разделитель обязан быть БОЛЬШЕ
  группирующего более чем в 1.3× и ещё на допуск; третья величина вкладывается рекурсией. id группы — `inferred:` + id членов через
  «+» (вложенные группы раскрыты до узлов макета; длиннее четырёх — `первый..последний#число`), выдаётся при записи принятой
  раскладки (отвергнутые попытки имён не занимают), коллизия с id источника — суффикс `~2`. Решётка — одна wrapping row, если все
  зазоры по обеим осям равны в допуске, все строки кроме последней из ≥ 2 блоков и реплей по ширине сходится (ширина содержимого —
  самая широкая строка, остаток уходит в padding справа); иначе column из строк-групп; колонка полновесных блоков — column.
  Подсказки-кандидаты: `w/h: fill` — на ребёнке, покрывающем контейнер от кромки до кромки (в том числе у неразобранного
  контейнера: оверлей-фон над контентом, F6); `main: space-between` — ведущий и замыкающий отступы равны и зазор больше допуска;
  `grid` — ряд из ≥ 3 равновеликих (medium) и перенос равновеликих (high, `columns` — число в строке). На синтетических группах
  подсказок нет; ни одна подсказка не меняет ни `layout`, ни `size`, ни `box` (применяет только resolve, 2.5).
  Проводка: `normalize_doc` по умолчанию не выводит (прямые вызовы в тестах 1.3–1.6 не затронуты), `normalize_frame` берёт флаг из
  конфига; при off/false модуль не вызывается (тест подменяет функцию на падающую); `stats.nodesOut` считает группы; ответ
  `daiver_normalize` несёт `layout: {inferred, groups, wraps, unproven (число), hints, next}`, а `stats.layout` в ответ не идёт.
- **Отклонения (строки в README):** к правилу 1.3× добавлено «и больше на допуск»; `main: space-between` ставится только при зазоре
  больше допуска.
- **Не проверено данными (допущения, образца нет).** Вся логика §8 — по тексту спеки; в частности: направление одиночного ребёнка
  (column), порог grid (3), чтение «прижаты к обоим краям» как равенства ведущего и замыкающего отступов (центрированная группа тоже
  получит кандидата space-between), главная ось только start + padding (end/center по ней не выводятся), раскладки из двух колонок
  разной высоты без обёрток (делится только по строкам, затем по зазорам), рамки контейнера (border) в реплее не моделируются
  (в Pixso дети не сдвигаются на толщину обводки, в CSS сдвигаются — учтёт сборка 3.2), инстансы контейнерами не считаются, а числа
  `width/height` рамок в потоке чужой раскладки (из них `rects`) взяты как вычисленные верными — README фикстуры предупреждает, что у
  узлов с кодами 1 и 2 они бывают размером мастера (для инстансов берутся данные материализатора). Образец — README → «Нужно от
  пользователя».
