# 5.4 — Разметка в отчёте и файл решений verify-decisions.json

**Этап:** 5 · **Зависит от:** 5.3 · **Статус:** todo
**Спека:** §14.10 (режим «Пометить проблему»), §14.11 · **INV:** C34, D9 · **QG:** P6

## Зачем
Второй способ ответить на итерацию — богаче чата: решение и заметка на каждый дефект, ручные метки
того, что гейты не увидели, ответ сразу всем кадрам трека.

## Что сделать
- В `report.html`: на каждый дефект — fix (с заметкой) / skip / false_positive; режим «Пометить
  проблему» — hit-test по захвату DOM итерации от меньшего к большему, шаг наружу, прямоугольник
  мышью, подавление нативного drag картинки; id меток `user-<iteration>-<n>`, перенесённые метки
  сохраняют старые id; экспорт решений всего трека — скачивание `verify-decisions.json`, пользователь
  кладёт его в папку трека.
- Повторный `daiver_verify_report` читает файл: answered (fix — заметка ДОСЛОВНО; skip → declined;
  false_positive → `noise:true` с именем решившего), reported (ручные метки: note = вся постановка;
  записываются `source:"review"`, `zone:"vision"`, `severity:"major"`, `problem` = note, pin = box
  при `side:"impl"`), answeredElsewhere (чинится в этом проходе, записывается следующей итерацией
  своего кадра). Инварианты файла — из 4.8.

## Готово, когда
- `test_decisions_ingest.py`: отображение ответов в записи итерации по всем четырём видам;
  `test_report_annotate.py` — headless Chrome через CDP 4.1 кликает по отчёту и экспортирует файл
  (skip без Chrome).
