# 6.4 — Правка существующей страницы (page baseline)

**Этап:** 6 · **Зависит от:** 6.3 · **Статус:** done
**Спека:** §12.2, §13.7 (page), §14.4.6 (baseline.standing), §20.4 (proposeSources: MIN_TEXT_LENGTH 3,
limit 8, maxFiles 3000) · **INV:** C18, C19, F18 · **QG:** U22, P4

## Зачем
Страница написана людьми, не forge-ui. Изменение по макету правит её точечно и отличает свои
регрессии от старых расхождений.

## Что сделать
- На ui-design: «страница уже есть?» → `sources` — находятся по конвенциям проекта → роутеру →
  текстам страницы (инструмент **`daiver_propose_sources(track, frame)`**: тексты канона ≥ 3
  символов, до 8 кандидатов, обход до 3000 файлов), подтверждаются ЧТЕНИЕМ, не угадываются;
  `scope` change | page. Без sources — `blocked: no-sources`.
- Захват базы ДО правок кода: `daiver_screenshot` → `daiver_verify_compare(iterationDir=<frame>/baseline)`
  → `daiver_code_compare(iterationDir=baseline)` → `baseline:{kind:"page"}`. Пропуск — только если
  работающей страницы нет вовсе, и это говорится открыто.
- Сборка в файлы `sources`: место каждого региона `location` own/inside/ancestor (file:line из
  код-гейта); файл читается до правки (чужой код — домашний стиль); вне регионов ничего не
  реформатится, не переименовывается. `ui-guard` для scope page разрешает запись в sources, а не в
  outputDir.
- Verify: `baseline.standing` — каждый дефект классифицируется change / pre-existing / regression по
  ключу (code, designId, свойства rows) / (code, element), никогда по id дефекта; scope change —
  pre-existing не блокирует; scope page — считается всё; три числа словами в nextStep.

## Готово, когда
- `test_page_baseline.py`: синтетическая «ручная» страница + база → классификация standing при
  scope change и page; propose_sources находит файл по текстам; проверка «вне регионов дифф нулевой».

*Заметка (2.6).* Поля кадра `sources` (список файлов страницы от корня репо) и `scope` (change | page, только вместе с `sources`) уже в `track.yaml` и задаются
`daiver_track_manifest` (`track.py`, 2.6): контракт плана проверяет их пунктами `sources` (файлы на диске, scope задан; блокирует) и `baseline` (папка `<кадр>/baseline` не пуста; блокирует) для
кадра с непустыми `sources`; кадр без `sources` строится с нуля, эти пункты «н/п». Здесь остаются поиск файлов (`daiver_propose_sources`), захват базы, запись `baseline: {kind}` и поток правки.
Записи об «открытом пропуске базы» формата нет — если он нужен, завести его здесь и дать контракту прочитать.

*Заметка (3.2).* Бриф `ui-build` исходит из нового модуля: пролог (конвенции, `plan.md`, карта цветов, пустой `mocks.ts`) идёт в каждом запуске, каталог — `<outputDir>/<имя кадра>`. Для кадра с `sources` (правка существующей
страницы) пролога нет — scaffold существует, `mocks.ts` редактируется, строится в файлы `sources`; эту ветку брифа и гейта добавляет 6.4 (сейчас бриф кадр с `sources` не отличает).

*Заметка (3.3).* `ui-guard` охраняет только `project.outputDir` (запись вне `ui-build`, подпись плана, инлайн-svg). Файлы `sources` кадра с правкой существующей страницы лежат вне outputDir и хуком НЕ охраняются:
чтобы «`ui-guard` для scope page разрешает запись в sources, а не в outputDir» стало правдой, расширить `_judge_write` в `hooks/ui-guard.py` — цели записи там сверяются с `outputDir` функцией `_in_output`; добавить
пути `sources` активного трека (список уже собирает `_extras` для ключа кеша подписи) и применять к ним те же три правила (шаг `ui-build`, подпись, инлайн-svg). Что делать с записью в outputDir при scope page — решить здесь.

*Заметка (3.4).* `baseline/**` и `versions/**` под `.daiver/tracks/<KEY>/…` охраняет `state-write-guard` — снимок базы страницы и ревизии пишет только движок. `daiver_propose_sources` решает по тому же правилу, что и остальные инструменты: чей он — `phase_tools`
шага `ui-design` или список свободных (`test_every_engine_tool_has_an_owner` не даст добавить его молча). Файлы страницы (`sources`) вне `.daiver/` — обычный прод-код фронта: `.tsx/.jsx/.vue/.svelte` классифицируются R2 (не тест), запись в них идёт по правилам `ui-guard` (см. заметку 3.3).

*Заметка (6.3).* Поле кадра `baseline` уже есть в `track.yaml`: сейчас только `{kind: version, version}` (`track.BASELINE_KINDS`, пишет pull ревизии) — `kind: page` добавить туда же, и `chk_baseline` контракта сначала смотрит версию, потом `sources`. Регионы, файлы регионов, вердикт базы и секции всех версий для гейтов живут в `daiver/baseline.py` (`analyze`, `verdict`, `version_sections` / `code_sections`) — `standing` (change / pre-existing / regression) и `location` логично класть рядом. `daiver_frame_baseline` отвечает только на ревизию (у кадра без версии — отказ «не ревизия»); QG-U22 целиком (sources-location, standing, scope) закрывает эта задача.

## Результат

Инструмент **`daiver_propose_sources(track, frame?)`** (читающий, свободный на любом шаге) и ветка правки страницы у `daiver_frame_baseline`. Код:
`daiver/page_base.py` (захват базы, регионы, `location`, standing, проверка INV-C19), `daiver/sources.py` (поиск файлов страницы), `track.py`
(`baseline {kind: page}`, поле `baselineSkip`, `is_page` / `page_captured`), `verify/capture.py`, `verify/verify_compare.py`, `verify/code_compare.py`,
`outline.py` (дельта-корень `inferred:delta:<кадр>@page`, блок `page` в outline и section), `plan.py` / `plan_digest.py` / `plan_contract.py`
(`plan.page`, «Правка страницы», «Правка страниц», пункт `baseline`), `build_state.py` (блок `page`), `build_gate.py` (C19), `verify/state.py`
(блокирует ли pre-existing — по `scope`), хук `hooks/ui-guard.py` (`sources` — тот же код, что outputDir), бриф `SKILL.md` (ui-design п. 3,
ui-build п. 2–3, ui-verify п. 6). Тесты: `test_page_baseline.py` (**30**), `hooks/test_ui-guard.py` (+3, `PageSources`); переписаны пины заглушки 2.6
(`test_plan_contract`: «файлы в baseline/ — уже база»; `test_screenshot`: подпапки `baseline/`), линтер брифа (`test_ui_design_brief`: screenshot и
verify_compare на ui-design — только в `/baseline`).

- **Поиск файлов.** Тексты канона ≥ 3 символов (без повторов) ищутся подстрокой в файлах кода репо; ранг — число РАЗНЫХ найденных текстов, затем путь;
  до 8 кандидатов, у каждого `found` (текст и строка). Адрес кадра (`implementation_url`) — свидетель роутера: путь с подставными сегментами на месте
  чисел/id ищется строковым литералом (`'/orders/:id'` для `/orders/42`) → `routes`. Словари (`.json/.yaml`) — `textFiles`. Обход отсортирован, до 3000
  файлов (`truncated`), каталоги зависимостей, сборки и служебные (`node_modules`, `dist`, `.git`, `.daiver`, `ground`…) — мимо. Решение «это страница» —
  чтение, запись — `daiver_track_manifest set={sources, scope}` (бриф).
- **Захват базы** — ровно `<кадр>/baseline` (`iteration_dir_ok` больше не пускает подпапки `baseline/`), только у кадра с `sources` (не ревизия, не
  состояние) и только пока сборка не начата (в build-state все секции pending) — иначе отказ «ДО правок», прежняя база остаётся (`capture_problem`,
  для screenshot / verify_compare / code_compare). `daiver_verify_compare` в базу: истории нет, при `clean | defects` пишет `baseline {kind: page}`
  (снимает `baselineSkip`); hard-gate-fail — ничего не пишет. `daiver_code_compare` в базу копирует `sources` в `baseline/sources/<путь>` и индекс
  `sources.json`, дерево строит из них. Снятие `sources` снимает и `baseline {kind: page}` (поле пишет движок — иначе кадр заперт валидацией).
  Работающей страницы нет вовсе — `baselineSkip` (причина одной строкой, `daiver_track_manifest`): пункт контракта `baseline` неблокирующий, цена —
  в «Принятых деградациях» ui-plan.md; outline — весь кадр (`page.skipped`), standing нет, считается всё.
- **Регионы** (pageGap → regions) считаются заново от durable-входов базы (`snapshot.json` + копии файлов) против ТЕКУЩЕГО канона тем же матчером и
  правилами, что у проверки, без плана: перетяжка макета не делает их протухшими (тест: фильтр убрали из макета — регион ушёл без перезахвата).
  added — `missing` матчера (верхние поддеревья), removed — `extra` (элемент по видимому тексту страницы), changed — находки «что показано»
  (`CHANGE_CODES`: TEXT, ORDER, SLOT_*, INVISIBLE). Расхождения значений (геометрия, типографика, цвет, форма) у найденных узлов вне регионов —
  `preExisting` при scope change; при scope page они тоже регионы changed. Дельта-корень — как у состояния и ревизии; outline / section / резолв / план /
  build-state идут по нему. Без базы (и без пропуска) outline отказывает с тремя вызовами захвата и выходом `baselineSkip`.
- **location** — дерево кода копий базы (`jsx_tree`, секция `page` из `sources`), сматченное с каноном матчером код-гейта: own — узел найден (у пары
  без места, синтетического `code:root`, — первый потомок с местом: корень компонента страницы); inside — найдены потомки (пролёт — их объединение в
  одном файле); ancestor — ближайший найденный предок; removed — по видимому тексту в коде. `endLine` — парный закрывающий тег (`lex.scan_jsx`).
  У плана правки страницы нет модуля (`placement` не принимается) и пролога; plan.md — «Правка страницы» (файлы, scope, что удалить с `file:line`,
  сколько старого не трогается), ui-plan.md — «Правка страниц», строка в вопросе подписи.
- **INV-C19** — гейт сборки (`build_gate.section_problems` → `page_base.gate_problems`): построчный дифф копии базы с текущим файлом. Можно: правка
  внутри пролёта changed/removed (смежные пролёты сливаются — дифф склеивает соседние строки двух регионов в один хунк), вставка added между найденными
  соседями в предке (граничные строки соседей — не регион), правка import-операторов, вставка целых операторов между операторами верхнего уровня
  (новый локальный компонент рядом), пустые строки между операторами. Остальное — отказ с `file:line` и строкой; удалённый файл — нарушение.
  Стили (`.css/.less/.scss`) и файлы без копии базы — `unchecked` с причиной. `daiver_frame_baseline` показывает `outsideEdits` до гейта.
- **Standing.** У кадра с базой `daiver_verify_compare` пересчитывает сравнение снимка базы с тем же каноном, планом и правилами; ключи базы — её
  находки (и подавленные) и дефекты: (code, designId, prop), у дефекта без узла макета — (code, элемент по видимому тексту). Дефект: в регионе —
  `change`; вне регионов с ключом базы — `pre-existing`; иначе — `regression`; плюс `scope`. Блокирует: pre-existing — только при scope page
  (`verify_compare` и `state.is_blocking`), регрессия — всегда; три числа словами — в nextStep. Код-гейт классифицирует свои дефекты по
  `findings.json` / `code-findings.json` базы и не валится от pre-existing при scope change. Попутно: у EXTRA-дефекта `element` — видимый текст
  элемента страницы (было `null`); в verify-report метка `[regression]` рядом с `[pre-existing]`.
- **Хук.** `ui-guard`: цели записи — outputDir И `sources` кадров активного трека (без регистра); правила те же — шаг ui-build, подпись, инлайн-svg.
  Запись в outputDir при scope page не меняется: в треке рядом может быть кадр-модуль. `sources` — вход подписи (так было с 3.3): заявили страницу
  после подписи — подпись stale.
- **Лестница** (решение, отложенное 1.10): «записаны sources — built» (§3.2) не делаем — кадр-страница идёт через план и сборку своих регионов,
  built = все секции done.
- **Мутационная проверка** (одноразовый скрипт, monkeypatch): 17 мутантов (ключи базы, регионы и scope в classify, ключ по id, захват после начала
  сборки и у кадра без sources, CHANGE_CODES, scope в регионах, место пары без места, окна C19 / слияние / import / вставка между операторами,
  scope в verify-state, длина текста и каталоги зависимостей в поиске, элемент EXTRA) — убиты все.

**Не проверено данными** (боевой «ручной» страницы нет, всё — на синтетике): правило «изменение = структура и слоты, значения вне регионов —
старые расхождения» (дизайнер, сменивший только цвет или отступ, при scope change увидит его в preExisting ui-plan.md — выход scope page, решение
человека); доля узлов, которые матчер кода находит в чужом коде (алиасы `@/…`, условный рендер, компоненты из других файлов) — от неё зависят
`location` и окна C19 (ancestor = весь предок); страницы, чьи тексты приходят с сервера (поиск по текстам их не найдёт — роутер и вопрос
человеку); синтаксис маршрутов кроме `:id` / `[id]` / `{id}` / `$id`; Vue/Svelte (дерева кода нет — location пуст, C19 только по JS/TS);
как слабая модель правит чужой файл по `location` и удаляет removed.
