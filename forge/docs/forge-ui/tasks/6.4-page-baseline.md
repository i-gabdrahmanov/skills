# 6.4 — Правка существующей страницы (page baseline)

**Этап:** 6 · **Зависит от:** 6.3 · **Статус:** todo
**Спека:** §12.2, §13.7 (page), §14.4.6 (baseline.standing), §20.4 (proposeSources: MIN_TEXT_LENGTH 3,
limit 8, maxFiles 3000) · **INV:** C18, C19, F18 · **QG:** U22, P4

## Зачем
Страница написана людьми, не forge-ui. Изменение по макету правит её точечно и отличает свои
регрессии от старых расхождений.

## Что сделать
- На ui-design: «страница уже есть?» → `sources` — находятся по конвенциям проекта → роутеру →
  текстам страницы (инструмент **`daiver_propose_sources(track, frame)`**: тексты канона ≥ 3
  символов, до 8 кандидатов, обход до 3000 файлов), подтверждаются ЧТЕНИЕМ, не угадываются;
  `scope` change | page. Без sources — `blocked: no-sources`.
- Захват базы ДО правок кода: `daiver_screenshot` → `daiver_verify_compare(iterationDir=<frame>/baseline)`
  → `daiver_code_compare(iterationDir=baseline)` → `baseline:{kind:"page"}`. Пропуск — только если
  работающей страницы нет вовсе, и это говорится открыто.
- Сборка в файлы `sources`: место каждого региона `location` own/inside/ancestor (file:line из
  код-гейта); файл читается до правки (чужой код — домашний стиль); вне регионов ничего не
  реформатится, не переименовывается. `ui-guard` для scope page разрешает запись в sources, а не в
  outputDir.
- Verify: `baseline.standing` — каждый дефект классифицируется change / pre-existing / regression по
  ключу (code, designId, свойства rows) / (code, element), никогда по id дефекта; scope change —
  pre-existing не блокирует; scope page — считается всё; три числа словами в nextStep.

## Готово, когда
- `test_page_baseline.py`: синтетическая «ручная» страница + база → классификация standing при
  scope change и page; propose_sources находит файл по текстам; проверка «вне регионов дифф нулевой».
