## Зачем
Канон — единственный контракт между фазами: его пишет ingest, по нему режет outline, по нему
строит build, с ним сравнивает verify (те же схемы для `dom`- и `code`-моделей).

## Что сделать
`daiver/canon.py`:
- Конверт `{daiver:{version, role:"canonical", sourceFormat}, stats, root}`; `sourceFormat` ∈
  pixso | figma-json-a | figma-json-b | figma-html | dom | code.
- Узел: поля §6.3 (`id, kind, name, box, layout, size, style, text, font, color, children,
  variants, textProps, component, art, occluded, tag`), kind ∈ frame|text|instance|icon|image|vector|rect;
  `component.*` по §6.4 (figmaName, variants, content[{text, overridden, font, color, path}],
  textProps, childrenRole content|fallback, origin library|local|undecided, paints, sized own|master,
  childrenPath).
- Валидация (аналог zod): `validate(env) -> [проблемы]`, одно сообщение на все нарушения.
- Детерминизм чисел: `round(v) = round(v·100)/100`, альфа до 3 знаков; цвет — строка `rgba(r,g,b,a)`.
- `subtree_hash(node)` — 12 hex от минифицированного JSON с сортировкой ключей; `weight(node)` —
  байты минифицированного поддерева.
- Навигация: `find_node`, `ancestors_of`, `iter_nodes`; `collect_texts(node)` — с учётом
  `component.content` и textProps, дедуп «ребёнок-текст = TEXT-проп», без occluded.
- Запись/чтение канона минифицированным (`write_canonical`, `read_canonical`).
