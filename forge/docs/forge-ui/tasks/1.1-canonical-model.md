# 1.1 — Каноническая модель

**Этап:** 1 · **Зависит от:** — · **Статус:** done
**Спека:** §6 (6.1–6.5), §9.1 (subtreeHash), §16, §20.4 (округление) · **INV:** B1, B4, B5, B6, B10, B13 ·
**QG:** U5, часть U2

## Зачем
Канон — единственный контракт между фазами: его пишет ingest, по нему режет outline, по нему
строит build, с ним сравнивает verify (те же схемы для `dom`- и `code`-моделей).

## Что сделать
`daiver/canon.py`:
- Конверт `{daiver:{version, role:"canonical", sourceFormat}, stats, root}`; `sourceFormat` ∈
  pixso | figma-json-a | figma-json-b | figma-html | dom | code.
- Узел: поля §6.3 (`id, kind, name, box, layout, size, style, text, font, color, children,
  variants, textProps, component, art, occluded, tag`), kind ∈ frame|text|instance|icon|image|vector|rect;
  `component.*` по §6.4 (figmaName, variants, content[{text, overridden, font, color, path}],
  textProps, childrenRole content|fallback, origin library|local|undecided, paints, sized own|master,
  childrenPath).
- Валидация (аналог zod): `validate(env) -> [проблемы]`, одно сообщение на все нарушения.
- Детерминизм чисел: `round(v) = round(v·100)/100`, альфа до 3 знаков; цвет — строка `rgba(r,g,b,a)`.
- `subtree_hash(node)` — 12 hex от минифицированного JSON с сортировкой ключей; `weight(node)` —
  байты минифицированного поддерева.
- Навигация: `find_node`, `ancestors_of`, `iter_nodes`; `collect_texts(node)` — с учётом
  `component.content` и textProps, дедуп «ребёнок-текст = TEXT-проп», без occluded.
- Запись/чтение канона минифицированным (`write_canonical`, `read_canonical`).

## Готово, когда
- `test_canonical.py`: хеш стабилен к порядку ключей и форме чисел, меняется при правке поддерева
  (U5); валидация ловит неизвестный kind и лишние поля; тексты не теряются на любой глубине, включая
  resolved-внутри-resolved (B13); occluded не попадает в тексты (B6).

## Результат
`daiver/canon.py` + `test_canonical.py` (28 тестов). Решения там, где спека свободна:
- Валидатор строгий: неизвестное поле — ошибка, нарушения собираются списком с путями
  (`root.children[2].layout.gap`); обход итеративный (дерево глубиной 3000 не рвёт стек); id узлов
  обязаны быть уникальны; узел-арт без детей.
- Схема дополнена полями, нужным следующим задачам: `layoutHints` (1.7), `tokens` (привязанные
  стили, 1.5), `font.token`, `layout.crossGap` (wrap), `component.implName` (имя компонента
  реализации для dom/code), `schema` в конверте. Расширения — только правкой схемы и тестом.
- Числа: round(v·100)/100 с половиной вверх (как JS Math.round), alpha/opacity — 3 знака, целые
  без «.0»; ключи при записи сортируются — одинаковое дерево даёт одинаковые байты.
- `subtree_hash` — sha256 минифицированных байт поддерева, 12 hex; `weight` — их длина;
  `weights()` считает вес всех узлов за O(n) точной арифметикой сериализации (тест сверяет с
  `weight()` на случайных деревьях).
- `collect_texts`: occluded-поддерево исключено, `content` заменяет `textProps`, дедупликация по
  одному потомку на собственный текст инстанса; вложенный инстанс без своих текстов область
  дедупликации внешнего не закрывает.
- Цветовые функции (разбор, допуски) — в задаче 1.5/4.4; здесь только формат `fmt_rgba`.
