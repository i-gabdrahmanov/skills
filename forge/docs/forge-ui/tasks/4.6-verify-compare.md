# 4.6 — Подавление, группировка, id, жизненный цикл; daiver_verify_compare

**Этап:** 4 · **Зависит от:** 4.4, 4.5 · **Статус:** done
**Спека:** §14.4.6, §14.4.7, §16 · **INV:** C25, C28 · **QG:** U17, U16, F2, F4, X3

## Зачем
Сырые находки превращаются в дефекты, которые можно чинить: одна причина — один дефект, ничего не
пропадает молча, id дефекта переживает итерации.

## Что сделать
- `daiver/verify/suppress.py`: каскад structure → component → token → geometry → typography → color
  → pixel; находка раннего слоя глушит позднюю, только если СОДЕРЖИТ И ОБЪЯСНЯЕТ её (неверный
  элемент целиком → поддерево; разница текста → геометрия этого узла; токен → значение того же
  свойства того же узла). Не глушатся: один слой; уже подавленная не подавляет; ORDER не объясняет
  покраску; deprecated не объясняет ничего; ближайшая причина побеждает; пересчёт каждую итерацию.
  Подавленное хранится с `suppressedBy/suppressedReason`, счётчики по слоям — в отчёт.
- `group.py`: свёртка по общей причине с `coverage` (12 строк одним неверным gap — 1 дефект);
  находки, делящие только предка, не сливаются.
- `ids.py`: `id = hash(code|designId|implId|property)` — никогда от значений; значение поменялось —
  id прежний; разные свойства — разные id.
- `lifecycle.py`: new / persisting / fixed / regressed (частичный фикс — не регресс).
- Форма дефекта: `id, code, layer, severity, zone (deterministic|vision), element (по видимому
  тексту), rows (МАКЕТ|РЕАЛИЗАЦИЯ), pin/designPin, coverage, suppressedCount, lifecycle, designUrl,
  rule?, location?, noise`; каждый id узла — ссылка `[id](designUrl)` (§16).
- Инструмент **`daiver_verify_compare(track, frame?, iterationDir)`**: impl model → match → check →
  DS → suppress → group; пишет `impl-model.json`, `findings.json`, `defects.json`,
  `compare-summary.json` (+ пары для код-гейта). Hard gate fail (`matchRate < 0.5`) — гейты
  визуального слоя записываются skipped, код-гейт идёт; перед показом — сверка `implNodes` с
  `designNodes` и `readiness.domSettled` (полусобранный захват → перезахват). declaredNoise: прошлые
  `noise:true` и `false_positive` решения помечаются, не блокируют, выходят из `counts.blocking` и
  знаменателя fidelity. Метрики `matchRate` и `fidelity` — обе; `unmatched` > 0 читается вслух.

*Заметка (4.3).* `daiver_verify_compare` зовёт `daiver.verify.match.match(design, impl, plan)` и кладёт `pairs` в `compare-summary.json` (их читает код-гейт 4.7). Вывод матчера уже содержит `hardGate {pass, matchRate, min, reason?}` и `lowMatchRate` (текст про «второе число выглядит хорошо» в nextStep — за 4.6); `missing[]` уже схлопнут по LOW_MATCH_RATE, id находки MISSING = id узла макета, EXTRA — id узла страницы. `stats.outsideRegion` — хром вне региона (в находки не идёт). План читается из `plan.json` кадра (`plan.read_plan`/`match.read_plan` понимают `sections[].nodes[]`).

*Заметка (4.4).* `daiver.verify.check.check(design, impl, match_result, tolerances, flags)` отдаёт сырьё для каскада: `findings[]` с `code`, `layer`, `design`, `impl`, `prop` (ключ дедупликации), `severity`; `dismissals[]` с `reason`; `unverified {items, counts, summary}` — summary читается вслух рядом со счётчиком; `degraded[]` (упавшее правило — гейт degraded, не тишина); `executed`. Допуски передавай из `verify.tolerances` конфига. `flags` (`overflowing`/`scrolls` по id страницы) бери из `snapshot.json` — модель страницы их сбрасывает. EXTRA/MISSING/ORDER уже в `findings` (слой structure) с id матчера.

*Заметка (4.5).* DS-гейт — `ds_gate.run(design, impl, match_result, plan, lib, sources, colors, colors_file, react_found)`; всё нужное с диска даёт `ds_gate.gather(root, track, frame)` (`lib` может быть `None` + `libProblem` — тогда `ran:false`). `react_found` бери из `stats.react.found` модели страницы. Находки несут `code` (DS_*), `rule`, `design`/`impl` или `file`/`line`, `layer: "ds"` — в каскаде это отдельный слой (identity/props/tokens не глушатся геометрией). `parts.*.ran:false` с причиной читается вслух, как unverified. Скан исходников — `verify/tsx_scan.py` (общий с 4.7).

*Заметка (4.7).* Код-гейт читает `compare-summary.json` из папки итерации: `{pairs: [{design, impl}], defectIds: [...]}` (терпимо; другие поля игнорирует) — 4.6 обязан писать такую сводку ДО вызова `daiver_code_compare` и в `defectIds` класть id DOM-дефектов. Функции id и ссылки готовы: `code_compare.defect_id(code, design, impl, prop)` (у MISSING impl не входит — один id у DOM и кода), `code_compare.editor_link(template, root, file, line, column)` — используй их же для DOM-дефектов (`designLocations` в `code-summary.json` даёт file:line через пары). Жизненный цикл дефектов (появился/исчез/остался между итерациями) код-гейт НЕ применяет: он отдаёт дефекты со стабильными id в `code-defects.json`, цикл — за 4.6. Леджер: пятый гейт `code` с `status` из ответа (`pass | fail | skipped`, у skipped — `reason`); `fail` только при critical-дефектах кода. `match(..., descend_root=False)` — режим модели кода.

## Результат
Инструмент **`daiver_verify_compare(track, frame?, iterationDir)`** (`daiver/tools.py`, владелец — шаг `ui-verify`: шаблон `daiver_verify_*` в `phase_tools` теперь находит инструмент) и четыре модуля: `verify/{ids,suppress,group,lifecycle}.py` + `verify/verify_compare.py` (конвейер). Читает `snapshot.json`, записанный `daiver_screenshot` в ту же папку; пишет `impl-model.json`, `findings.json`, `defects.json`, `compare-summary.json` (в сводке — `pairs` и `defectIds` для код-гейта 4.7). Тесты: `test_suppress.py` (**13**), `test_verify_compare.py` (**39**: id, свёртка, жизненный цикл, конвейер на настоящем канон «Modal», `run` на настоящем треке); правки `ds_gate.py` (поле `slot` у токен-находок, DS_DEPRECATED — `minor`) и `code_compare.py` (id вынесен в `ids.py`).

- **Каскад** (`suppress.apply`): три объяснения — целиком неверный элемент (MISSING/EXTRA) → поздние слои его поддерева (макета и страницы); TEXT на узле → SIZE/POSITION этого узла; токен (DS_TOKEN_*) → COLOR того же свойства того же узла (fill→background, text→color, stroke→border). Не глушатся: один слой, уже подавленная находка как подавитель, ORDER, DS_DEPRECATED, DS-идентичность и пропы; ближайшая причина (глубже узел) побеждает; пересчёт с нуля. F4 — «высота корня» не глушит 16 цветовых находок. Подавленные хранятся с `suppressedBy`/`suppressedReason`; счётчики по слоям — в сводке (`layers`).
- **Свёртка** (`group.fold`): слои geometry/typography/color/shape, ключ — код + свойство + ПОДПИСЬ вида узла макета (вид + имя компонента/слоя): 12 строк с одним неверным gap — 1 дефект с `coverage: 12`; находки, делящие только предка, и все structure/component/DS — по одной; разные пары значений одного адреса остаются обе (`rows[]`).
- **id** (`ids`): `sha1(код|узел макета|узел страницы|свойство)[:12]`, не от значений (X3), у MISSING узел страницы не входит — один id у DOM- и код-гейта. Складной дефект получает id от «свойства у ВИДА элемента» (`fold_id`), а не от узла-представителя: частичный фикс 12 → 5 не меняет id (`persisting`, `coverageDelta`).
- **Жизненный цикл** (`lifecycle`): history — соседние папки итераций `verify/` по естественному порядку (iter-9 раньше iter-10, текущая не входит); new / persisting / regressed (исправлен и вернулся); fixed — списком в `defects.json` и ответе. declaredNoise — прошлые `noise: true` + `false_positive` из `verify/decisions.json` (формат закрепит 5.4): остаются в дефектах, не блокируют, выходят из blocking и знаменателя fidelity.
- **Метрики и статусы.** `matchRate` и `fidelity` — оба (fidelity — доля найденных элементов, то есть узлов с содержимым или дефектом, без блокирующих неправильностей); `unmatched` и LOW_MATCH_RATE читаются вслух в `nextStep` вместе с объяснением, почему второе число выглядит хорошо; `status`: `clean` | `defects` | `hard-gate-fail` (дефектов нет, находки — уликами, `pixel`/`vision` — skipped) | `recapture` (снимок не `ready` или недорисован: находок нет, nextStep — перезахватить). Блокируют critical и major без noise; `minor` предупреждает. OVERFLOW получает флаги `overflowing`/`scrolls` из `snapshot.json` (модель страницы их сбрасывает).
- **Форма дефекта**: `id, code, layer, severity, zone: deterministic, element (по видимому тексту), rows [{МАКЕТ, РЕАЛИЗАЦИЯ, count}], pin/designPin (боксы), coverage, suppressedCount, lifecycle, noise, designUrl, designLink ([id](url) или голый id), rule?, location?`. Зона `vision` и разметка пикселей — 5.x.
- **Мутационная проверка** (одноразовый скрипт): 34 мутанта (три правила каскада, слой, подавленный подавитель, ближайшая причина, сброс аннотаций, ключ свёртки, значения, складывание structure, id от значений, регресс, coverageDelta, шум, естественный порядок, текущая итерация, блокировка minor/noise, hard gate, знаменатель, слова про low/unmatched, перезахват, флаги, severity группы) — убиты все.

**Не проверено данными.** Боевых страниц и итераций нет: градация severity (critical/major — выбор 4.4); подпись вида для свёртки на реальных таблицах и списках (одноимённые слои разных видов сольются; безымянные «Frame 123» одного вида — тоже); fidelity на больших экранах; как слабая модель читает `status` и два числа; формат `decisions.json`.
