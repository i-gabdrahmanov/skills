# 5.1 — Эталонный рендер и пиксельный дифф

**Этап:** 5 · **Зависит от:** 4.2 · **Статус:** done
**Спека:** §14.6 · **INV:** F17 · **QG:** N15

## Зачем
Дифф картинок локализует зоны расхождения для человека и визуального обзора. Это сигнал, а не
вердикт: сам он дефекта не производит.

## Что сделать
- Инструмент **`daiver_render_reference(track, frame?, iterationDir)`**: HTML из канона
  (`data-daiver-id`-штампы; арт — из `.svg` трека, нет файла — помеченный блок, а не серый бокс;
  инстанс с неатрибутируемым боксом — bounded, не pinned; плейсхолдер-копия помечена; имя шрифта с
  кавычками внутри кавычек вычищается, чтобы не уронить хвост style); скриншот в ТОМ ЖЕ viewport в
  `iterationDir` + `reference-snapshot.json` (маркеры макета для отчёта).
- Инструмент **`daiver_visual_diff(track, frame?, iterationDir, against goal|reference)`**: дифф
  считается В Chromium (canvas) — свой порт алгоритма pixelmatch (дельта YIQ, порог, детект
  сглаживания) в `daiver/assets/pixeldiff.js`, без npm и без PNG-декодера на Python; выход —
  `diff.png` и полоса «макет | реализация | дифф» (3×, с промежутками); разные размеры — подложка на
  белый холст; идентичные — 0; процент возвращается ПРОЦЕНТОМ (3.18 = 3.18 %).
- Goal image: обрезка по `frameBox` (в образце — поля 24 px под тень) и подложка на белое
  (JPEG без альфы дал чёрные поля); goal правдивее reference — в ответе сказано, что использовано.
- Порог `visualDiffThreshold` — подсказка; зоны, объяснённые гейтом compare, повторно не
  комментируются; сглаживание и плейсхолдеры reference — не баги.

## Готово, когда
- `test_visual_diff.py` на синтетических PNG (пишутся stdlib-кодировщиком PNG в тесте): идентичные →
  0; известный сдвиг → ненулевой дифф в ожидаемой зоне; разные размеры — подложка; процент как
  процент; обрезка по frameBox (skip без Chrome); N15 — ненулевой дифф при пустых дефектах не
  делает вердикт fail.

*Заметка (4.1).* Дифф в Chromium считает вкладка, открытая клиентом из `daiver.browser.cdp` (`chrome.new_page("about:blank")`, затем `page.evaluate(скрипт)` и `page.screenshot()`); картинки в страницу несутся `data:`-адресом
или строкой base64 в `evaluate` — сообщение клиента ограничено 128 МБ (`ws.DEFAULT_MAX_MESSAGE`), для больших кадров режь на полосы. `check_url` пускает `data:` и `about:blank`, а `file:` — только в названных каталогах.

## Результат
Два инструмента: **`daiver_render_reference`** и **`daiver_visual_diff`** (оба — в `phase_tools` шага `ui-verify`). Код: `verify/reference.py` (HTML из канона), `verify/visual_diff.py` (оркестрация и объяснение зон), `daiver/assets/pixeldiff.js` (порт pixelmatch для canvas Chromium). Тесты: `test_visual_diff.py` (**30**: 9 без браузера на рендер HTML и чистую логику, остальное — настоящий Chrome; skip без него).

- **Эталон** (`reference.render_html`): канон → HTML со стампами `data-daiver-id` на каждом узле; auto-layout → flex (direction, gap, padding, align, wrap), абсолютные узлы → `position:absolute` по боксам относительно родителя, `fill` → flex/stretch, стили (фон, градиент, радиус, обводка по сторонам, тень, opacity), тексты и шрифты слотов инстансов (`content`, иначе `textProps`). Чего в каноне нет — не выдумывается, а ПОМЕЧАЕТСЯ пунктиром `#d0f`: арт без `.svg` — блок с подписью `art: slug` (не серый бокс), картинка и значок без арта — блок с видом, слот-плейсхолдер библиотеки (`overridden: false`) — `data-daiver-placeholder`, инстанс с неатрибутированным размером (`sized` не own, чисел нет) — `bounded`, а не прибит к размеру мастера. Имя шрифта очищается от кавычек, слэшей, `;`, скобок; значения цвета/тени/градиента — от символов, способных начать новое объявление; текст и атрибуты экранируются. Итеративно (глубокие деревья), детерминированно. `run` пишет `reference.html` и снимает его захватом 4.2 (`target: reference`) в том же viewport, обрезая по корню кадра: `reference.png` + `reference-snapshot.json`.
- **Дифф** (`pixeldiff.js`): порт pixelmatch v5 — дельта YIQ с альфой, порог `35215·threshold²` (0.1), детект сглаживания (`antialiased` + `hasManySiblings`, жёлтый и в счёт не идёт), бледно-серая подложка совпавшего; разные размеры — обе картинки на белом холсте максимального размера; картинка с прозрачностью — на белом (JPEG без альфы больше не даёт чёрных полей); процент — ПРОЦЕНТ с тремя знаками (1.25 = 1.25 %), 0 у идентичных. Зоны: ячейки 16 px, связные группы → прямоугольники (до 12, по весу). Выход: `diff.png`, `diff-strip.png` (полоса «макет | реализация | дифф» с промежутками 8 px), `visual-diff.json`.
- **Что с чем**: `against: goal` — картинка дизайна кадра (обрезка по `frameBox`, выход за картинку — отказ), `reference` — эталон; без `against` берётся goal, если он есть (правдивее), в ответе `used` говорит, что именно взято. Зоны, чьи ≥ 50 % площади накрывает пин дефекта compare (с учётом смещения clip), помечаются `explainedBy` и повторно не комментируются; остальные — материал для визуального обзора (5.2).
- **Сигнал, не вердикт (N15)**: ответ несёт `signal: true`, `gate: pass` (`skipped` без браузера), ключа дефектов в нём нет; `aboveHint` — лишь подсказка по `verify.visualDiffThreshold`; `daiver_verify_state_record` с ненулевым `diffPercent` и чистым сравнением остаётся `clean` (тест на настоящем треке).
- **Проверка порта**: независимый эталон на Python (по тому же описанию алгоритма) даёт те же `diffPixels` и `antialiasedPixels`, что JS в Chrome, на 8 парах — полосы, мягкая диагональная кромка (22 и 43 сглаженных пикселя), градиент, пара, найденная перебором, на которой решает граница «трёх равных соседей», случайные пары.
- **Мутационная проверка** (одноразовый скрипт): 26 мутантов (порог, сглаживание с одной стороны и вовсе, веса YIQ, подложка, обрезка, процент, зоны, промежутки, объяснение зон и сдвиг clip, выбор goal, frameBox, gate, mime, кавычки шрифта, экранирование, серый бокс вместо арта, bounded, плейсхолдер, сборка значений, окклюзия, абсолютные боксы, обрезка по корню) — убиты все; один мутант признан эквивалентным и снят — ветка альфы `a < 255` в `colorDelta` недостижима в нашем конвейере (всё кладётся на белое, данные canvas непрозрачны); она оставлена ради верности порту.

**Не проверено данными.** Боевых экранов нет: порог 0.1 на живых страницах (сглаживание шрифтов разных рендереров даёт «шум» зон), сходство эталона с настоящим рендером на сложных экранах (grid, text-transform), настоящая JPEG-картинка дизайна (стандартным кодировщиком в тесте её не построить: проверена ветка PNG и mime по заголовку), очень большие кадры (картинки уходят в страницу base64; предел сообщения клиента 128 МБ), точность совмещения goal и actual при `clipSelector` (зоны объясняются по смещению clip), шрифты макета, которых нет в системе, рисуются `sans-serif`.
