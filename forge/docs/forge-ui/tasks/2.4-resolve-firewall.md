# 2.4 — Firewall резолва: кандидаты, resolve_query, resolve_finalize

**Этап:** 2 · **Зависит от:** 1.8, 2.1 · **Статус:** done
**Спека:** §10.1, §10.2, §10.4, §20.4 (query: depth 2, maxNodes 48, maxTextLen 40) ·
**INV:** A7, B23, A2, A3 · **QG:** S11

## Зачем
Субагент выбора компонента видит ровно сигналы совпадения, а не геометрию и стили; его вердикт
проходит схему, а не верится на слово.

## Что сделать
`daiver/resolve.py`:
- Кандидаты: все `kind=instance` и фреймы с осмысленными именами (`header_bf_01` — да; Frame 123,
  Group 5, TEXT, Rectangle — нет); арт — не кандидат; простые фреймы — div.
- **`daiver_resolve_query(track, frame?, nodeId)`** — проекция: имя, варианты, КЛЮЧИ textProps без
  значений, figmaName/варианты вложенных инстансов (композиционный сигнал), текст до 40; без
  box/style/font/color; отпечаток поддерева по kind даже при капе; капы глубина 2 / 48 узлов с
  флагом усечения; неизвестный id — ясная ошибка. В ответ встроен результат `daiver_map_lookup`.
  *Контракт карты (2.1):* `component_map.lookup(root, figmaName, variants)` → `{hit, outcome, component, props, import, rule,
  confidence:"high"}`; `MapError` («карта некорректна») не глотать — резолв останавливается и называет проблему, а не идёт «как без карты».
- **`daiver_resolve_finalize(track, frame?, verdict)`** — схема `{nodeId, decision
  component|local|ignore, component?, props?, confidence high|medium|low, rationale,
  mapRuleProposal?}`: component без имени — отказ; имя при не-component — отказ; rationale
  обязателен и ограничен (≤ 400 символов); все нарушения одним сообщением. Принятый вердикт
  пишется в `.daiver/tracks/<KEY>/resolutions.json` (машинное хранилище движка).
- Переиспользование: кандидат с теми же figmaName+variants, что у записанного вердикта, получает
  его без нового резолва (INV-B23).

## Готово, когда
- `test_resolve.py`: проекция без значений слотов и геометрии; капы и флаг усечения; неизвестный
  id — ошибка; матрица валидации finalize; повторный кандидат берёт сохранённый вердикт.

## Результат
`daiver/resolve.py` (кандидаты `scan`, проекция `project`, форма вердикта `check_verdict`, хранилище `read_store`/`write_store`, разбор состояния
`analyze`, переиспользование, `candidates_frame` / `query_frame` / `finalize_frame`, `verdicts` для 2.5/2.6), в `tools.py` — три инструмента
**`daiver_resolve_candidates(track, frame?)`**, **`daiver_resolve_query(track, frame?, nodeId)`**, **`daiver_resolve_finalize(track, frame?, verdict)`**, три строки в
`EXPECTED_TOOLS`, абзац в брифе `SKILL.md`, `test_resolve.py` (173 теста: кандидаты, белый список проекции, капы, матрица формы вердикта, карта, библиотека,
INV-B23, хранилище и замок, поверхность S11). Мутационно проверено 75 правил (одноразовый скрипт: копия дерева, правка текста модуля) — 7 содержательно выживших с первого прогона
(вложенный закрытый узел, порядок выбора при капе, hit против эвристики с тем же ключом, порядок эталонов между кадрами и внутри кадра, не проглоченная ошибка
подстановки карты, эталон из записей карты) получили тесты, итог 75/75.

- **Данные образца.** «Modal» даёт 4 кандидата: корень-фрейм «Modal» (осмысленное имя) и три инстанса. Два «Modal Header» с вариантами `Steps=OFF` — один ключ
  `modalheader|Steps=OFF` (слоты `Header` и `Header,Description`): INV-B23 пинится на нём; «Modal Action» — слоты `Label×2` (два слота с одним именем — две кнопки, это
  сигнал состава). У инстансов образца нет детей и `textProps`: слоты Pixso живут в `component.content`, поэтому «ключ текстового слота» — `content[].name`. Проекция корня:
  `fingerprint instance=3`, три строки `tree`. Из настоящего канона в ответы резолва не попал ни один из пяти текстов слотов, ни шрифт, ни
  токен, ни цвет, ни ключи геометрии (тест строит набор «секретов» из `collect_texts` и стилевых слов канона).
- **Что видит резолвер (§10.2) — белый список, не вычитание.** `candidate` (id, kind, name, figmaName, variants, `textSlotKeys` — КЛЮЧИ без значений, origin — готовые
  аргументы `daiver_ds_lookup`), `tree` — потомки строками (`kind "имя" <figmaName> {варианты} origin= slots=`, у текста — сам текст ≤ 40; у потомков нет id, чтобы не
  звали чужое), `fingerprint` и `descendants` — по ВСЕМУ видимому поддереву (обрезка их не меняет), `truncated` / `hidden` / маркеры `… +N`, `occluded` (число узлов
  закрытых слоёв: они не контент экрана и в дерево и отпечаток не входят, но исключение названо). Глубина 2, 48 узлов вместе с кандидатом, текст 40 (§20.4); выбор при
  капе — по уровням (мелкие раньше глубоких), в документе — по порядку. Предков, соседей, значений слотов, geometry/style/font/color/tokens/tag/layoutHints в ответе нет;
  неизвестное будущее поле канона невидимо по построению (тест). Потолок размера — код: TREE_CHARS 8000 знаков на строки дерева, имена ≤ 64, варианты ≤ 8 пар по ≤ 32
  знаков, ключи слотов ≤ 8 по ≤ 32 (на враждебном входе дерево обрезается, `truncated`); на кандидате из 30 панелей по три настоящих инстанса образца проекция — менее 10 % поддерева.
  Рядом `map` — дословный результат `daiver_map_lookup` (для фрейма — по имени слоя); битая карта и подстановка, которую карта сделать не может, ОСТАНАВЛИВАЮТ резолв
  (`ResolveError`, а не «как без карты»); карты нет — промах с пометкой; имя без букв и цифр — промах без вызова карты.
- **Кандидаты (§10.1, `scan`).** Все `instance` и фреймы с осмысленным именем (`names.is_auto_name` — тот же предикат, что у ingest, плюс «хоть одна буква»); не кандидаты: арт,
  закрытое с поддеревом, внутренности библиотечного инстанса (`childrenRole: content`; предикат продублирован из `outline` и сверен тестом), `inferred:`-узлы, text/rect/vector/
  image. Каждый отказ называет причину (`why_not`) и ведёт к `daiver_resolve_candidates`; обход итеративный (3000 вложенных рамок). Решено сверх буквы §10.1: **`kind=icon` с
  `component` — кандидат** (icon-only инстанс коллапсируется в иконку с сохранённым component, §7.2; иконки резолвятся по карте/`icons.fallback`, §10.5), корневой фрейм с
  осмысленным именем — тоже кандидат (на «Modal» композиционный сигнал «Modal Header ×2 + Modal Action» говорит за компонент «Modal»).
- **Вердикт (INV-A7).** Поля — ровно `{nodeId, decision, component?, props?, confidence, rationale, mapRuleProposal?}`, схема в `tools/list` строится из тех же констант
  (тест S11). Форма: все нарушения ОДНИМ сообщением (`вердикт не принят (N): 1) … 2) …`, ничего не записано); неизвестное поле — нарушение; `component` — только при
  `component` и по JSX-правилам карты; `props` — только при `component`, значения строка/число/true-false, ≤ 30; `confidence` без дефолта; `rationale` ≤ 400 после схлопывания
  пробелов в одну строку (в таблицу отчёта 2.5 идёт одна строка); `null` у необязательных полей = «нет». Сверх формы код сверяет с тем, что сильнее модели: (1) узел — кандидат
  этого кадра; (2) **hit в карте** — вердикт обязан совпасть с правилом (decision, component, props строго — `false ≠ 0`, confidence high), запись `source: map`, расхождение
  отклоняется с продиктованным вердиктом (INV-B17: карта сильнее вывода; менять решение может человек правкой карты); (3) для того же figmaName+variants вердикт уже записан —
  принимается только он (INV-B23); (4) компонент без правила карты обязан быть в библиотеке по требованиям ДС (`Form.Item` — по корню `Form`; при `storybook-mcp`
  документов нет — проверка за MCP-сервером; требований нет/устарели — `blocked: library-source-unreachable`; проект не инициализирован — отказ), отказ называет «похожие по
  имени» и выход `local`; (5) `mapRuleProposal` проходит `daiver_map_append(dryRun)` (то же, что сделает запись после «да»), не противоречит вердикту и покрывает этот узел.
- **Переиспользование (INV-B23).** Ключ — figmaName (ключ имени карты: регистр и разделители не важны) + variants (точно, регистр значений важен): `modalheader|Steps=OFF`.
  Эталон ключа — самая ранняя запись резолвера (кадр по порядку манифеста, затем `seq`); остальные узлы ключа получают КОПИЮ (`source: reuse`, `from`, `fromFrame`) — в кадре
  сразу при записи эталона (в ответе `reused`), в других кадрах — при `daiver_resolve_candidates` (читающие вызовы пишут только когда есть что раздать). Копия несёт confidence и
  rationale эталона и **не повышает уверенность**; пересмотр эталона обновляет копии, копию напрямую пересмотреть нельзя. Не переиспользуются: фреймы и инстансы без figmaName
  (в спеке у них нет figmaName+variants), узлы с правилом карты (карта сверяется с каждым узлом: regex без флага `i` может ловить одно написание и не ловить другое при том же ключе),
  вердикты по карте между кадрами. Узлы с одним правилом карты и вердиктом идут группой тоже: один finalize пишет запись `map` всем.
- **Хранилище.** `resolutions.json` в папке кадра (`track.frame_paths`; для трека из одного кадра это `.daiver/tracks/<KEY>/resolutions.json`, как в задаче; со второго кадра — в
  `frames/<имя>/`, и `pull` уже называет его устаревшим при перетяжке требования). Формат `{schema, seq, verdicts:{nodeId: запись}}`, запись = вердикт + `source`, `key`, `kind`,
  `name`, `figmaName`, `variants`, `seq`, `from`. Атомарно (tmp + replace, байтами), под замком `ground/resolve.lock` (параллельные резолверы не теряют записи — тест на потоках и на
  процессах), ключи отсортированы, ни времени, ни случайности. Повреждённый или не прошедший проверку файл — отказ с названным файлом, а не сброс (удалить может человек). Годность записи
  проверяется при каждом чтении: узел всё ещё кандидат с тем же ключом, у hit — содержимое равно правилу, у копии — эталон на месте и совпадает; иначе `[stale]` в списке и причина в
  `stale`, узел решается заново.
- **`daiver_resolve_candidates` — третий инструмент, сверх списка спеки** (строка в README): кандидаты — детерминированная работа (INV-A1), а не «посмотри на outline». Показывает только
  нерешённое: строки `id kind "имя" <figmaName> {варианты} ×N [stale]`, ≤ 100 групп (`more`), `stats`; пустой список — кадр решён. Субагенту-резолверу id передаёт оркестратор (как инвентарь библиотеки).
- **Граница с 2.5 / 7.2 / 6.x.** Здесь НЕТ: политики подтверждений `workflow.confirmResolutions` («low — ВСЕГДА спрашивается, в автономии → local», INV-C6) — вердикт хранит `confidence` как есть,
  копии — эталона, поля «подтверждено человеком» в записи нет (форму решает 2.5, там же `resolution-report.md` и `icons.fallback`: как записать иконку без маппинга в рамках
  `component | local | ignore`, спека не говорит); автономного триажа (7.2); кандидатов state-кадров и shared-узлов изменения (§10.1 п.4–5 → 6.2/6.3). Для 2.5/2.6: `resolve.verdicts(root, track, frame)` отдаёт
  годные записи по id (чтение), перед планом зови `daiver_resolve_candidates` (раздаёт эталоны между кадрами); имя локального компонента из правила карты (`outcome: local` + `component`) в вердикт не
  входит — его берёт план из `daiver_map_lookup`; `nodeId` во всех записях — id канона, `source` различает `map` (в отчёт эвристик не идёт) и `resolver` / `reuse`.
- **Не проверено данными.** Боевых экранов и ДС нет: правило кандидатов (иконки-инстансы, корневой фрейм, доля автоимён), сигналы `origin` и `slots=`, размеры строк проекции и потолок 8000, группировка
  `×N` и то, как слабая модель читает `tree`, `reuse` и отказы, — выведены из текста спеки; строгость finalize (карта и библиотека сильнее вывода) — решение, не данные: если боевой прогон покажет, что она
  мешает (карта без учёта вариантов не умеет выразить «эта кнопка — другой компонент»), ослабить до предупреждения. Реальный MCP-клиент (GigaCode) не гонялся — JSON-RPC-сессия в тесте.
