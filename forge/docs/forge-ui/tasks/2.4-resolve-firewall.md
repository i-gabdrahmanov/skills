# 2.4 — Firewall резолва: кандидаты, resolve_query, resolve_finalize

**Этап:** 2 · **Зависит от:** 1.8, 2.1 · **Статус:** todo
**Спека:** §10.1, §10.2, §10.4, §20.4 (query: depth 2, maxNodes 48, maxTextLen 40) ·
**INV:** A7, B23, A2, A3 · **QG:** S11

## Зачем
Субагент выбора компонента видит ровно сигналы совпадения, а не геометрию и стили; его вердикт
проходит схему, а не верится на слово.

## Что сделать
`daiver/resolve.py`:
- Кандидаты: все `kind=instance` и фреймы с осмысленными именами (`header_bf_01` — да; Frame 123,
  Group 5, TEXT, Rectangle — нет); арт — не кандидат; простые фреймы — div.
- **`daiver_resolve_query(track, frame?, nodeId)`** — проекция: имя, варианты, КЛЮЧИ textProps без
  значений, figmaName/варианты вложенных инстансов (композиционный сигнал), текст до 40; без
  box/style/font/color; отпечаток поддерева по kind даже при капе; капы глубина 2 / 48 узлов с
  флагом усечения; неизвестный id — ясная ошибка. В ответ встроен результат `daiver_map_lookup`.
  *Контракт карты (2.1):* `component_map.lookup(root, figmaName, variants)` → `{hit, outcome, component, props, import, rule,
  confidence:"high"}`; `MapError` («карта некорректна») не глотать — резолв останавливается и называет проблему, а не идёт «как без карты».
- **`daiver_resolve_finalize(track, frame?, verdict)`** — схема `{nodeId, decision
  component|local|ignore, component?, props?, confidence high|medium|low, rationale,
  mapRuleProposal?}`: component без имени — отказ; имя при не-component — отказ; rationale
  обязателен и ограничен (≤ 400 символов); все нарушения одним сообщением. Принятый вердикт
  пишется в `.daiver/tracks/<KEY>/resolutions.json` (машинное хранилище движка).
- Переиспользование: кандидат с теми же figmaName+variants, что у записанного вердикта, получает
  его без нового резолва (INV-B23).

## Готово, когда
- `test_resolve.py`: проекция без значений слотов и геометрии; капы и флаг усечения; неизвестный
  id — ошибка; матрица валидации finalize; повторный кандидат берёт сохранённый вердикт.
