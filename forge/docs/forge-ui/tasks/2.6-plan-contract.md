# 2.6 — План секций, контракт готовности, подпись

**Этап:** 2 · **Зависит от:** 2.5 · **Статус:** todo
**Спека:** §11.5–11.6, §12.2–12.4, §20.4 (16 id проверок контракта) · **INV:** B12, C8, C9, D1, F6 ·
**QG:** U12

## Зачем
План — контракт для сборки; человек подписывает ровно прочитанное, а подпись умирает при смене
требования. Всё, что автономная сборка спросила бы, выясняется сейчас.

## Что сделать
- `daiver/plan.py` + инструмент **`daiver_plan_write(track, frame, plan)`** (отклонение от спеки:
  план пишет инструмент с валидацией, а не модель файлом — INV-A11): дерево секций; на узел
  `{component, props}` | `{resolution:"local"}` | `{resolution:"ignore"}`; у контейнеров дайджест
  раскладки из outline; ссылки на разделы спеки; `buildOrder` — РЕАЛЬНЫЕ id секций с хешами
  (сначала секции с общими local-компонентами, потом потребители, потом порядок документа;
  пролог — не секция). Пишет `plan.json` и человекочитаемый `plan.md`.
- **`daiver_plan_contract(track)`** — из ДИСКА: проверки `initialized, library-source, browser,
  requirement, canonical, plan, resolutions, assets, goal-image, specs, state, baseline, sources,
  implementation, dev-command, signature`, у каждой `{id, frame?, blocking, blockedReason, owner
  human|plan|host, detail, ask (дословный вопрос), degradesTo}`; `ready` (нет блокирующих),
  `complete` (нет и деградаций), `signed`; `planUncertainty` — каждый узел один раз; неразбираемый
  план ≠ pass.
- `ui-plan.md` — дайджест для ревьюера: кадры / секции / компоненты (+ local и почему) /
  дизайн-система (токены, несовпавшие цвета) / ассеты (+ плейсхолдеры) / бизнес-логика (спеки →
  e2e) / принятые деградации / открытые вопросы. Каждый факт — из артефакта.
- `plan.lock.json` — sha256 требований, `plan.json`, `resolution-report.md`, `ui-plan.md`. Подпись:
  `record_approval.py --key ui-plan-<KEY> --bind-file .daiver/tracks/<KEY>/plan.lock.json --evidence
  "<ответ>"`; `signed` = согласие есть и `bound_sha256` = текущему lock; re-pull → lock меняется →
  подпись stale.
- Brownfield-вопросы шага: url/open кадра, devCommand, sources, scope, baseline — в контракт как
  `ask`, ответы — `daiver_track_manifest`.
- `ui_gate.py design` по-настоящему: контракт `ready`, lock есть, подпись валидна.
- **Контракт для статуса (1.10):** лестница `daiver_status` читает у `plan.json` лишь наличие и разбираемость (JSON-объект), содержимое не читает — не ломать; неразбираемый план статус считает отсутствующим и называет в warnings (`artifact-unreadable`).

## Готово, когда
- `test_plan_contract.py`: матрица проверок контракта; неверный buildOrder (чужой id, хеш не тот)
  — отказ `plan_write`; подпись stale после re-pull; гейт design: 0 только при ready+signed.
