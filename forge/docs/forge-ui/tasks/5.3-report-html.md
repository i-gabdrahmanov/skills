# 5.3 — report.html: отчёт итерации

**Этап:** 5 · **Зависит от:** 4.8, 5.1 · **Статус:** todo
**Спека:** §14.10 · **INV:** C32 · **QG:** P6 (часть)

## Зачем
Человек решает по итерации глазами: макет и реализация рядом, пины дефектов, таблица значений —
до любых слов агента.

## Что сделать
Инструмент **`daiver_verify_report(track, frame?, iterationDir)`** (interactive; в автономии не
рендерится):
- Самодостаточный HTML без внешних ресурсов: обе картинки — data-URI; дата — из входа; одинаковый
  вход → одинаковые байты.
- Пронумерованные пины по списку дефектов; таблица МАКЕТ | РЕАЛИЗАЦИЯ; чипы-фильтры только из
  фактических кодов; имена свойств переведены на русский; экранирование против `</script>` в
  текстах; ссылки на узлы макета по nodeUrl; полоса кадров для мультикадрового трека, «не
  проверялся» у непроверенного кадра; встроенные ранее принятые решения.
- Путь отчёта сообщается пользователю ВСЕГДА; `stateRecorded:false` — сначала записать итерацию.

## Готово, когда
- `test_report_html.py`: одинаковый вход — одинаковые байты; `</script>` в тексте не ломает
  страницу; картинки — data-URI; чипы только для присутствующих кодов; полоса кадров при двух кадрах.
