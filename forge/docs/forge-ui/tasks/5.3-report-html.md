# 5.3 — report.html: отчёт итерации

**Этап:** 5 · **Зависит от:** 4.8, 5.1 · **Статус:** done
**Спека:** §14.10 · **INV:** C32 · **QG:** P6 (часть)

## Зачем
Человек решает по итерации глазами: макет и реализация рядом, пины дефектов, таблица значений —
до любых слов агента.

## Что сделать
Инструмент **`daiver_verify_report(track, frame?, iterationDir)`** (interactive; в автономии не
рендерится):
- Самодостаточный HTML без внешних ресурсов: обе картинки — data-URI; дата — из входа; одинаковый
  вход → одинаковые байты.
- Пронумерованные пины по списку дефектов; таблица МАКЕТ | РЕАЛИЗАЦИЯ; чипы-фильтры только из
  фактических кодов; имена свойств переведены на русский; экранирование против `</script>` в
  текстах; ссылки на узлы макета по nodeUrl; полоса кадров для мультикадрового трека, «не
  проверялся» у непроверенного кадра; встроенные ранее принятые решения.
- Путь отчёта сообщается пользователю ВСЕГДА; `stateRecorded:false` — сначала записать итерацию.

## Готово, когда
- `test_report_html.py`: одинаковый вход — одинаковые байты; `</script>` в тексте не ломает
  страницу; картинки — data-URI; чипы только для присутствующих кодов; полоса кадров при двух кадрах.

## Результат
Инструмент **`daiver_verify_report(track, frame?, iterationDir, date?)`** (в `phase_tools` шага `ui-verify`, зовёт субагент итерации после записи), модуль `verify/report_html.py`. Тесты: `test_report_html.py` (**20**, страницу разбирает stdlib-парсер).

- **Читает только артефакты итерации и состояние кадра**: дефекты — тем же кодом, что запись итерации (`state._derive` + решения человека `DEC.apply`), поэтому отчёт не может разойтись с тем, что запишет движок (dom + code + находки обзора; измеренное выигрывает у кода).
- **Самодостаточность**: обе картинки (макет — картинка дизайна, иначе эталонный рендер с подписью «реконструкция»; реализация) и дифф вшиты data-URI, CSS и скрипт внутри, шрифты системные; ни `<link>`, ни `<script src>`, ни `url(http…)`. **Дата — вход** (`date`, одна короткая строка), часы не читаются: одинаковый вход — побайтно одинаковый файл (ключи JSON отсортированы, порядок входных ключей решений не влияет).
- **Что на странице**: шапка (статус, matchRate, fidelity, дифф %, дата), баннер «итерация не записана» при `stateRecorded: false`, полоса кадров трека (текущий выделен; непроверенный назван «не проверялся»), две панели «макет | реализация» с пронумерованными пинами и зонами диффа (зелёные — объяснённые дефектами), панель диффа, гейты, чипы-фильтры только по фактическим кодам с числом, карточки дефектов: номер = номер пина, серьёзность, код и свойство по-русски («внутренний отступ слева», «слот s1: размер шрифта»), теги (жизненный цикл, ×покрытие, шум, отклонён, «не подтверждено (обзор)»), таблица МАКЕТ | РЕАЛИЗАЦИЯ | раз, ссылка на узел макета по nodeUrl, файл:строка, правило, ранее принятое решение человека (в том числе «переоткрыт: значения уехали»). Встроено `seeded-decisions` и `report-data` (JSON для 5.4).
- **Пины**: реализация — бокс дефекта минус левый верхний угол `clip` захвата, проценты от размера картинки; макет — `designPin` процентами от размера корня кадра (нет числового размера — пинов макета нет, и страница это говорит). Подпись пинов и фильтр работают скриптом без внешних библиотек (подсветка карточки ↔ пина, прокрутка по клику).
- **Экранирование**: текст и атрибуты — `html.escape` (с кавычками); JSON для скрипта — без `<`, `>`, `&`, U+2028/2029 (тест с `</script><img onerror>` в сообщении, элементе, заметке и имени решившего: число закрывающих тегов равно числу скриптов, JSON читается обратно побайтно).
- **Автономный режим** (`workflow.mode: autonomous`) — `rendered: false` с причиной; ответ всегда несёт `report` (путь), `stateRecorded`, `filters`, `ground`, и `nextStep` требует сообщить путь человеку ВСЕГДА.
- **Мутационная проверка** (одноразовый скрипт): 25 мутантов (экранирование JSON и HTML, кавычки, сдвиг clip, проценты, чипы, номера, пины макета без размера, таблица, переводы, ссылки, баннер, полоса кадров, автономия, проверка даты, решения, переоткрытие, vision-метка, зоны, data-URI, сортировка JSON, эталон) — убиты все; выжили три — дописаны тесты (экранирование атрибута, корень без размера, порядок ключей).

**Не проверено данными.** Вид на настоящих экранах (длинные таблицы, десятки дефектов), точность пинов макета при `frameBox` и масштабе картинки дизайна (считаются от размера корня канона), размер файла на больших кадрах (картинки вшиваются целиком), браузеры кроме Chromium; переключение кадров и один отчёт на весь трек — 6.1; кнопки решений, разметка «Пометить проблему» и экспорт `verify-decisions.json` — 5.4.
