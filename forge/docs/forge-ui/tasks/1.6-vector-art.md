# 1.6 — Векторный арт и svg-ассеты

**Этап:** 1 · **Зависит от:** 1.3 · **Статус:** done
**Спека:** §7.4, §6.3 (`art`), §13.5 п.6, §20.4 (`ICON_MAX` 64) · **INV:** B7, F5 · **QG:** U1, U23, F5, N6

## Зачем
Экспорт не несёт геометрию путей: иллюстрация приходит десятками шейпов. Её надо склеить в ОДИН
узел-арт, который строится из `.svg`-файла, а не рисуется кодом и не подменяется голым div.

## Что сделать
- `daiver/ingest/art.py` — `collapse_vector_art(root)`: группа шейпов → один узел с
  `art:{slug, nodes}` и id верхушки; одиночный вектор ≤ 64 px — кандидат в иконки, больше —
  арт (вордмарк, лого); НЕ коллапсировать поддерево с текстом, с инстансом, с bitmap, контейнер
  простых прямоугольников (фон), auto-layout контейнер; коллапс на ВЕРХНЕЙ арт-ноде.
- Slug: из осмысленного имени; автоимя → ближайший осмысленный предок; не-ASCII не
  транслитерируется — фолбэк; коллизии двух рисунков разводятся суффиксом.
- `collect_vector_art(root)` — список ассетов из уже схлопнутого дерева.
- Инструмент **`daiver_svg_assets(track, frame?, slug?, svgPath?, moduleDir?)`**:
  регистрация `.svg` (экспорт Pixso, как `Modal.svg` образца) в `<frame>/assets/<slug>.svg`;
  `missingArt` — слаги без файла; с `moduleDir` (используется на 3.2) — копия в модуль и точный
  import + JSX под `svg.render` (component — SVGR-импорт, url — `<img>`, inline). Нет файла — не
  блокер: placeholder правильного размера с меткой slug'а и названным недостающим файлом.

## Готово, когда
- `test_art.py`: веер из N безымянных фигур → одна арт-нода, slug стабилен между прогонами
  normalize (F5); группа с текстом/инстансом не коллапсируется; не-ASCII имя → фолбэк;
  `test_svg_assets.py`: регистрация идемпотентна, missingArt перечисляет без файла, JSX для трёх
  режимов `svg.render`.

## Результат
`daiver/ingest/art.py` (`collapse_vector_art`, `collect_vector_art`, `slugify`, `node_dims`), `daiver/svg_assets.py`
(инструмент `daiver_svg_assets`: список, регистрация, копия в модуль, JSX, placeholder), правки `ingest/pixso.py` (вызов
над готовым деревом — после иконного коллапса инстансов 1.4, до раскладки 1.7; `stats.art`; `stats.nodesOut` считает узлы
после склейки; `ICON_MAX` теперь одна константа — в `art.py`), `ingest/normalize.py` (сводка `art` в ответе normalize),
`tools.py` + `EXPECTED_TOOLS`; `test_art.py` (63), `test_svg_assets.py` (44). Мутационно проверено 48 правил в копии дерева
(текст/инстанс/bitmap, rect-контейнер, auto-layout, заливка фрейма, корень, граница ICON_MAX, порядок документа, ветки slug,
коллизии, идемпотентность записи, активное содержимое svg, границы moduleDir, placeholder, формы JSX, сводка normalize): 47
ловятся, один мутант эквивалентен (убрать `continue` после склейки — у склеенного узла уже нет детей).
- **Данные образца.** На экране «Modal» векторных групп нет: канон образца побайтно не изменился (3750 байт, `stats.art`
  нет). Векторы образца живут в определениях: 4 иконки-мастера (SYMBOL 24×24 с ОДНИМ составным VECTOR «Outline» 11–20 px) и
  скрытая булева операция [VECTOR, ELLIPSE]; GROUP в образце нет. На реальных данных (`OnFixtureAnatomy`) проверено: определение
  иконки, сделанное local, отдаёт виртуальный вектор 20 px — он остаётся иконкой-кандидатом (≤ 64), а те же данные ×6
  склеиваются в `art:{slug: "outline", nodes: 1}` по реальному имени слоя. Корпоративный `Modal.svg` (116 КБ, 648×293) валидатор
  принимает и читает его размер; в git файла нет, тестовые svg синтетические (шапка как у экспорта Pixso).
- **Правила §7.4 (как написано, кроме отмеченного).** Рисунок — поддерево из frame/vector/rect без `layout` и хотя бы с одним
  vector; текст, инстанс, иконка и bitmap внутри — не рисунок, поддерево из одних rect — фон. Коллапс — на верхней арт-ноде,
  корень не склеивается, id верхушки цел, `art.nodes` — число узлов канона с верхушкой; узел-арт минимален (kind=vector, id,
  name, box/size, occluded, `style.opacity`): заливка, обводка, тень, цвет и токены «запечены» в .svg — останься они в каноне,
  verify требовал бы их от `<img>`. Одиночный vector (фигура, булева операция или цепочка фреймов-обёрток вокруг одной): ≤ 64 по
  обеим сторонам — иконка-кандидат (остаётся как есть, `stats.art.iconCandidates`), больше хоть по одной — арт; размер решает
  верхушка и числа канона (два знака); размер fill/hug не доказательство (`sizeUnknown`). Группа из нескольких шейпов
  склеивается при любом размере.
- **slug.** Имя верхушки, иначе ближайший осмысленный предок; у инстанса-предка с автоименем или строкой вариантов
  («Steps=OFF») — имя компонента. В slug — латиница и цифры через «-» (camelCase режется, ≤ 48), не-ASCII отбрасывается, имя без
  латиницы и цифр (в том числе осмысленное, но не ASCII — подъём по предкам на нём останавливается) даёт фолбэк `art` и
  предупреждение; имена устройств Windows получают суффикс `-art`; коллизии — `-2`, `-3` в порядке документа и мимо естественных
  slug. Slug — чистая функция дерева: два прогона normalize (и другой порядок ключей источника) дают побайтно тот же канон (F5);
  повторный коллапс — тождество.
- **`daiver_svg_assets(track, frame?, slug?, svgPath?, moduleDir?)`.** Без slug/svgPath/moduleDir — арты кадра из канона,
  `missingArt` (occluded-арты файла не просят), осиротевшие файлы, предупреждение об устаревшем каноне. `slug` + `svgPath` —
  регистрация в `<кадр>/assets/<slug>.svg`: slug обязан быть в каноне; файл — настоящий svg (XML, корень `<svg>`, без DOCTYPE/
  ENTITY, скриптов, `on*=`, `javascript:`, ≤ 10 МБ); повтор — `unchanged` без перезаписи, другой файл — `replaced`. `moduleDir`
  (шаг ui-build) — копия в `<moduleDir>/<svg.assetsDir>/` и точные import + JSX под `svg.render`; moduleDir обязан лежать в
  `project.outputDir` и не в `.git/.daiver/.gigacode/node_modules`, `svg.assetsDir` — относительный, символическая ссылка наружу
  отвергается. Нет файла — не блокер: `<div data-art-placeholder="slug" role="img" …>ART MISSING: slug.svg</div>` размером узла
  (неизвестная сторона — min 32 px; inline-стили работают при любом `styling.mode`) и `missingFile` — какой файл положить.
- **Формы JSX (решение задачи: спека называет только режимы).** component — SVGR: `import XArt from "./assets/x.svg?react"`
  (`vite-plugin-svgr` в package.json) либо `import { ReactComponent as XArt } from "./assets/x.svg"` (`react-scripts`); без
  признаков загрузчика — `?react` и предупреждение в ответе. url — `import xUrl from "./assets/x.svg"` + `<img … alt="" />`
  (одна форма для всех сборщиков). inline — `import xMarkup from "./assets/x.svg?raw"` + `<span dangerouslySetInnerHTML={{ __html:
  xMarkup }} />` (разметку svg через контекст модели не гоняем; без `vite` в package.json — предупреждение). Путь импорта — от
  файла в корне moduleDir; `width`/`height` — из узла, когда это числа.
- **Сводка в normalize.** Ответ `daiver_normalize` несёт `art: {count, missingArt, next}` — иллюстрации без файла видны сразу
  (спека, статусные warnings: «иллюстрации без .svg … placeholder незамеченным не шипится»).
- **Отклонение (строка в README):** FRAME с собственной заливкой, обводкой или тенью не считается группой шейпов (иначе
  «кнопка-иконка: фрейм с фоном + глиф» стала бы картинкой) — уточнение к §7.4; рисунок внутри такого фрейма склеивается сам.
- **Не проверено данными (допущения):** вся группа §7.4 — на экране образца нет векторной группы (как Pixso отдаёт иллюстрацию:
  GROUP/FRAME с VECTOR/BOOLEAN_OPERATION, имена слоёв, попадает ли opacity верхушки в экспорт .svg); склейка малых групп из
  нескольких шейпов (иконки, нарисованные слоями) при любом размере — спека отдаёт порог ICON_MAX только одиночному вектору;
  россыпь шейпов рядом с текстом без общей группы не склеивается (синтетических групп коллапс не создаёт), каждый вектор судится
  как одиночный; позиционный суффикс slug — удаление первого из одноимённых рисунков в макете сдвинет slug следующего, и уже
  зарегистрированный файл окажется под чужим узлом: привязки файла к id узла нет (вернуться в 6.3, ревизии макета); формы import
  под сборщики и `?raw` для inline не прогонялись на реальном фронт-репо (README → «Нужно от пользователя»).
