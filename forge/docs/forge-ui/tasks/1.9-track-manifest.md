# 1.9 — Трек: track.yaml, кадры, goal image, source_nodes

**Этап:** 1 · **Зависит от:** 1.1 · **Статус:** done
**Спека:** §4.2, §11.4 п.1 (source_nodes), §20.4 (`MAX_PROBE_NODES` 40) · **INV:** B14, C2, A11, F1 ·
**QG:** U6

## Зачем
Трек = фронт-часть одной стори (имя трека = ключ стори, не выдумывается). Его манифест —
источник правды о кадрах, требованиях и их хешах; правится только инструментами.

## Что сделать
- `daiver/track.py`: `.daiver/tracks/<KEY>/track.yaml` — кадры `{name, dir, role
  screen|dialog|state|breakpoint, frameUrl, requirement{kind, path, sha256, pulledAt}, raster,
  frameBox, open, stateOf, url}`, `implementation{url, devCommand}`, `specs[]`; пути — от папки
  трека. Подписи планов в track.yaml НЕ храним — это согласия forge (`ui-plan-<KEY>`).
- Запись YAML — свой эмиттер в `yamlite.py` (подмножество, которое сам же читает; комментарии
  шапки сохраняются).
- Инструмент **`daiver_track_manifest(track, frame?, set{…})`**: url / open-рецепт (глаголы
  click, dblclick, hover, fill, press, select, waitFor, waitForGone, wait, scrollTo — без «выполнить
  JS») / role / stateOf / implementation / specs; проверка значений; неизвестное поле — отказ.
- Goal image: `rasterPath` → копия в папку кадра (`visual-requirements.png|jpg`) + `frameBox` —
  смещение кадра внутри растра (в образце поля 24 px под тень), обрезку делает 5.1.
- Инструмент **`daiver_source_nodes(track, frame, nodeIds[≤40])`**: читает raw-экспорт с диска и
  возвращает только декларации раскладки названных узлов (`horizontalConstraint`/
  `verticalConstraint`, autoLayout, sizing); файл целиком не возвращает никогда.
- Один кадр — файлы прямо в папке трека; переезд в `frames/<name>/` — 6.1, но все пути уже через
  манифест, чтобы 6.1 ничего не сломал.

## Готово, когда
- `test_track_manifest.py`: создать/обновить/прочитать track.yaml; неверные значения и неизвестные
  поля — отказ одним сообщением; sha256 требования записан; source_nodes отдаёт декларации узлов
  фикстуры, отказывает на > 40 id и не возвращает файл.

## Результат
`daiver/track.py`, `recipe.py`, `image.py`, `source_nodes.py`, инструменты `daiver_track_manifest` и
`daiver_source_nodes` в `tools.py`; `test_track_manifest.py` (30), `test_yamlite.py` (12).
- **Манифест**: `track, schema, created, frames[], implementation{url, devCommand}, specs[]`; кадр
  `name, role, dir, frameUrl, requirement{kind, path, sha256, pulledAt}, raster, frameBox, url, open,
  stateOf, notes`. Проверяется каждое поле; неизвестные поля — ошибка; шапка-комментарий сохраняется
  при перезаписи; запись атомарная; ключи в стабильном порядке.
- **Раскладка**: единственный кадр — `dir: "."` (в папке трека), со вторым все уезжают в
  `frames/<имя>` (правило уже в валидации — 6.1 переносит файлы); все пути артефактов кадра — только
  через `track.frame_paths()`.
- **Отклонения/решения**: `specs[]` — пути ОТ КОРНЯ РЕПО (не от папки трека, как остальные): спеки
  лежат рядом со стори, вне трека; `daiver_spec` теперь подхватывает зарегистрированные спеки.
  Подписей плана в манифесте нет — это согласие `ui-plan-<KEY>`. `stateOf` автоматически ставит роль
  `state` (и говорит об этом в `changed`); первичный кадр не может быть состоянием.
- **Растр**: `rasterPath` → `visual-requirements.png|jpg` по СОДЕРЖИМОМУ (расширение источника
  ничего не значит), прежний растр другого формата удаляется; размеры PNG/JPEG читаются по заголовку
  без библиотек. `frameBox` пока задаётся явно (поля под тень у образца: растр 648×293, кадр 600×245);
  автоматический расчёт — после pull (1.2) и в 5.1.
- **Рецепт открытия** (`recipe.py`): десять глаголов, «выполнить JS» нет и отказ это объясняет.
- **source_nodes**: декларации (`horizontalConstraint/verticalConstraint`, auto-layout без null,
  геометрия) для ≤ 40 узлов; синтетические `inferred:` пропускаются с причиной; файл не возвращается.
- **Попутно**: в `yamlite` исправлены дефекты, мешавшие записи/чтению назад — раскодировка `\\n`
  (последовательные replace), закрытие строки в flow после `\\`, ключ в кавычках как элемент списка,
  `#` после экранированной кавычки; добавлен эмиттер (`dumps`, `dump_scalar`, `split_header`),
  фаззинг: 18 000 структур замыкаются без расхождений. Слова-булевы YAML 1.1 (`y`, `n`, `on`…) как
  ключи пишутся в кавычках — чтобы PyYAML не прочёл их как булевы.
