## Зачем
Трек = фронт-часть одной стори (имя трека = ключ стори, не выдумывается). Его манифест —
источник правды о кадрах, требованиях и их хешах; правится только инструментами.

## Что сделать
- `daiver/track.py`: `.daiver/tracks/<KEY>/track.yaml` — кадры `{name, dir, role
  screen|dialog|state|breakpoint, frameUrl, requirement{kind, path, sha256, pulledAt}, raster,
  frameBox, open, stateOf, url}`, `implementation{url, devCommand}`, `specs[]`; пути — от папки
  трека. Подписи планов в track.yaml НЕ храним — это согласия forge (`ui-plan-<KEY>`).
- Запись YAML — свой эмиттер в `yamlite.py` (подмножество, которое сам же читает; комментарии
  шапки сохраняются).
- Инструмент **`daiver_track_manifest(track, frame?, set{…})`**: url / open-рецепт (глаголы
  click, dblclick, hover, fill, press, select, waitFor, waitForGone, wait, scrollTo — без «выполнить
  JS») / role / stateOf / implementation / specs; проверка значений; неизвестное поле — отказ.
- Goal image: `rasterPath` → копия в папку кадра (`visual-requirements.png|jpg`) + `frameBox` —
  смещение кадра внутри растра (в образце поля 24 px под тень), обрезку делает 5.1.
- Инструмент **`daiver_source_nodes(track, frame, nodeIds[≤40])`**: читает raw-экспорт с диска и
  возвращает только декларации раскладки названных узлов (`horizontalConstraint`/
  `verticalConstraint`, autoLayout, sizing); файл целиком не возвращает никогда.
- Один кадр — файлы прямо в папке трека; переезд в `frames/<name>/` — 6.1, но все пути уже через
  манифест, чтобы 6.1 ничего не сломал.

## Готово, когда
- `test_track_manifest.py`: создать/обновить/прочитать track.yaml; неверные значения и неизвестные
  поля — отказ одним сообщением; sha256 требования записан; source_nodes отдаёт декларации узлов
  фикстуры, отказывает на > 40 id и не возвращает файл.
