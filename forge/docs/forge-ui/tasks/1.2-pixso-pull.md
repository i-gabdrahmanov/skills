# 1.2 — Pixso pull: slim, raw-evidence, регистрация кадра

**Этап:** 1 · **Зависит от:** 1.0, 1.1, 1.9 · **Статус:** done
**Спека:** §3.3, §7.3 (pull, Slim), §4.2, §20.4 (диагностики материализатора) · **INV:** B3, C2, C3, F1 ·
**QG:** U10, N12

## Зачем
Сырой DSL (у модалки 490 КБ ≈ 150 тыс. токенов, у экрана — до 12 МБ) не должен проходить через
контекст модели. Инструмент берёт файл, худеет его и регистрирует кадр.

## Что сделать
`daiver/pixso/pull.py`, `daiver/pixso/slim.py`; инструмент **`daiver_pixso_pull(track, dslPath,
frameUrl, frame?)`**:
- Только `dslPath` (путь от корня репо). Инлайн-`dslJson` — отказ с объяснением (отклонение от
  спеки: payload через контекст запрещён INV-B3). `frameUrl` обязателен.
- Проверка, что это Pixso: `dsl.{pixTreeDslNodes, pixComponentTreeDslNodes, localStyleMap}`;
  коэффициент сжатия ≈ 1 → предупреждение «это не Pixso-экспорт»; оба вида (дерево/плоский
  список узлов) читаются одинаково.
- Slim: дерево экрана + определения, достижимые из него (`mainComponent`, `mainStateGroup`,
  `props[].componentId`, транзитивно), стили `localStyleMap`, на которые есть ссылки
  (`inherit*StyleID`), шрифты; остальное библиотеки и служебное редактора — выбросить. Одноимённые
  определения — слиты с флагом конфликта вариантов. Узлы slim валидны как узлы конверта.
- Запись в папку кадра: `visual-requirements.pixso.json` (slim) и `visual-requirements.pixso.raw.json`
  (минифицированный raw — evidence; сбой записи = предупреждение, pull не валится).
- Регистрация кадра в track.yaml (1.9): frameUrl, время, sha256 требования; ответ — ratio,
  nodesIn/Out, `screenRoots` (> 1 → «это N отдельных кадров»), счётчики диагностик
  (`MISSING_MAIN_COMPONENT`, `MISSING_COMPONENT_DEFINITION`, …), предупреждения: инстанс без
  определения; другой трек уже тянул этот URL.
- Кадр уже собран (build-state с done) — отказ «ревизии — задача 6.3» (до 6.3 не перезаписываем).

## Готово, когда
- `test_pixso_pull.py` на фикстуре 1.0: ratio > 1 и в ответе; slim проходит валидацию 1.1; raw
  записан; sha256 в track.yaml; повторный pull того же файла — тот же sha, без дублей кадра;
  произвольный JSON → отказ/предупреждение «не Pixso»; `dslJson` → отказ.

## Результат
`daiver/pixso/slim.py`, `daiver/pixso/pull.py`, инструмент `daiver_pixso_pull`; `test_pixso_pull.py` (17).
- **Формат определяется по структуре**, а не по сжатию: кадр, выгруженный вместе с одним компонентом,
  и так без библиотеки (образец: ×1.15). Отклонение от спеки («ratio ≈ 1 → не Pixso»): ratio
  сообщается числом, а «не Pixso» — только по структуре (`pixTreeDslNodes` с узлами `{guid, type}`).
  Плоский список узлов (вторая форма экспорта из спеки) пока не поддержан — образца нет.
- **Slim** — тот же формат DSL (нормализатор читает сырой и слимнутый одинаково): остаются дерево
  экрана и ДОСТИЖИМЫЕ определения; выбрасываются недостижимые определения, прототипные
  `overlay*`/`interactions`, `null`, неиспользуемые стили/шрифты/specialNode, незнакомые ключи верхнего
  уровня (названы в warnings; сырой лежит рядом). Пустые списки, `false`, нули — значения, не трогаются.
  Определения остаются по guid, а не сливаются по имени (экспорт ссылается по guid); совпавшие имена
  только считаются. Вес образца: 94 % — определения, 12 % снимает чистка полей, остальное — реальная
  библиотека на больших экранах.
- **Диагностики** (счётчик + до 5 примеров): MISSING_MAIN_COMPONENT, MISSING_COMPONENT_BASE (указана
  `mainStateGroup`, а её нет; её отсутствие у обычного компонента — норма: 58 из 135 инстансов образца),
  MISSING_COMPONENT_DEFINITION (6 подстановок слотов образца без определения), COMPONENT_EXPANSION_CYCLE.
  INFERRED_NESTED_INSTANCE_SWAP и VIRTUAL_HIERARCHY_CYCLE — при материализации (1.4).
- **Регистрация**: кадр и sha256 slim-файла в track.yaml; повторный pull того же экспорта — `unchanged`,
  манифест не переписывается; изменённый — удаляет канон, называет устаревшие `plan.json`/`plan.md`/
  `resolutions.json`; тот же `frameUrl` в другом треке — предупреждение.
- **Отказы с причиной**: `dslJson` (сырой через контекст запрещён), нет `dslPath`, `frameUrl` не
  http(s), не JSON / не Pixso, файл вне репо, собранный кадр (→ 6.3), второй кадр в треке (→ 6.1).
  Сбой записи сырого — предупреждение, pull продолжается.
- Абсолютный путь принимается, только если лежит под корнем репо (рантайм не пускает за его пределы).
