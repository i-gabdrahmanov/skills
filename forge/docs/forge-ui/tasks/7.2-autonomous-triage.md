# 7.2 — Автономный триаж verify

**Этап:** 7 · **Зависит от:** 7.1 · **Статус:** done
**Спека:** §14.12, §15.4 (таблица interactive vs autonomous) · **INV:** D8, D9, E4, E5, C31, F12 ·
**QG:** P5, N4, N5, N20

## Зачем
Без человека точка решения — триаж агента по каждому дефекту с записанной причиной, а остановка —
только clean, потолок итераций или отсутствие прогресса.

## Что сделать
- Автономный verify: report.html не рендерится; на каждый блокирующий дефект — `fix` (по умолчанию
  для deterministic; значение — из канона/спеки, никогда с картинки) / `skip` (с причиной: размер
  состояния макета, переопределение padding библиотеки, шелл приложения, противоречие спеке) /
  `noise` (артефакт сравнения, с причиной). `daiver_verify_state_record` в автономии отказывает без
  триажа по каждому блокирующему (skip без причины — дефект, который никто не ревьюит).
- Vision-пункт чинится только после собственного подтверждения по картинкам и только как измеренное
  значение или недостающий файл; Minor/noise не «чинятся ради закрытия».
- Стоп: clean; `capReached` (`workflow.autonomous.maxVerifyIterations`, по умолчанию 3, решение
  stop); `progress.stalled` (не лучше прошлой; регресс — тоже).
- Готовый `verify-decisions.json` в папке трека/кадра соблюдается ПЕРВЫМ (skip → declined,
  false_positive → noise) — решения человека автономия не отменяет.
- Таблица §15.4: medium — принят с пометкой `unconfirmed`; low — `resolution: local`
  (`outputDir/local/`, отмечено в плане и отчёте); иконка без маппинга — плейсхолдер с именем;
  предложение правила карты — блок «paste-ready» в отчёте, карта не пишется; URL — из ключей
  директивы, нет — `blocked: no-implementation`; dev-сервер — записанный devCommand (хелпер 4.9),
  нет — `blocked: implementation-unreachable`; модалка без рецепта — `blocked: no-open-recipe`.
- `verify-report.md`: frontmatter outcome + блок `### Триаж` на каждую итерацию (действие и почему
  по каждому дефекту) + кем закончен цикл; затем `daiver_run(finish:true)`.

## Готово, когда
- `test_autonomous_triage.py`: отказ записи без триажа; стоп по cap и stall; решения человека
  соблюдаются; N4 (нет записи конфига/карты, нет report.html, нет init), N5 (low → local), N20
  (vision-пункты не чинятся автономно).

*Заметка (2.5).* Подтверждение резолва сейчас требуется всегда, режим прогона не читается: «спрашивать или нет» решает одна функция
`resolution_report.confirm_reason(rec, threshold, icons_fallback)`, а `resolution_report.write/check` требуют согласия `ui-resolve-<KEY>`. В автономии те
же записи получают `unconfirmed` (medium; иконка-плейсхолдер при `ask` — просто плейсхолдер) и `local` вместо вопроса (low, N5), согласие не требуется,
а блок «Предложенные правила карты» отчёта уже есть («paste-ready»).

*Заметка (7.1).* Режим прогона — `run.mode_of(root, track)` (открытый `run.json`, иначе `workflow.mode`), а не `cfg["workflow"]["mode"]`: так уже читают `verify/state.py` (`mode`, `run`), `verify/report_html.py`, `implementation.resolve`. Политика прогона (`run.json` → `policy`: `verify.decision: triage`, `stop: [clean, cap, stall]`, `iterationCap`) записана при открытии — триаж и остановы читают её, а не конфиг. Конец автономного цикла — `daiver_run(track, finish: true)` (исход из истории verify, `note` — заметка чекбокса). Запрет D3 — `run.refuse_autonomous(root, что)`; init и запись карты уже отказывают, отчёт не рендерится.

## Результат

Без новых инструментов: режим прогона (`run.mode_of`, 7.1) читают запись итерации, решение, отчёт, резолв и захват. Код: `verify/state.py`
(`triage_entries`, `autonomous_decision`, `_cap`, отказы `decide` и открытия итерации после останова), `verify/verify_report.py` (режим из записи,
«### Триаж (итерация N)», кто закончил цикл по причине останова), `resolve.py` (low-компонент в автономии), `resolution_report.py` (`write` / `check`
без согласия, `unconfirmed`), `verify/capture.py` (записанный devCommand), `tools.py` (аргумент `triage` у `daiver_verify_state_record`). Бриф —
§5 «Автономный прогон». Тесты: `test_autonomous_triage.py` (**21**).

- **Триаж** (D8, E4): в автономии `daiver_verify_state_record` требует `triage` — `{id, action: fix | skip | noise, reason, confirmed?}` на КАЖДЫЙ
  блокирующий дефект и vision-пункт; без записи, без причины, с чужим id, повтором, неизвестным полем — отказ одним сообщением, ничего не
  записано. fix не-блокирующего (minor, noise, старое расхождение страницы) — отказ «не чинится ради закрытия»; fix vision — только `confirmed:
  measured | missing-file` (C31, N20). `decision` / `fixed` / `declined` в автономии не передаются, `triage` у человека — отказ.
- **Решения человека первыми** (D9): skip → declined, false_positive → noise, fix — записи триажа `by: human`; агент их не переворачивает (отказ),
  REOPENED-решение решает агент.
- **Решение и останов** выводит движок: clean → `clean`; иначе потолок итераций (`policy.verify.iterationCap` записи прогона, иначе
  `workflow.autonomous.maxVerifyIterations`; E5) → `stop: capReached`; застой (не лучше прошлой, регресс — тоже) → `stalled`; весь блок —
  skip/noise → `nothing-to-fix`; иначе `fix_all` / `fix_some` с `fixed` = fix-записи. Шум по слову агента итерацию чистой не делает: блокирующий
  остаётся блокирующим (чистоту дают только факты гейтов и решения человека). После останова новая итерация не открывается;
  `daiver_verify_decide` в автономии отказывает (решение человека там не пишется).
- **verify-report.md**: `mode` — из записи прогона; после итерации — блок «### Триаж (итерация N)»: id, действие, агент или человек,
  подтверждение, причина; «кто закончил цикл» — по причине останова. report.html не рендерится (7.1).
- **Резолв** (§15.4, N5): low-вердикт компонента в автономии — отказ `finalize` с выходом `decision: local` (не тихая подмена); ответ
  `daiver_resolve_report` — `autonomous: true`, `unconfirmed` (что человек обязан был увидеть), правила карты не спрашиваются (paste-ready блок
  в отчёте); гейт `check` не ждёт согласия, но ловит прежний low-компонент без него. Текст отчёта от режима не зависит (на нём держится lock плана).
- **Dev-сервер** (§14.12): автономный `daiver_screenshot` цели implementation поднимает ЗАПИСАННЫЙ `implementation.devCommand`, если адрес не
  отвечает, и гасит его после захвата всегда (`finally`); нет команды или сервер не поднялся — ответ `blocked: implementation-unreachable` с
  supply; у человека сервер не стартует никогда (INV-D4).
- **Мутационная проверка** (одноразовый скрипт, monkeypatch): 10 мутантов (неполный триаж, решения человека, vision без подтверждения, застой,
  потолок, noise закрывает, skip как fix, потолок не из политики, режим всегда interactive / autonomous) — убиты все.

**Не проверено данными** (автономного прогона на настоящем экране нет): как слабая модель пишет причины триажа (читаемы ли они человеку,
не шаблонны ли), доля skip/noise против fix на реальных дефектах; dev-сервер стартует и гасится на КАЖДЫЙ захват — время старта настоящего
vite/webpack не измерено (при долгом старте — держать сервер на всю итерацию, решение за X.4).
