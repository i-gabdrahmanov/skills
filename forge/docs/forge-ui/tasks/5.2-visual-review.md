# 5.2 — Визуальный обзор (рукопожатие двух вызовов)

**Этап:** 5 · **Зависит от:** 5.1, 4.8 · **Статус:** done
**Спека:** §14.7, §3.4 · **INV:** C30, C31, A8, F3 · **QG:** U19, N19, N20

## Зачем
Спросить модель ровно о том, чего измерение не видит (иконки, наложения, обрезка, порядок, сбои
рендера), и не дать ей «описать картинку, которую она не открывала».

## Что сделать
Инструмент **`daiver_visual_review(track, frame?, iterationDir, review?)`**:
- Первый вызов (без `review`) — собранный промпт, список картинок (goal ПЕРВОЙ, actual ВТОРОЙ) и
  `reportPath`; ничего не пишет.
  - Есть доказанные дефекты compare → вопрос сужается до ОСТАТКА: иконки/изображения, перекрытия и
    обрезка, перенос/усечение текста, визуальный порядок, сбои рендера; значения (px, HEX, шрифт)
    запрещены; таблица `expected` удерживается намеренно; «ничего не нашёл» — законный ответ.
  - Нет доказанных → полный обзор: семь осей, формат плана ремонта (Сейчас / Должно быть / Фикс /
    Проверка), числа обязательны, слова «слегка/примерно» запрещены.
  - `priorFixes` из `priorReview` → каждый прежний пункт FIXED / NOT FIXED / REGRESSED (пустой —
    отсутствует; `priorReview=null` — опустить, другой файл не подставлять).
- Второй вызов (`review=…`) пишет `visual-review.md` — это `priorFixes` следующей итерации.
- `verify.vision: off` или картинки не открылись → второй вызов отклоняется, гейт пишется `skipped` с
  `reviewSkipped`; руками `visual-review.md` не пишется (защищён 3.4).
- Под GLM 5.3 Flash: длинный экран режется на парные фрагменты goal/actual по высоте/секциям; PNG
  отдаётся как есть, не прочёлся — JPEG-копии через canvas (5.1).
- Находки обзора — неподтверждённые: `zone:"vision"`, `source:"review"`; показываются и триажатся,
  clean не блокируют никогда; автономия их не чинит (кроме самоподтверждённого измеренного значения
  или отсутствующего файла).

## Готово, когда
- `test_visual_review.py`: промпт в обоих режимах; `expected` не попадает в промпт остатка; разбор
  вердиктов priorFixes; отказ второго вызова при vision off; второй вызов пишет файл; геометрия
  нарезки длинного экрана.

## Результат
Инструмент **`daiver_visual_review(track, frame?, iterationDir, review?, prepare?)`** (в `phase_tools` шага `ui-verify`), модуль `verify/visual_review.py`; изменена запись итерации (`state.record`) — гейты `visualDiff` / `review`, `diffPercent`, находки обзора и `reviewReport` теперь берутся из артефактов. Тесты: `test_visual_review.py` (**36**), правки `test_verify_state.py` (52).

- **Первый вызов ничего не пишет** (проверено побайтным списком файлов): `images` (картинка дизайна ПЕРВОЙ, реализация ВТОРОЙ; нет картинки — эталонный рендер с оговоркой «реконструкция»), `prompt`, `reportPath`, `priorFixes`, `slices`, `mode`, `proven`. **Остаток** (есть доказанные дефекты `defects.json` + `code-defects.json` без noise): дефекты названы построчно как «код (свойство) — «элемент»» БЕЗ значений, таблица «макет | реализация» и `expected` в промпт не попадают (тест ищет в нём числа и слова колонок); спрашивается про иконки/изображения, перекрытия и обрезку, перенос и усечение текста, визуальный порядок, сбои рендера. **Полный обзор** (доказанных нет): семь осей, формат «Сейчас / Должно быть / Фикс / Проверка», числа обязательны, оговорки запрещены. `verify.vision: off` — первый вызов отдаёт `gate: skipped` с `reviewSkipped`, ответ второго вызова отказан (кроме `{skipped}`).
- **Второй вызов проверяет форму кодом, а не просьбой**: `opened` — перечень картинок РОВНО как в `images` и в том же порядке (иначе отказ: описывать неоткрытое нельзя, не открылись — `{skipped: причина}`); `prior` — вердикт FIXED / NOT FIXED / REGRESSED на каждый прежний пункт (пропущенные и несуществующие названы); пустой обзор принимается только как явное `nothingFound: true`; в остатке значения (px, %, rem, HEX, rgb/hsl) запрещены, в полном обзоре обязательны все четыре поля, числа в «Должно быть»/«Фикс», слова «слегка/примерно/чуть/немного/около/приблизительно» запрещены. Все нарушения — одним сообщением, при отказе не пишется ничего. Принятый ответ движок рендерит в `visual-review.md` сам (руками файл не пишется, хук 3.4) и в `visual-review.json`; возвращает находки как `zone: vision`, `source: review`, `severity: major` с id от оси и заголовка (не от формулировки).
- **priorFixes**: пункты раздела «## Fix plan» прошлого `visual-review.md`, путь — ТОЛЬКО из `reviewReport.path` последней записи `verify-state.json` (null → пунктов нет, соседний файл с пунктами не подставляется; путь вне `verify/` кадра не читается — предупреждение); пустой план и голый заголовок — нет пунктов; формат md разбирается тем же кодом, что его пишет (круговой тест).
- **Длинный экран**: `slices(height)` — полосы до 1200 px с перекрытием 48, последняя доходит до низа (геометрия пинится для ряда высот); `prepare: jpeg` (единственная запись первого вызова, только по просьбе) — JPEG-копии картинок и полос через canvas Chromium в `review-images/` (PNG, который GLM не прочёл, отдаётся запасным путём).
- **Запись итерации не верит словам агента про визуальные гейты** (принцип 3): `visualDiff` / `review` = pass только при `visual-diff.json` / `visual-review.json` в папке итерации, иначе `skipped` с причиной (`reviewSkipped` агента) и предупреждением; `fail` у этих двух отказан («сигнал, а не вердикт»); `diffPercent` берётся из `visual-diff.json` (расхождение — warning, без артефакта — отброшено: 0.0318 вместо 3.18 больше не пролезет); находки обзора и `reviewReport {path, mode, nothingFound}` берутся из артефактов, vision-пункты чистоту не блокируют (тест на настоящем треке).
- **Мутационная проверка** (одноразовый скрипт): 31 мутант (нарезка: перекрытие, низ, порог, ранняя остановка; раздел плана; noise и значения в строках; запрет значений в промпте; opened; пустой обзор; nothingFound; значения в остатке; оговорки, числа и поля в полном; prior: пропущенные, неизвестные, без плана; vision off и ответ при off; режим по доказанным; порядок картинок; skipped пишет файл; путь вне verify; «последняя запись»; зона; гейты, процент и находки в записи) — убиты все. Первый прогон выжил на «последняя запись» (хватало одной итерации) — добавлен тест на две; мутанты нарезки сперва зациклили скрипт (он убит по памяти, файл остался мутированным — восстановлен вручную: мутант без выхода из цикла теперь исключён из набора).

**Не проверено данными.** Боевой модели-читателя нет: насколько GLM следует форме ответа и честно ли пишет `opened` (его честность проверить нечем — только форма); регулярки значений и оговорок — грубая сеть, а не разбор смысла (русская морфология шире списка); порог нарезки 1200 px — подбор, не измерение; читает ли GigaCode PNG (запасной путь — `prepare: jpeg`); формулировки промпта на слабой модели.
