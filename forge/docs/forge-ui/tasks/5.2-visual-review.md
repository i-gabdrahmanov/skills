# 5.2 — Визуальный обзор (рукопожатие двух вызовов)

**Этап:** 5 · **Зависит от:** 5.1, 4.8 · **Статус:** todo
**Спека:** §14.7, §3.4 · **INV:** C30, C31, A8, F3 · **QG:** U19, N19, N20

## Зачем
Спросить модель ровно о том, чего измерение не видит (иконки, наложения, обрезка, порядок, сбои
рендера), и не дать ей «описать картинку, которую она не открывала».

## Что сделать
Инструмент **`daiver_visual_review(track, frame?, iterationDir, review?)`**:
- Первый вызов (без `review`) — собранный промпт, список картинок (goal ПЕРВОЙ, actual ВТОРОЙ) и
  `reportPath`; ничего не пишет.
  - Есть доказанные дефекты compare → вопрос сужается до ОСТАТКА: иконки/изображения, перекрытия и
    обрезка, перенос/усечение текста, визуальный порядок, сбои рендера; значения (px, HEX, шрифт)
    запрещены; таблица `expected` удерживается намеренно; «ничего не нашёл» — законный ответ.
  - Нет доказанных → полный обзор: семь осей, формат плана ремонта (Сейчас / Должно быть / Фикс /
    Проверка), числа обязательны, слова «слегка/примерно» запрещены.
  - `priorFixes` из `priorReview` → каждый прежний пункт FIXED / NOT FIXED / REGRESSED (пустой —
    отсутствует; `priorReview=null` — опустить, другой файл не подставлять).
- Второй вызов (`review=…`) пишет `visual-review.md` — это `priorFixes` следующей итерации.
- `verify.vision: off` или картинки не открылись → второй вызов отклоняется, гейт пишется `skipped` с
  `reviewSkipped`; руками `visual-review.md` не пишется (защищён 3.4).
- Под GLM 5.3 Flash: длинный экран режется на парные фрагменты goal/actual по высоте/секциям; PNG
  отдаётся как есть, не прочёлся — JPEG-копии через canvas (5.1).
- Находки обзора — неподтверждённые: `zone:"vision"`, `source:"review"`; показываются и триажатся,
  clean не блокируют никогда; автономия их не чинит (кроме самоподтверждённого измеренного значения
  или отсутствующего файла).

## Готово, когда
- `test_visual_review.py`: промпт в обоих режимах; `expected` не попадает в промпт остатка; разбор
  вердиктов priorFixes; отказ второго вызова при vision off; второй вызов пишет файл; геометрия
  нарезки длинного экрана.
