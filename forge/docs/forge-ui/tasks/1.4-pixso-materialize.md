# 1.4 — Pixso → канон: материализация инстансов

**Этап:** 1 · **Зависит от:** 1.3 · **Статус:** done
**Спека:** §7.3 (Materialize — все пункты), §6.4, §6.5, §20.4 (`UNMATCHED_LIST_LIMIT` 20, коды
диагностик) · **INV:** B4, B5, B6, B13 · **QG:** U27, U2

## Зачем
В образце дерево экрана — фрейм и 3 инстанса без детей; вся анатомия и все тексты — в 20
определениях компонентов. Без материализации канон пуст, и сравнивать будет нечего
(«картинка против разметки», §6.4).

## Что сделать
`daiver/ingest/materialize.py`:
- Определение инстанса: `mainComponent` → узел в `pixComponentTreeDslNodes` (на любой глубине;
  вложенный инстанс → его мастер; swap — следовать); набор вариантов — `mainStateGroup`.
- Слоты и `component.content`: тексты мастера (`PARAGRAPH.nodeText`, overridden=false — плейсхолдер
  библиотеки) поверх — оверрайды инстанса из `props[]` по `pathString` (`nodeText`,
  overridden=true — копия экрана); у каждого слота путь `<instance>;<path>` (две ячейки не делят
  id), `font`, `color`. Скрытые слоты (`propAssignMap` type visible=false, дефолт `propDefMap`) —
  прячутся. Оверрайд, не легший ни на один слот, — в `stats` с именем инстанса (до 20).
- Варианты — из `propRefMap` (`variant`); TEXT-свойства — в textProps, не в variants.
- `origin`: опубликованное определение (`publishFile`) → library (чёрный ящик, свой content);
  определение без публикации → local (анатомия детьми, `childrenRole: fallback`); вложенные
  library-инстансы внутри local остаются чёрными ящиками; ничего не опубликовано → undecided.
- `paints`: мастер красит поверхность (fill/stroke) там, где инстанс состояний не показывает;
  векторная краска арта — не поверхность. `sized`: бокс инстанса vs бокс определения → own/master/
  тишина (определения нет).
- Окклюзия: закрыто поздним НЕПРОЗРАЧНЫМ слоем → `occluded:true`, из текстов исключено;
  полупрозрачный backdrop ничего не закрывает.
- Диагностики → `stats.materialization`: MISSING_MAIN_COMPONENT, COMPONENT_EXPANSION_CYCLE,
  MISSING_COMPONENT_DEFINITION, MISSING_COMPONENT_BASE, INFERRED_NESTED_INSTANCE_SWAP (≥ 5
  голосов), VIRTUAL_HIERARCHY_CYCLE — счётчики качества входа, не дефекты страницы.

## Готово, когда
- `test_materialize.py` на фикстуре: заголовок, «Количество документов - 20», описание, кнопки
  «Отмена»/«Подтвердить» есть в content с overridden=true; плейсхолдеры мастера («Кнопка») —
  overridden=false; слот «Info» скрыт (propAssignMap); origin library у опубликованных; циклы не
  вешают процесс; синтетика: окклюзия непрозрачным/полупрозрачным слоем, sized own/master.

## Результат
`daiver/ingest/materialize.py` (класс `Materializer`), `daiver/ingest/paint.py` (предикаты красок —
общие с 1.5), правки `ingest/pixso.py` (раскрытие инстанса, окклюзия, icon-коллапс, размеры);
`test_materialize.py` (74), 1.3-тесты обновлены под настоящие размеры и `origin/childrenRole`.
Правила выведены по ДАННЫМ образца и сверены с его картинкой (записаны в README фикстуры и docstring
`materialize.py`); тесты мутационно проверены (выключение видимости, рангов оверрайдов, окклюзии,
иконок, подмен, анатомии local — каждое ловится).
- **Канон образца.** Шапка 1: один слот «Header» (overridden=true), Description скрыт присвоением;
  шапка 2: «Header» + «Description»; блок действий: «Отмена» (`2:170352/2:170446`, overridden=**false** —
  настройка библиотеки) и «Подтвердить» (`2:170353/2:170486`, true — текст экрана). Все три — `library`,
  `childrenRole: content`, `sized: own`; ширина блока действий — 560 (запись корня), а не 600 узла.
  Слотов 5, переопределённых 4, скрытых 4; без потерь: `collect_texts` отдаёт те же 5.
- **Модель оверрайдов** (то, что спека называет «join master-текстов × override'ов»): цепочка guid в
  `pathString` начинается с прямого ребёнка мастера; запись с `pathString == mainComponent` — корень с
  настоящей геометрией; слои: экран (ранг 0) сильнее настроек библиотеки (ранг = глубина), поля слоёв
  складываются; видимость — узел → свойство (`propAssignMap` ближайшего инстанса, иначе `propDefMap`
  владельца определения) → запись оверрайда; скрытый узел скрывает поддерево, но его оверрайд не
  «потерянный». `componentId` записи, нацеленной на вложенный инстанс, — его `mainComponent` (21 из 21).
- **Размеры берутся из записи корня:** у шапки узел 600×64, настоящие 560×44 и 560×80; `size.w/h` и
  `box` с числовым намерением пишутся настоящими; `sized` — настоящий размер против размера варианта.
- **`origin`:** `publishFile` у определения/варианта → library; нет, но в экспорте публикуется хоть
  что-то → local (анатомия детьми с id `<инстанс>;<цепочка>`, оверрайды применены, скрытое отброшено,
  вложенные library-инстансы остаются инстансами и получают пере-базированные записи экрана);
  ничего не опубликовано → undecided (чёрный ящик, как library). `childrenPath` — пути прямых детей.
- **Диагностики** в `stats.materialization` (счётчики + до 5 примеров): MISSING_MAIN_COMPONENT,
  MISSING_COMPONENT_BASE, MISSING_COMPONENT_DEFINITION (инстанс без определения и подмена слота на
  отсутствующий компонент; скрытые ветки счётчики не наращивают), COMPONENT_EXPANSION_CYCLE (самовложение и взаимное, в том числе у local-
  композиций — на цикле анатомия не раскрывается). `overridesUnmatched` — до 20 записей `{instance, id, path, text}` при полном счётчике.
- **Окклюзия:** закрыт, если у того же родителя выше по порядку рисования лежит FRAME/RECTANGLE со
  сплошной заливкой альфы 1, opacity 1, обычным режимом наложения, чей бокс целиком накрывает бокс
  узла (допуск 0.5); backdrop с альфой < 1, градиент, скрытая заливка ничего не закрывают; флаг ставится
  на верхушку поддерева, узел остаётся в дереве, из `collect_texts` исключён.
- **Иконки:** library/undecided-инстанс без видимого текста, с видимой векторной анатомией, без
  поверхности (`paints`) и ≤ 64×64 (по настоящему размеру) → `kind=icon`, `component` сохранён, детей нет.
  Корень экрана с автоименем остаётся фреймом, но тексты мастера раскрываются детьми (контракт «текст
  не теряется»).
- **Отклонения/ограничения (названы):**
  - `overridden` у настроек библиотеки — **false**, как в §6.4 («false = плейсхолдер библиотеки»);
    фраза §7.3 «overridden:true … и для definition-дефолтов» противоречит ей — взята таблица §6.4;
  - `font`/`color` у слотов `content` — в 1.5 (нужен конвертер красок и шрифтов, общий со всеми узлами);
  - «labeled placeholder пустого resolved-инстанса» не вводится отдельным полем: такой инстанс уже
    помечен `component.figmaName`, а число их — `stats.emptyInstances` (метка в канон без потребителя
    не нужна, потребитель — 2.x при резолве);
  - **INFERRED_NESTED_INSTANCE_SWAP** (≥ 5 голосов) и **VIRTUAL_HIERARCHY_CYCLE** не реализованы: в
    образце нет ни подмены через `componentId`, ни виртуальной иерархии — выводить правила не по чему
    («ничего не выдумывать»); подмена слота через `propAssignMap` (тип `instance`) работает и покрыта
    синтетикой;
  - TEXT-свойства компонента (`propAssignMap` типа `text`) пока только как `textProps` при пустом
    `content`; привязка к текстовому узлу (`propRefMap`) в образце не встречается.
- Скорость: 3000 инстансов × 6 уровней вложенности (756 тыс. слотов) — 1.5 с.
