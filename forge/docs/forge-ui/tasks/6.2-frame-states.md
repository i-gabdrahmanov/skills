# 6.2 — Состояния экрана (stateOf)

**Этап:** 6 · **Зависит от:** 6.1 · **Статус:** todo
**Спека:** §10.1 (кандидаты состояния), §13.6, §14.4.6 (state.verdict), §20.4 (`SAME_SCREEN_SIMILARITY`
0.6) · **INV:** C4 · **QG:** U21, P3

## Зачем
Кадр «ошибка», «пусто», «раскрыто» — это состояние экрана, а не второй экран: строится ВНУТРЬ
модуля экрана как регионы и переключатель, проверяется на URL экрана.

## Что сделать
- Инструмент **`daiver_frame_states(track, frame)`**: кадр-состояние против своего экрана (схожесть
  ≥ 0.6 и корни одной ширины ±1 px) → регионы `shared` (стабы с base-id), `added`, `removed`,
  `changed` (+ `changes`: вариант/текст/цвет; `consequence:true` — высота/позиция от контента — не
  пинятся никогда); `available:false` — чинить причину, а не планировать от целой страницы;
  `triggers` — кандидаты-переключатели.
- `daiver_section` для кадра-состояния отдаёт ДЕЛЬТУ региона (хеш региона = хеш дельты).
- Резолв: кандидаты — только внутри регионов; changed-инстанс с тем же компонентом сохраняет
  вердикт экрана с новым пропом.
- План: `stateOf` — имя переменной состояния и её значения (`decision: yes|no`), переключатель
  (из triggers или названный пользователем); сборка — переменная, управление и условие на регион в
  коде экрана; outputs — по регионам.
- Verify: URL экрана + рецепт открытия; `state.verdict` по эксклюзивному контенту обоих макетов
  против одного захвата (только уверенные пары): reached / not-reached (→ hard gate fail, причина —
  рецепт, дефекты не показываются) / ambiguous (смотреть actual.png) / unknown.
