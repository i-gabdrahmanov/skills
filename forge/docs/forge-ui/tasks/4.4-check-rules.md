# 4.4 — Правила проверки, допуски, dismissals, unverified

**Этап:** 4 · **Зависит от:** 4.3 · **Статус:** done
**Спека:** §14.4.3, §14.4.4, §5.1 (`verify.tolerances`) · **INV:** C27, B16 · **QG:** U16, F3

## Зачем
Каждое правило куплено на реальных прогонах: ложный дефект так же вреден, как пропущенный. Всё,
что не стало дефектом, выводится с причиной — молча не дропается.

## Что сделать
`daiver/verify/check.py`:
- Коды и слои: structure (MISSING/EXTRA/ORDER/TEXT) → component (SLOT_MISSING, SLOT_TEXT,
  SLOT_TYPOGRAPHY, SLOT_COLOR, INVISIBLE) → token → geometry (SPACING, SIZE, POSITION, OVERFLOW) →
  typography → color → shape (SHAPE).
- Допуски из конфига, каждый со своим дефолтом: px 2, color 2 на канал (с альфой), fontSize 0.5,
  lineHeight 1, sizeRatio 0.01 (только размеры), sizeRatioMaxPx 8. «На грани» не срабатывает;
  размер в пропорции, но сверх капа — репорт.
- Доктрины §14.4.3 по списку: числовые — только на уверенных парах; сравнивается то, что компонент
  РЕНДЕРИТ (только overridden-слоты; SLOT_TYPOGRAPHY+SLOT_COLOR на двух слотах ячейки — подсказка
  «перепутаны caption/value»); SIZE на resolved-компоненте только при `sized:"own"`; согласный
  обеим сторонам внутренний padding/gap/radius/border — контракт библиотеки (dismissal), но
  INVISIBLE — дефект; выведенный размер (hug/fill/высота текста/line box шрифта) — dismissals,
  «тот же текстовый бокс короче» — репорт; padding по сторонам; margin vs gap при равных боксах —
  dismissal; корневой фрейм и «число макета больше комнаты родителя» — dismissal; типографика (первое
  семейство, пропущенный вес = Regular, text-align/lineHeight — только где обе стороны объявили);
  цвет (hex/keyword = rgba, нет заливки = transparent, градиент — текстом); форма (радиус — что рисует
  браузер, 50 % круг ≠ дефект, присутствие обводки и тени); текст (normalizeText, разная копия —
  critical, только регистр — dismissal, пустой слой не толкуется); overflow; падение правила →
  гейт degraded, остальные идут; «пар нет» — правила считаются исполненными.
- Unverified — третий выход: аспекты `content`, `copy`, `size` для инстансов без определения;
  зачитываются вслух рядом со счётчиком дефектов.

## Готово, когда
- `test_check.py`: F3 — +3 px позиции, Δ3 цвета на канал, fontSize Δ1, размер 1.5 % в пределах и
  сверх капа, изменённый текст → ожидаемые коды; внутри допуска — dismissal, не дефект; по тесту
  на каждую доктрину; unverified по трём аспектам.

*Заметка (4.3).* Матчер готов: `from daiver.verify import match as MT; res = MT.match(design_env, impl_env, plan)`. Пары — `res["pairs"]` (`design`, `impl`, `anchor`, `confidence`); у `confidence: low` числовые правила пропускаются со счётчиком (`stats.lowConfidence`), identity-правила работают всегда. Тексты слотов инстанса макета лежат в `component.content` / `textProps` (детей-текстов у инстанса нет), страница несёт их текст-детьми — правило сверки текста инстанса берёт слоты макета и тексты поддерева страницы (см. `match._covered`: перекрытие считается с прощением одного символа). Имя слоя инстанса — строка вариантов; название компонента — `component.figmaName`. Боксов у настоящего канона почти нет (только у абсолютных) — числовые правила геометрии опираются на раскладку, а не на box макета.

## Результат
Правила проверки над парами матчера: чистая функция `check(design, impl, matched, tolerances=None, flags=None)` → `findings`, `dismissals`, `unverified`, `degraded`, `executed`, `tolerances`, `stats`. Код: `skills/forgeui/scripts/daiver/verify/check.py`; инструмента MCP нет — его даст 4.6 (`daiver_verify_compare`). Тесты: `skills/forgeui/scripts/test_check.py` (**60 тестов**: допуски F3, по тесту на доктрину, unverified по трём аспектам, настоящий канон «Modal»); правка `match.py` (пустой текстовый слой не содержимое) + 1 тест в `test_match.py` (54).

- **Выход.** Находка: `{code, layer, severity, design, impl, message, prop?, expected?, actual?, …}`; `severity`: `critical` для MISSING / TEXT / SLOT_MISSING / SLOT_TEXT / INVISIBLE, иначе `major` (выбор этой задачи — спека уровней не называет); `hint` у перепутанных слотов; `corners` у SHAPE-радиуса. Dismissal: `{code, layer, design, impl, reason, prop?}` — `reason` несёт приговор-предложение («не чинить, потому что…»). Порядок детерминирован: слой → id макета → id страницы → код → свойство. Стабильные id дефектов, подавление и группировку делает 4.6 (поля `design`/`impl`/`code`/`prop` — их сырьё).
- **Правила** (`RULES`, по одному на группу, каждое под своим try): `structure` (MISSING/EXTRA/ORDER матчера пробрасываются как есть), `text`, `slots`, `invisible`, `size`, `spacing`, `position`, `overflow`, `typography`, `color`, `shape`. Слой `token` правил не имеет: снимок страницы не несёт имён токенов, цвет сверяется по значению.
- **Допуски** — из `verify.tolerances`: сверх допуска строго «>» (на грани тихо и без dismissal); размер: `max(px, min(sizeRatio × число_макета, sizeRatioMaxPx))`; цвет: на канал, альфа — `max(0.02, color/255)` («округлённый токен проходит»); межбуквенный — константа `LETTER_SPACING_TOL` = 0.1 px. Мусор в допусках (не число, отрицательное, неизвестный ключ) игнорируется.
- **Что показали данные «Modal».** (1) Мастер библиотеки рисует поверхность, которой в каноне инстанса нет: «макет без фона» у инстанса ≠ transparent, поэтому фон/обводка/тень/радиус, которых макет у библиотечного инстанса не назвал, не сверяются (`_master_draws`), иначе каждая кнопка получала ложный COLOR/SHAPE. (2) Копия слота, изменённая на странице, иначе шла бы дважды — SLOT_TEXT и EXTRA матчера: тексты, объяснённые слотом (и копия слота-плейсхолдера), из EXTRA снимаются (`_claims`). (3) У настоящего инстанса `size.w` — число, `h` — `hug`; `sized: own` у обоих «Modal Header», у Modal Action размер 560. (4) Unverified на образце: один элемент (`copy` — слот «Текст3» на плейсхолдере у Modal Action).
- **Решения там, где спека свободна** (README → «Отклонения»): severity; `LETTER_SPACING_TOL`; допуск альфы; OVERFLOW читает внешние `flags` (в каноне страницы признака нет: `impl_model` его сбрасывает, у макета нет вовсе); POSITION работает только там, где у макета есть box; «extent auto-layout = content + padding» не вычисляется; слой `token` без правил.
- **Мутационная проверка** (одноразовый скрипт, файлы не правились): 35 мутантов (допуски, кап и пол размера, пропуск низкоуверенных пар, плейсхолдеры, мастер рисует, sized, контракт библиотеки, INVISIBLE и размер поверхности, margin вместо gap, семейство, вес, align, lineHeight, letter-spacing, радиус, claims, регистр, высота текста, fill/hug, комната родителя, переполнение, degraded, три аспекта unverified, градиент, обводка, тень, позиция, корень) — убиты все. Первый прогон: 2 выживших — тест принимал упавшее правило за «чисто» (теперь `run()` в тестах падает на `degraded`) и мутант попал не в ту строку.

**Не проверено данными.** Всё на синтетике и одном канон-образце: severity; доля ложных SIZE/SPACING на реальной странице (боксов у настоящего канона почти нет — геометрия опирается на `size`/`layout`); поведение `margin вместо gap` на настоящих страницах; допуск альфы; кириллические/нестандартные семейства шрифтов в `_first_family`; цветовые форматы страницы, кроме hex/rgb/rgba/ключевых слов (oklch, color-mix, var() — dismissal «не разобран»).
