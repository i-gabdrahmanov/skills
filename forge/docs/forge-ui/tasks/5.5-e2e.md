# 5.5 — e2e по сценариям ui-spec

**Этап:** 5 · **Зависит от:** 4.8 · **Статус:** todo
**Спека:** §14.8, §11.2 (id сценариев) · **INV:** C36, B19, F15 · **QG:** N17

## Зачем
Сценарии фронт-спеки становятся тестами: поведение проверяется так же, как вид.

## Что сделать
- Инструмент **`daiver_e2e_plan(track)`**: из `daiver_spec` — список `{id, file, title, body,
  context, skip?}`; имя файла детерминировано по id (`ui-spec#2` → `ui-spec-2.e2e.spec.ts`);
  контекст REMOVED → `skip` с причиной (тест на удаляемое поведение не пишется); `hasE2e:false` —
  гейт `skipped`, сказать один раз.
- Агент пишет тела тестов (ассерты — по текстам `mocks.ts`), повторный прогон заменяет свои файлы.
- Гейт `e2e` в итерации: `@playwright/test` есть в package.json фронт-репо → прогон
  `npx playwright test <файлы>` с JUnit-отчётом; падения — в дефекты итерации; нет playwright —
  `skipped` с причиной. Падения называются, не глушатся.

## Готово, когда
- `test_e2e_plan.py`: детерминированные имена; REMOVED → skip (N17); `hasE2e:false` → skipped;
  разбор JUnit-отчёта playwright в дефекты.

*Заметка (3.3).* `ui-guard` запрещает ЛЮБУЮ запись в `project.outputDir` вне шага `ui-build` (в том числе файлов тестов): если `*.e2e.spec.ts` лежат внутри outputDir, агент `ui-verify` их не запишет. Класть e2e-файлы
вне outputDir (каталог тестов фронт-репо по `project.conventions`) либо расширить `_judge_write` в `hooks/ui-guard.py` исключением для e2e-файлов (и тестом на него).

*Заметка (3.4).* Новый инструмент `daiver_e2e_plan` не подходит под шаблоны `phase_tools` (`daiver_verify_*`, `daiver_screenshot`): решить, чей он — субагент итерации `ui-verify` (добавить имя в `phase_tools`) или оркестратор (добавить в список
свободных `PhaseToolsRegistry.FREE` в `hooks/test_branches_registry.py`); без решения падает `test_every_engine_tool_has_an_owner`. Файлы `*.e2e.spec.ts` вне `project.outputDir` — тесты для `path_risk` (R1, не R2), `pii-boundary` их не исключает (PII в тестах разрешена и без этого).

*Заметка (4.1).* «Есть ли `@playwright/test` у репо» уже считает `daiver_capabilities` (поле `playwright`: `found` — объявлен в package.json, `installed` — стоит в node_modules, `version`); повторно разбирать package.json не нужно.
Нет пакета — гейт `skipped` с причиной из этого поля. `daiver_capabilities` — читающий, свободный инструмент (в `phase_tools` не входит); `daiver_e2e_plan` решается отдельно (заметка 3.4).
