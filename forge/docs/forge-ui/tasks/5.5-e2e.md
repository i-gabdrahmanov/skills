# 5.5 — e2e по сценариям ui-spec

**Этап:** 5 · **Зависит от:** 4.8 · **Статус:** done
**Спека:** §14.8, §11.2 (id сценариев) · **INV:** C36, B19, F15 · **QG:** N17

## Зачем
Сценарии фронт-спеки становятся тестами: поведение проверяется так же, как вид.

## Что сделать
- Инструмент **`daiver_e2e_plan(track)`**: из `daiver_spec` — список `{id, file, title, body,
  context, skip?}`; имя файла детерминировано по id (`ui-spec#2` → `ui-spec-2.e2e.spec.ts`);
  контекст REMOVED → `skip` с причиной (тест на удаляемое поведение не пишется); `hasE2e:false` —
  гейт `skipped`, сказать один раз.
- Агент пишет тела тестов (ассерты — по текстам `mocks.ts`), повторный прогон заменяет свои файлы.
- Гейт `e2e` в итерации: `@playwright/test` есть в package.json фронт-репо → прогон
  `npx playwright test <файлы>` с JUnit-отчётом; падения — в дефекты итерации; нет playwright —
  `skipped` с причиной. Падения называются, не глушатся.

## Готово, когда
- `test_e2e_plan.py`: детерминированные имена; REMOVED → skip (N17); `hasE2e:false` → skipped;
  разбор JUnit-отчёта playwright в дефекты.

*Заметка (3.3).* `ui-guard` запрещает ЛЮБУЮ запись в `project.outputDir` вне шага `ui-build` (в том числе файлов тестов): если `*.e2e.spec.ts` лежат внутри outputDir, агент `ui-verify` их не запишет. Класть e2e-файлы
вне outputDir (каталог тестов фронт-репо по `project.conventions`) либо расширить `_judge_write` в `hooks/ui-guard.py` исключением для e2e-файлов (и тестом на него).

*Заметка (3.4).* Новый инструмент `daiver_e2e_plan` не подходит под шаблоны `phase_tools` (`daiver_verify_*`, `daiver_screenshot`): решить, чей он — субагент итерации `ui-verify` (добавить имя в `phase_tools`) или оркестратор (добавить в список
свободных `PhaseToolsRegistry.FREE` в `hooks/test_branches_registry.py`); без решения падает `test_every_engine_tool_has_an_owner`. Файлы `*.e2e.spec.ts` вне `project.outputDir` — тесты для `path_risk` (R1, не R2), `pii-boundary` их не исключает (PII в тестах разрешена и без этого).

*Заметка (4.1).* «Есть ли `@playwright/test` у репо» уже считает `daiver_capabilities` (поле `playwright`: `found` — объявлен в package.json, `installed` — стоит в node_modules, `version`); повторно разбирать package.json не нужно.
Нет пакета — гейт `skipped` с причиной из этого поля. `daiver_capabilities` — читающий, свободный инструмент (в `phase_tools` не входит); `daiver_e2e_plan` решается отдельно (заметка 3.4).

## Результат
Два инструмента: **`daiver_e2e_plan(track)`** и **`daiver_e2e_run(track, frame?, iterationDir)`** (второй — не в списке задачи, но без него «гейт в итерации» остался бы словами агента: см. README «Отклонения»). Оба в `phase_tools` шага `ui-verify`. Код: `verify/e2e.py`; запись итерации (`verify/state.py`) читает `e2e-summary.json` и `e2e-defects.json`. Тесты: `test_e2e_plan.py` (**43**; без Chrome, прогон playwright — подставным запускателем и настоящим подпроцессом через поддельный `npx` в PATH).

- **План**: из разбора `daiver_spec` — `{id, file, title, body, context, line, spec, skip?}`, порядок по id (вход на план не влияет). Файл — `<dir>/<id>.e2e.spec.ts` с `#` → `-` (`ui-spec#2` → `ui-spec-2.e2e.spec.ts`); каталогов и странных символов в имени нет, id, давшие одно имя после очистки, различаются хвостом из sha1. Контекст REMOVED → `skip` с причиной, файла в `files` нет (N17), в ответе `skipped[]` — агент обязан сказать, что скипнуто. `hasE2e: false` и «все сценарии удаляются» — `gate: skipped` с причиной, `nextStep` велит сказать это ОДИН раз.
- **Каталог тестов**: `testDir` из `playwright.config.*` (строковый литерал), иначе `e2e/`; внутри `project.outputDir` и вне репо — отказ поимённо (`warnings`), запасной `e2e/`. Так `ui-guard` не мешает агенту `ui-verify` писать тесты (он запрещает запись только в outputDir вне ui-build) и менять `hooks/ui-guard.py` не пришлось.
- **Прогон** (`daiver_e2e_run`): `npx --no-install playwright test <написанные файлы> --reporter=junit`, `PLAYWRIGHT_JUNIT_OUTPUT_FILE` в папку итерации, `CI=1`, таймаут 600 с, группа процессов убивается целиком. Ничего не ставится и не скачивается. `skipped` с причиной и БЕЗ запуска: нет сценариев; ни одного файла плана не написано (названы в `notWritten`); в package.json нет `@playwright/test`; объявлен, но не установлен (две разные причины, поле `playwright` из `daiver_capabilities`); `npx` нет или не запускается. `pass` — код 0 и отчёт с тестами. `fail` — есть падения; прогон кончился без отчёта (конфиг, зависимости, webServer; хвост вывода в причине); чистый отчёт, но код ≠ 0; пустой отчёт; отчёт не читается; не уложился во время. Старый `e2e-junit.xml` перед прогоном удаляется — зелёный отчёт прошлого запуска новому не засчитывается.
- **Падения → дефекты**: `zone: e2e`, `source: e2e`, `severity: major`, `code: E2E_FAIL`, `layer: behavior`, `rule` = id сценария, `location` {файл, строка из стека, иначе 1}; id — sha1 от (сценарий | название теста), стабилен между прогонами и не зависит от порядка (одинаковые названия — суффикс). Падение файла не из плана называется в сообщении. `e2e-defects.json` пишется всегда (пустым при skipped).
- **Запись итерации**: статус гейта и падения берутся из `e2e-summary.json` / `e2e-defects.json`, слова агента проигрывают (расхождение — в `warnings`); «pass» без прогона записывается `skipped` (прогона нет — «прошёл» нельзя), «fail» без прогона остаётся `fail` (сомнение в пользу остановки; причину агент называет сам). Падение блокирует clean (дефект major зоны e2e, не vision); если решениями человека (`false_positive`) блокирующих падений не осталось и пункты были — гейт `pass` с причиной; падение без пунктов (таймаут, нет отчёта) решением не снимается. `skipped` e2e clean не мешает (§14.9).
- **Мутационная проверка** (одноразовый скрипт): 26 мутантов (имя файла, разделитель каталогов, skip/REMOVED, пропуск гейта, каталог внутри outputDir, разбор error/skipped/строки, id без названия теста, проверка «не установлен», `found`/`installed`, старый отчёт, код возврата, пустой отчёт, таймаут, `notWritten`, обрезка, победа факта над словами, «pass» без прогона, снятие блокировки решением) — выжили два (id без названия теста, старый отчёт): дописаны тесты (два падения одного сценария в любом порядке; зелёный старый отчёт при коде 0), повторный прогон — убиты оба.

**Не проверено данными.** Настоящий playwright-проект (формат JUnit разных версий — разбираем `testsuite/testcase/failure|error|skipped`, строку берём из стека `.ts:N`), `webServer`/`baseURL` репо (их задаёт `playwright.config`, движок dev-сервер для e2e не поднимает), время прогона настоящего набора (порог 600 с взят с потолка), `npx` на Windows, `testDir` в нестандартных конфигах (не литерал — молча `e2e/`), как слабая модель пишет тела тестов по сценариям и держится ли она ассертов по `mocks.ts`.
