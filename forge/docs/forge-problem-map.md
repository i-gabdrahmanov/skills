# Forge — карта проблем обвязки

Срез от 26 ноября 2026 года, HEAD `1855fa9`. Область разбора — установка расширения, подключение хуков, аварийная обработка и достоверность проверок CI. P1 означает риск потери рабочей установки или пропуска обязательной проверки. P2 означает ошибочный сигнал готовности или успешной проверки. Приоритеты предложены для планирования. Все девять пунктов исправлены в рабочем дереве. Таблицы ниже описывают исходное состояние на указанном коммите.

## Где возникает отказ

| Этап | Нарушенное ожидание | Находки |
|---|---|---|
| Обновление | Предыдущая рабочая версия доступна до приёмки новой | P1 · F01 |
| Сборка и регистрация | Команды запускаются из реального пути, а код установки отражает результат подключения | P1 · F02, P2 · F03–F04 |
| Выполнение PreToolUse | Ошибка блокирующей проверки даёт предсказуемый отказ, восстановление имеет узкие границы | P1 · F05–F06 |
| Диагностика и CI | Зелёный результат подтверждает полноту проверенного состава и сохранность состояния | P2 · F07–F09 |

**Связь проблем.** Путь с пробелом может испортить команды новой поставки (F02). К моменту диагностики предыдущая версия уже удалена (F01), а сообщение preflight само по себе не делает установку неуспешной (F03). Это три разных места исправления одного возможного инцидента.

## P1 — работоспособность установки и обязательных проверок

| ID | Условие и последствие | Что изменить и как принять |
|---|---|---|
| F01 | При обновлении старый каталог удаляется сразу после подмены, до успешной сборки манифеста. При ошибке build установщик выходит с 1, оставляя неполную новую поставку. [install.sh, шаг 2](../install.sh#L207) | Сохранить старый каталог до успешной проверки новой поставки, восстанавливать его при отказе. Критерий — искусственная ошибка сборки при обновлении оставляет доступной предыдущую рабочую версию. |
| F02 | Абсолютные пути к wrapper и хуку вставляются в строку команды без кавычек. Для проекта с пробелом разбор на аргументы разделяет имя каталога. Замена обратных слэшей проблему пробелов не решает. [Сборка команды](../hooks/forge_extension.py#L107) · [Разбор команд при диагностике](../hooks/forge_extension.py#L195) | Собирать команду из отдельных аргументов с экранированием под протокол рантайма. Критерий — установка в каталог с пробелами проходит диагностику, а безвредный вызов действительно достигает тестового хука. |
| F05 | Необработанное исключение внутри запускаемого хука покидает общий wrapper. В предыдущей локальной проверке исключение дало код 1. По принятому в проекте контракту отказ PreToolUse требует кода 2, поэтому конкретная проверка может потерять силу. [Wrapper](../hooks/_run_hook.py#L69) · [Контракт кодов](../hooks/test_import_failclosed.py) | Задать обработку аварий с учётом назначения хука. Критерий — сбой блокирующего обработчика даёт 2 и имя хука, а информационный хук и Stop сохраняют свои контракты. |
| F06 | При повреждённом бандле исключение для восстановления классифицирует команду поиском совпадения в строке. Имя служебного скрипта в аргументе может быть ошибочно принято за запуск восстановления. В предыдущей локальной проверке один блокирующий хук вернул 0. Остальные хуки принимают свои решения независимо. [Классификатор восстановления](../hooks/_failclosed.py#L84) | Сопоставлять целый разрешённый вызов, включая исполняемый файл и допустимые аргументы. Критерий — штатная диагностика работает, посторонний вызов с похожим аргументом получает отказ. |

## P2 — ложные сигналы успеха

| ID | Условие и последствие | Что изменить и как принять |
|---|---|---|
| F03 | Ошибка обязательного link превращается в предупреждение. Аналогично обрабатывается отрицательный итог preflight. Автоматизация может получить код 0 при неподключённом расширении. [Подключение](../install.sh#L225) · [Завершение диагностики](../install.sh#L273) | Различать «файлы установлены», «подключено» и «готово». Для обычной установки сбой запрошенного подключения должен возвращать ненулевой код. Сохранить самостоятельные сценарии явного `--no-link` и ещё не инициализированного проекта. |
| F04 | При установке в несколько проектов результат команд взаимного отключения расширений игнорируется, а отчёт всегда ставит отметку успеха. Оператор получает неверное подтверждение изоляции workspace. Фильтр чужого проекта в wrapper остаётся отдельной защитой. [Цикл обработки соседних проектов](../hooks/forge_extension.py#L337) | Учитывать каждый возврат CLI. Критерий — отказ для одного соседнего проекта меняет итог операции и выводит его имя вместо сообщения об успешном отключении. |
| F07 | `forge_extension.check()` проверяет команды, уже присутствующие в hooks.json, но не сверяет набор событий, матчеры, порядок и признак sequential с шаблоном. Частичная регистрация может пройти именно эту проверку. У preflight есть отдельная проверка присутствия essential-хуков. [Проверка расширения](../hooks/forge_extension.py#L231) · [Preflight](../hooks/preflight.py#L441) | Сравнивать фактическую регистрацию с ожидаемой по каждой группе. Критерий — перестановка двух обязательных обработчиков или потеря matcher определяется даже при сохранении всех файлов хуков. |
| F08 | При пустой выборке тестовый раннер печатает «Тесты не найдены» и возвращает 0. Опечатка в `--skill` даёт зелёный CI без единой проверки. [Точка возврата](../skills/run_all_tests.py#L78) | Считать пустую явно запрошенную выборку ошибкой либо требовать явного разрешения на пустой набор. Критерий — неизвестное имя скилла даёт ненулевой код и понятное сообщение. |
| F09 | Контроль загрязнения ground/ сравнивает путь и размер файла. Перезапись существующего файла другим содержимым той же длины проходит незамеченной. [Снимок](../skills/run_all_tests.py#L59) · [Сравнение](../skills/run_all_tests.py#L102) | Сравнивать контрольные суммы содержимого. Критерий — замена одного байта без изменения размера обнаруживается, неизменённый файл проходит. |

## С чего начать

1. **Выпуск и восстановление установки** — F01–F03. Проверить обновление уже рабочего проекта со сложным путём и ошибкой на каждом этапе.
2. **Поведение при аварии** — F05–F06. Зафиксировать отдельно контракты блокирующих хуков, наблюдателей и Stop, затем подтвердить их в целевом GigaCode.
3. **Достоверность диагностики** — F04, F07–F09. Использовать отрицательные контрольные случаи, для которых ожидается явная ошибка.

**Основание карты.** Для F05 и F06 наблюдался локальный результат отдельного процесса Python. Остальные выводы получены чтением текущего кода. Сквозная проверка этих отказов в GigaCode и оценка частоты на рабочих проектах остаются открытыми. Критерии приёмки в таблицах описывают будущую проверку исправлений.
