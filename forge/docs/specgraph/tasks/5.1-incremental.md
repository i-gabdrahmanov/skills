# 5.1 — Инкрементальное обновление

**Этап:** 5 · **Зависит от:** 3.6, 4.1 · **Статус:** todo
**ТЗ:** §8.6 · **Уроки:** «сборка с первого раза» и wipe-регрессия прототипа (агентские флоу
терялись при сносе vault)

## Зачем
Спека живёт: в неё мержат новые требования (forge-merge) и правят разделы. Пересобирать граф с
нуля дорого, и при этом теряются решения человека. Повторный `/graph` должен работать по дельте и
спрашивать человека только о новом.

## Что сделать
- Дельта по блокам: пересканировать, сравнить `sha` и соседство. Неизменённые блоки сохраняют
  назначение. Новые и изменённые идут на перепланирование только своих секций — субагент видит
  прежнее назначение соседей. Удалённые блоки уходят из заметок.
- Заметка, оставшаяся без блоков, в vault не удаляется: в дельта-каталоге она помечается
  кандидатом в `status: deprecated`, решает человек.
- Рёбра: у заметок с изменённым текстом основания перепроверяются; ребро, чья цитата исчезла,
  возвращается в `proposed`, и модель заново предлагает связи для этой заметки.
- Дельта-отчёты `catalog.md` и `edges-review.md` показывают только изменения; согласия — те же
  три, на дельту.
- Решения человека из `_graph/decisions.md` применяются повторно: слияния, переименования и
  отклонённые рёбра не переспрашиваются.
- **Дельта по правилам** — главный сценарий петли обратной связи: пришла новая версия
  extension'а (поправленные экстракторы, брифы, онтология) при неизменной спеке. Кандидаты
  пересчитываются; на перепланирование идут только секции, где кандидаты изменились или
  остались `unplaced`; рёбра пересчитываются там, где сработало новое правило. Версия правил
  (тег + хеш `config.json` и `ontology.local.json`) пишется в стейт, чтобы было видно, какой
  граф каким набором правил построен.

## Готово, когда
- Фикстура с изменённой копией (правка шедулера, новый эндпойнт, удалённый раздел): перепланируются
  только затронутые секции; рёбра неизменённых заметок не трогаются; решения человека сохранены.
- Прогон без изменений исходников — 0 вопросов и 0 изменений vault.
- Новая версия правила шедулеров (мутант «до» → «после» на варианте 0.5) перепланирует только
  секции, где появились новые кандидаты; остальной граф и решения человека не тронуты.
