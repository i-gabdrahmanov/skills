# 2.3 — Предложения рёбер с основаниями

**Этап:** 2 (graph-link) · **Зависит от:** 2.1 · **Статус:** done
**ТЗ:** §1.3, §1.5, §3, §4.1–4.3, §5, §7, §8.5 · **Решения:** рычаг 2, D9, D14

## Зачем
Связи, которые требуют понимания текста — «этот шедулер формирует задачи укомплектования», «этот
экран — UI передачи упаковок», «закрывает задачи трёх типов», — предлагает модель. Каждое
предложение проверяется механически: у ребра есть основание, и оно дословно есть в спеке. Так
выдуманная связь не проходит (ТЗ §8.5).

## Что сделать
- Инструмент `graph_link_put(note, proposals[])`, предложение — `{edge, target, quote,
  confidence, why?}` (`target` — имя или ключ). Проверки:
  - ребро допустимо онтологией для пары (`kind`/`role` источника, `kind` цели);
  - `quote` (≥ 20 знаков, с нормализацией пробелов) дословно есть в source-блоках заметки-
    источника или заметки-цели;
  - цель резолвится (2.1); `ambiguous`/`ghost` → предложение не принимается, а уходит в вопросы с
    кандидатами;
  - дубли (тот же `from, edge, to`) сливаются, цитаты копятся.
  Ответ — принято / отклонено с причиной, не больше 10 строк.
- Очередь `.spec-graph/edges/<note-id>.json`: статусы `proposed` → `accepted` | `rejected`;
  отклонённое человеком повторно не предлагается.
- Единицы работы — очередь `link-note` (0.6), по одной на заметку в scope; вход готовит движок.
- Бриф субагента `references/briefs/link-note.md`. Вход — ОДНА заметка: её source-блоки, допустимые
  для её вида рёбра, подсказки резолвера (имена и ключи, упомянутые в теле), список бизнес-операций
  каталога. Выход — вызов `graph_link_put`. Правила: ребро — только для взаимодействия, не для
  упоминания; `creates_task`/`closes_task` — только если текст говорит о создании или закрытии
  задач этого типа; общий шедулер закрытия даёт по ребру на каждую операцию из своего текста.

## Готово, когда
- Выдуманная цитата, недопустимая пара видов, цель-призрак — отклоняются (тесты).
- Неоднозначная цель → вопрос с кандидатами, ребро не ставится.
- «Ответы модели» фикстуры (`expected/edges/`) проходят и вместе с 2.2 дают рёбра эталона без
  лишних.

## Результат
- `sgraph/link.py`: `start` — очередь `link-note` (без утверждённого каталога — отказ): единица на заметку,
  у вида которой онтология разрешает исходящие рёбра кроме `belongs_to` (фикстура — 21 единица); крупная
  заметка — частями по абзацам в бюджете. Вход: вид, роль, сервис; допустимые рёбра с видами целей;
  бизнес-операции с ключами; подсказки резолвера (METHOD /path, точные имена и алиасы в тексте); уже
  предложенное правилами; текст заметки дословно.
- `put` — каждое предложение через `edges.Graph.check`: цитата не из текста или недопустимая пара —
  отказ всей единицы (очередь возвращает её, три отказа — брошена); `belongs_to` от модели — отказ;
  неоднозначная или несуществующая цель — НЕ отказ, а вопрос в `.spec-graph/questions.json` (остальные
  рёбра единицы ставятся). Повтор механического ребра сливается в одну запись.
- Инструменты `graph_link_start` (свободный) и `graph_link_put` (`x-queue: link-note`, `phase_tools`
  шага graph-link); бриф `references/briefs/link-note.md`.
- «Ответы модели» фикстуры — `fixtures/tz-mini/expected/edges/model-edges.json` (14 рёбер, которые ставит не
  правило); механика + ответы через настоящую очередь = ровно 45 рёбер эталона (без `belongs_to`).
- Тесты `test_edge_proposals.py` (5); мутанты (цель валит единицу, ошибка цитаты — в вопросы, belongs_to от
  модели) пойманы. Урок X.1 `P-inv-5` → covered.
