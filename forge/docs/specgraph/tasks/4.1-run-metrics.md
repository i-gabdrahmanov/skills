# 4.1 — Счётчики прогона и история здоровья графа

**Этап:** 4 (диагностика) · **Зависит от:** 0.1 · **Статус:** todo
**Решения:** D18 · **Уроки:** `loop-check.json` прототипа (история 30 прогонов, метка
стабилизации); память: «логи и бюджет удалены из forge» — оверхед хуков-логгеров

## Зачем
Обратная связь из окружения будет только в виде цифр и кодов. Чтобы понять, где ломается
система, движок должен сам считать, что происходило: какие инструменты отказывали модели и почему,
где она переделывала секцию по пять раз, какие правила срабатывали. Логи-хуки forge уже снимал из-за
оверхеда, поэтому считает сам движок в диспетчере инструментов и бесплатно для модели.

## Что сделать
- Обёртка в `sgraph/tools.call`: на каждый вызов — инструмент, исход (`ok` | `rejected` | `error`),
  коды отказа, id секции или заметки (только id), длительность, размер ответа. Запись —
  `.spec-graph/runs/<KEY>/calls.jsonl`, компактно; новые инструменты считаются автоматически.
- Счётчики шага: попытки плана на секцию, брошенные секции (нет плана после N попыток), вопросы
  человеку, решения человека по типам (merge/rename/reject/place), исключения движка.
- `.spec-graph/health.json` — история последних 30 прогонов: узлы по видам, рёбра по типам и
  происхождению (rule/model/manual/improve), `E-*`/`W-*` по кодам, дыры 3.2, покрытие, `unplaced`,
  доля согласия самопроверки (4.5, когда появится). Метка стабилизации: N прогонов подряд без новых
  находок.
- **В счётчиках нет текста исходников:** только id, коды, числа, размеры. Тест-утечка: прогон на
  фикстуре, затем ни одна строка из `sources/` (≥ 4 слов подряд) не встречается в `runs/` и
  `health.json`.

## Готово, когда
- Каждый вызов инструмента на фикстуре оставил запись; исключение внутри инструмента
  записалось как `error` с типом исключения (без сообщения, если в нём может быть текст исходника).
- Тест-утечка зелёный; мутант «записать имя заголовка в счётчик» его валит.
- `health.json` хранит не больше 30 прогонов, метка стабилизации считается.
