# 1.2 — Экстракторы кандидатов

**Этап:** 1 (graph-map) · **Зависит от:** 1.1, 0.5 · **Статус:** todo
**ТЗ:** §1.1, §2, §9.2 · **Решения:** D14 (всё, что можно экстрактором, — экстрактором)

## Зачем
Модель слабая: чем больше узлов найдено механически, тем меньше она решает и тем меньше
ошибается. Экстракторы предлагают кандидатов с доказательством (блок и сработавшее правило), а
модель на разведке (1.3) подтверждает и называет узлы, а на раскладке (1.5)
раскладывает блоки.

## Что сделать
- `sgraph/extract.py`, правило → кандидат `{kind, name_hint, key?, role?, blocks[], rule, confidence}`:
  - `endpoint`: `METHOD /path` в заголовках, таблицах API, прозе и OpenAPI-блоках. Регулярки
    взять из прототипа (`spec_graph_parse.py`: `normalize_path`, `prose_endpoints`,
    `split_endpoint_blocks`) без доменных путей.
  - `topic`: шаблон имени канала из конфига (`kafka_topic_re`, по умолчанию «точечное имя с
    `.v<N>`»), с ролью по глаголу рядом.
  - `scheduler`: заголовки со словами «шедулер / планировщик / по расписанию / scheduler / job»,
    cron-выражения.
  - `kafka-op`: «обработка / обработчик / получение» + сообщение/топик → `consume`; «отправка /
    публикация» + топик отдельным разделом → `publish`.
  - `algorithm`: заголовки «Алгоритм …», «Расчёт …» (список слов — конфиг).
  - `data`: «Динамические атрибуты …» → `attributes`; таблицы колонок → `table`/`dto`; таблицы
    значений со статусами → `enum`.
  - `operation`: коды типов задач из таблиц-справочников («тип задачи») → `key: task:<код>`.
  - `service`: из конфига `services{}` либо по каталогу/шапке файла.
- Все словари и шаблоны лежат в `.spec-graph/config.json` (`extract.*`) с нейтральными
  умолчаниями; доменных констант в коде нет.
- Результат — `.spec-graph/candidates/<file>.json`; модели отдаётся короткая сводка по секции.

## Готово, когда
- На фикстуре `tz-mini` все эндпойнты, топики и шедулеры с заголовками найдены (recall 100 % по
  эталону для этих видов); строка «см. также rmoc-service» кандидатом в ребро не становится.
- Каждое правило покрыто позитивным и негативным примером.
- Матрица стресс-корпуса (0.5): по каждому варианту recall по видам записан; варианты, которые
  правила не берут, — `known_gap` с причиной (английские заголовки, жирное вместо заголовка и т. п.).
- В коде нет доменных литералов (grep-тест на `kid`, `rmoc`, `upz`, `KidTopic`).

## Заметки
- Реальной спеки не будет, поэтому все правила — допущения по синтетике и стресс-корпусу (0.5).
  Это норма, а не долг: у каждого правила есть `rule id`, по которому счётчики (4.1) и пакет
  диагностики (4.3, раздел 6) показывают его попадания, промахи и ложные срабатывания в поле.
  Доучивание в окружении — 4.7, исправление по обратной связи — 4.4.
