# 1.3 — Разведка: обзор спеки и черновой каталог по оглавлению

**Этап:** 1 (graph-map) · **Зависит от:** 1.2, 4.2, 0.6 · **Статус:** todo
**ТЗ:** §9.1 («проанализировать текущую структуру»), §9.2 · **Решения:** D14, D24

## Зачем
До дорогой нарезки нужно понять, что вообще лежит в спеке и сколько это работы. Решить, какие
узлы в ней есть, можно по оглавлению и кандидатам экстракторов, не читая текст. Это дёшево, а имена
общих узлов выбираются один раз на весь корпус. Иначе один и тот же шедулер закрытия рождается в
разных секциях под разными именами.

## Что сделать
- Инструмент `graph_survey(scope)` (механика, без модели): скан (1.1), экстракторы (1.2),
  профиль (4.2) → `_graph/survey.md` для человека (живёт в окружении, наружу не выносится):
  - по файлу — сервис, размер, оглавление верхних 2–3 уровней, кандидаты по видам;
  - аномалии: исключённые черновики, файлы-дубли по `sha`, `W-fence-unclosed`, очень длинные
    секции;
  - **объём работ:** сколько единиц очереди будет на каждом шаге (`draft-file`, `assign-section`,
    `link-note`, `card`) и сколько это вызовов субагентов;
  - предложение scope: с каких 2–3 сервисов начать (по связности кандидатов и размеру).
- Очередь `draft-file`: единица на файл, очень большой файл — на раздел верхнего уровня. Вход —
  оглавление с id и размерами секций, кандидаты экстракторов (вид, имя, ключ), имена узлов,
  уже предложенные по прошлым файлам (для повторного использования). Текста секций во входе нет.
- Инструмент `graph_draft_put(item_id, nodes, not_nodes)`. Узел — `{kind, name, service, key?,
  role?, subkind?, sections[], confidence, why}`, `not_nodes` — кандидаты, которые не узлы, с
  причиной и необязательной меткой `suggested_kind` (её подхватывает 4.9). Проверки:
  - виды из онтологии, грамматика имён;
  - секции существуют;
  - каждый кандидат 1.2 учтён: либо узел, либо `not_nodes` с причиной.
  Ответ — не больше 10 строк.
- Бриф `references/briefs/draft-file.md`. Правила: одна самостоятельная операция — один узел; общее
  описание — узел `service`; бизнес-операции называются как тип задачи; если узел с таким смыслом
  уже есть в списке имён — взять это имя, а не придумать новое.
- Результат — `.spec-graph/drafts/<file>.json`, из них каталог собирает 1.4.

## Готово, когда
- Фикстура: черновики по оглавлению дают все узлы эталона, у которых есть заголовок. Узлы без
  своего заголовка перечислены в «Результате», их ловит раскладка (1.5) как новые узлы.
- Общий шедулер закрытия во втором файле получает то же имя, что в первом (тест с подставными
  ответами и проверкой, что список имён во входе есть).
- Оценка объёма работ в `survey.md` совпадает с фактическим числом единиц очередей после шага
  (тест на фикстуре).
- Вход `draft-file` на «раздутом» варианте 0.5 укладывается в бюджет.
