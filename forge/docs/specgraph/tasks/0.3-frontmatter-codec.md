# 0.3 — FM-кодек: чтение и запись frontmatter без потерь

**Этап:** 0 · **Зависит от:** 0.2 · **Статус:** todo
**Уроки прототипа:** инварианты 1, 9, 12, 15; PROBLEMS-интент repair п. 4 («96 файлов откатаны из
бэкапа» — голые `[[x]]` дали тройные скобки)

## Зачем
Frontmatter — это рёбра графа. Прототип терял их на парсинге: некавычный список читался с
потерями и перезаписывался усечённым. PyYAML нет (stdlib, а homebrew-python сломан), поэтому
нужен свой строгий кодек на подмножество YAML, которое пишем мы и пишет Properties Obsidian.

## Что сделать
- `sgraph/fm.py`:
  - чтение: отделить FM (первые `---`…`---`); подмножество — скаляры (строка, число, bool,
    null), строки в двойных/одинарных кавычках, flow-списки `["[[a]]", "[[b]]"]`, block-списки
    (`- "[[a]]"`), `[]`. Всё остальное (вложенные словари, якоря, многострочные скаляры) — ошибка
    с номером строки. Дубль ключа — ошибка. Некавычный `[[x]]` в списке — ошибка с подсказкой
    «возьми в кавычки».
  - запись: порядок ключей — `ontology.fm_keys(kind)`, затем чужие ключи человека в исходном
    порядке; ссылки всегда в двойных кавычках; стиль списков — тот, в котором пишет Properties
    Obsidian (сверить на заметке, сохранённой в Obsidian), чтобы правка человеком не давала
    шумного диффа.
  - маркеры тела `<!-- graph:<name>:start … -->` / `<!-- graph:<name>:end -->`: чтение и замена
    содержимого; пустая строка до и после каждого маркера обязательна — без неё Obsidian держит
    HTML-блок открытым и рендерит таблицу сырым текстом (инвариант 12 прототипа).
- Кодек ничего не теряет: ключи, которых нет в онтологии (добавил человек), сохраняются.

## Готово, когда
- Round-trip: `write(read(s)) == s` для канонических образцов, `read(write(x)) == x` для моделей.
- Образцы «как пишет Obsidian» (block-списки, `[]`, кириллица, ссылки с `#заголовок` и `|алиас`)
  читаются без потерь.
- Сломанные образцы из уроков прототипа (тройные скобки, `[[[a]], [b]]`, дубль ключа, вложенный
  словарь) дают ошибку с номером строки, а не тихое чтение.
- Маркеры без пустых строк вокруг кодек при записи нормализует, а валидатор (3.1) ругается.
