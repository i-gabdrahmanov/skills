# 3.1 — Валидатор графа

**Этап:** 3 (graph-check) · **Зависит от:** 2.4 · **Статус:** todo
**ТЗ:** §8.1–8.5, §9.7–9.8 · **Уроки:** `validate_vault`, `deep_audit`, `edge_walk`,
`connectivity_audit` прототипа — их проверки, но по онтологии, без хардкода

## Зачем
Один валидатор с кодами ошибок — гейт шага check, и его же зовут остальные шаги после записи.
«Граф без ошибок» должно означать одно и то же для человека, гейта и отчёта.

## Что сделать
- `sgraph/validate.py`, инструмент `graph_validate(scope?)` и CLI. Ошибки:
  - `E-fm-parse`, `E-fm-key` (нет обязательного ключа вида или неизвестный ключ-ребро);
  - `E-name` (чарсет, грамматика, дубль имени во vault), `E-path` (путь ≠ `path_for`), `E-key-dup`;
  - `E-ghost` (`[[x]]` в FM на несуществующую заметку);
  - `E-edge-kind` (ребро недопустимо для видов концов), `E-inverse` (обратные ключи ≠ пересчёту);
  - `E-evidence` (прямое ребро без основания и не `manual`; цитата не найдена в теле);
  - `E-verbatim` (source-блок ≠ исходнику, пока исходник существует), `E-coverage`;
  - `E-index` (`_graph/index.md` ≠ файлам), `E-marker` (непарный маркер, нет пустых строк вокруг).
  Предупреждения: `W-orphan` (узел без рёбер, кроме `belongs_to`), `W-manual-inverse`,
  `W-unplaced`, `W-source-missing` (исходник удалён: после приёмки — норма).
- Выход: `_graph/report.md` и `.spec-graph/validate.json`; модели — счётчики по кодам и первые
  10 строк с путями.

## Готово, когда
- По тесту на каждый код (маленький сломанный vault, собранный построителем в тесте).
- Vault фикстуры после e2e-подготовки — 0 `E-*`.
- Код не содержит видов и рёбер литералами (берёт из онтологии) — проверка из DoD п. 3.
