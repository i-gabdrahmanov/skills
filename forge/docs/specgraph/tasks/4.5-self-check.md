# 4.5 — Самопроверка вопросами: граф против плоской спеки

**Этап:** 4 (самоулучшение) · **Зависит от:** 3.4 · **Статус:** todo
**Вводные:** режим diff `граф вводные/spec-graph-bench/SKILL.md` (классы AGREE / SPEC_ONLY /
GRAPH_ONLY / CONFLICT / HOLE, независимость ответов, FACTS)

## Зачем
Эталона у нас нет, но в окружении он есть — сама плоская спека, пока её не удалили. Если задать
одни и те же вопросы агенту, который ходит по графу, и агенту, который грепает спеку, их расхождения
покажут дыры графа без чьего-либо знания о домене. Это главный датчик качества в поле.

## Что сделать
- Вопросы строятся детерминированно из графа, без ответов внутри: на бизнес-операцию — 4 формы:
  кто формирует и кто закрывает её задачи; какой UI и какие эндпойнты он вызывает; через какие
  топики и сервисы идёт процесс; что затронет изменение её ключевого шедулера.
- Выборка: K операций за прогон (конфиг, по умолчанию 5), по кругу через все операции между
  прогонами; операции с изменённым текстом — первыми.
- Единицы — очередь `selfcheck` (0.6): вопрос × сторона.
- Пара изолированных субагентов на вопрос: «граф» (только MCP `spec-graph`) и «grep» (только
  каталоги исходников из конфига). Цель сравнения агентам не сообщается. Ответ — ANSWER плюс FACTS:
  атомарные факты с источником (`[[заметка]]` или `файл:строка`).
- Дифф делает только оркестратор, по фактам, классами прототипа. Каждый не-AGREE проверяется чтением
  источников (≤ 2 файла) → confirmed / refuted / needs_human.
- Подтверждённое → очередь самоулучшения (4.6) с классом: SPEC_ONLY — потерянная связь; GRAPH_ONLY
  опровергнутое — лишнее ребро; CONFLICT — противоречие спек (в open-questions, не ремонт); HOLE —
  дыра.
- В `health.json` — доля AGREE за прогон; в диагностику — только счётчики по классам.
- Исходники удалены → самопроверка не запускается, в отчёте об этом есть строка.

## Готово, когда
- На фикстуре со снятым ребром («закрывает задачи регистрации») самопроверка находит SPEC_ONLY
  и ставит его в очередь (тест с подставными ответами субагентов).
- Цена ограничена конфигом: K × 4 × 2 субагента; превышение невозможно (проверка в оркестрации
  кодом).
- Слабая модель с обеих сторон даёт шум, поэтому без проверки по источникам ничего в очередь не
  попадает (тест).
