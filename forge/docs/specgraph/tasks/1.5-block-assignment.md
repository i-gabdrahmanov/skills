# 1.5 — Раскладка блоков по утверждённым узлам

**Этап:** 1 (graph-map) · **Зависит от:** 1.4 · **Статус:** todo
**ТЗ:** §1 («одна самостоятельная функциональная операция — одна логическая спецификация»), §9.3
**Решения:** рычаг 1, D8, D14, D24

## Зачем
Узлы уже утверждены. На этом проходе модель решает одно: какой блок секции к какому узлу относится.
Это классификация, а не творчество — по силам слабой модели. Результат пишется планом, а не
текстом заметок. Валидатор плана — это enforcement: план, в котором блок потерян, назначен дважды
или узел склеил две операции, не принимается.

## Что сделать
- Очередь `assign-section`: единица на секцию в scope (крупная секция режется по границам блоков).
  Вход:
  - блоки секции дословно, с id;
  - узлы каталога этого файла и общие узлы, на которые секция может ссылаться;
  - кандидаты 1.2 в секции;
  - подсказки проекта (4.7), когда появятся.
- Инструмент `graph_assign_put(item_id, assign, skip, unplaced, new_nodes)`. `assign` — блок →
  узел каталога; `skip` — `{blocks[], reason: toc|boilerplate|duplicate-of, of?}`; `unplaced` —
  блоки, с необязательной меткой `suggested_kind`; `new_nodes` — узел, которого нет в каталоге, с
  `why`. Проверки:
  - каждый блок секции назначен ровно один раз;
  - цель `assign` есть в утверждённом каталоге или в `new_nodes` этого же вызова;
  - один узел не получает блоков двух разных кандидатов-операций (два разных `key` или два
    заголовка шедулеров) → «разделите»;
  - `skip: duplicate-of` — только при побайтном (с нормализацией пробелов) совпадении с блоками,
    назначенными в другом месте;
  - у нового узла вид из онтологии и имя по грамматике; он пишется в `catalog.delta.json` и
    решается в отчёте связей (2.6);
  - строки без сырых обратных слэшей и управляющих символов (урок PROBLEMS §G.2).
  Ответ — не больше 10 строк ошибок, с id блоков.
- Результат — `.spec-graph/plan/<file>.json`: блоки → узлы каталога (по id узла, не по имени).
- Бриф `references/briefs/assign-section.md`. Правила:
  - общее описание сервиса — в узел `service`;
  - текст, относящийся к нескольким операциям, — в один узел (общий алгоритм или сервис), остальные
    ссылаются на него ребром на шаге link;
  - оглавление — `skip: toc`;
  - новый узел — только если в каталоге нет подходящего, с объяснением.
  - `invokes` → `kafka-op(publish)`: отдельный узел публикации нужен, только если раздел описывает
    её сам (формат сообщения, условия отправки), иначе блоки идут в узел-отправитель (0.2).

## Готово, когда
- Ручные ответы фикстуры (`expected/plans/`) проходят; мутанты (потерянный блок, двойное
  назначение, два эндпойнта в узле, цель вне каталога без `new_nodes`, обратный слэш) отклоняются с
  понятной ошибкой.
- Узлы фикстуры без своего заголовка (см. «Результат» 1.3) появляются через `new_nodes` и
  попадают в дельту.
- Вход единицы вместе с брифом < 6 тыс. токенов на фикстуре и «раздутом» варианте 0.5 (оценка по
  длине).
