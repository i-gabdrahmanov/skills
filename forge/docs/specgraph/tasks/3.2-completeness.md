# 3.2 — Проверки полноты по ТЗ

**Этап:** 3 (graph-check) · **Зависит от:** 3.1 · **Статус:** done
**ТЗ:** §4–§6, §10 · **Уроки:** «эндпойнт без флоу — ошибка полноты, которую не видит ни один
валидатор» (прототип)

## Зачем
Ноль ошибок валидатора значит только одно: существующие ссылки целы. Для ТЗ этого мало. У
операции может не оказаться шедулера закрытия — и тогда её задачи никогда не закрываются, а граф
формально чист. Такие дыры — первые находки для аналитика и сигналы для цикла самоулучшения
(4.6); с них же начинается анализ процессов (6.4).

## Что сделать
- `sgraph/completeness.py`, правила — данными в `references/completeness.json` (порог,
  severity, текст вопроса):
  - `W-op-no-creator` — у операции нет `created_by`;
  - `W-op-no-closer` — нет `closed_by`;
  - `W-op-no-ui` — нет `screens` (исключение — флаг `system: true` в FM операции, если аналитик
    так решит);
  - `W-sched-idle` — шедулер без `creates_task`/`closes_task`/`invokes`;
  - `W-ep-no-caller` — эндпойнт без `called_by` (ни UI, ни сервис его не вызывает);
  - `W-topic-side` — у топика нет издателя или потребителя (внешний контрагент закрывает сторону);
  - `W-screen-no-op` — экран без `ui_of`;
  - `E-consume-no-topic` — `kafka-op(consume)` без `consumes` (структурная ошибка).
- Раздел «Дыры графа» в `_graph/report.md`, сгруппированный по бизнес-операциям, и вопросы в
  `_graph/open-questions.md` (идемпотентно, без дублей).

## Готово, когда
- Фикстура с намеренно снятыми рёбрами поднимает каждое правило; чистая фикстура — ни одного
  `W-op-*`.
- Повторный прогон не дублирует вопросы.

## Результат
- `sgraph/completeness.py`, правила данными в `references/completeness.json`. У правила: вид и роль узла,
  ключи frontmatter, условие `empty_all` (во всех ключах вместе меньше `min` ссылок) или `empty_any` (хотя бы в
  одном меньше `min`), флаг-исключение `unless`, severity, вопрос с `{name}`; `group_by` — вид для
  группировки. `self_check` сверяет правила с онтологией, при битых правилах `check` падает (fail-closed).
- Восемь правил ТЗ. Флаги аналитика: `system` (операция без UI), `public` (эндпойнт без вызывающего),
  `external_side` (другую сторону топика держит контрагент).
- Валидатор зовёт полноту сам: дыры идут в его счётчики (`E-consume-no-topic` — ошибка, поэтому её увидит
  гейт), в `_graph/report.md` — раздел «Дыры графа» по бизнес-операциям, вопросы — в `_graph/open-questions.md`
  вместе с вопросами шага link (операции без описания, неясные цели). Файл вопросов пересобирается целиком,
  поэтому дублей нет по построению.
- Тесты `test_completeness.py` (13): правила и их самопроверка, каждое правило через снятое ребро, флаги,
  группировка, идемпотентность вопросов. 10 мутантов пойманы.
- Уроки X.1: P-build-2, P-build-3 → covered.
- **Отклонение от «Готово, когда»:** чистая фикстура даёт два `W-op-no-*`. Это `W-op-no-creator` у «Регистрации»
  и «Приёма транспортных упаковок»: спека фикстуры действительно не называет, кто их формирует. Плюс
  `W-topic-side` у `pprbkid.task.closed.v1`: читателя нет. Это настоящие дыры корпуса, и тесты закрепляют
  ровно их. `W-op-no-closer` и `W-op-no-ui` на чистой фикстуре нет.
