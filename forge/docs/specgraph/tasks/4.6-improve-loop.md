# 4.6 — Цикл самоулучшения графа

**Этап:** 4 (самоулучшение) · **Зависит от:** 4.1, 3.5 · **Статус:** todo
**Решения:** D19 · **Механизм forge:** `verify_to_impl` (ui-verify переоткрывает ui-build)

## Зачем
Граф после первого прохода будет с дырами — в слепой разработке это неизбежно. Часть дыр можно
закрыть в окружении автоматически: целевой вопрос по одной заметке часто находит основание, которое
общий проход пропустил. Цикл берёт сигналы, пытается закрыть каждую дыру через те же проверяемые
инструменты и честно останавливается, когда прогресса нет.

## Что сделать
- Очередь `improve` — та же механика 0.6 (`.spec-graph/queue/improve.json`). Источники: дыры
  полноты (3.2), `W-orphan`, low-confidence рёбра, `unplaced`, stub-операции, находки
  самопроверки (4.5), обратная связь аналитиков (4.8, высший приоритет). Элемент: тип, цель (id
  заметки или секции), действие, попытки, исход.
- Действия:
  - **перелинковка заметки с целевым вопросом** — субагент получает одну заметку и вопрос («у
    операции нет шедулера закрытия: найди в тексте её и соседних заметок основание для
    `closes_task` или ответь „в спеке нет“»); предложения идут через `graph_link_put` с той же
    проверкой цитат;
  - **перепланирование секции** — для `unplaced` и подозрительных нарезок, через
    `graph_assign_put`;
  - **вопрос человеку** — то, что не решается текстом.
- Исход элемента: `resolved` | `not-in-spec` (уходит в open-questions для аналитика) | `failed`
  (попытка + 1, не больше 2 попыток на элемент).
- Границы (кодом): не больше N элементов за прогон (конфиг), стоп, если итерация закрыла 0
  элементов; рёбра с `confidence: low` не применяются, а идут человеку.
- Место в конвейере: шаг `graph-check` переоткрывает `graph-link` или `graph-map` для конкретных
  заметок и секций (`check_to_link`, `check_to_map` — по образцу `verify_to_impl`), затем снова
  проверка. Отдельный режим `/graph improve` запускает тот же цикл между прогонами.
- Отчёт приёмки (3.5) получает раздел «Изменено самоулучшением»: каждое добавленное или снятое
  ребро с основанием. Человек может отклонить любое (`graph_edges_decide`) перед согласием.

## Готово, когда
- Фикстура с тремя снятыми рёбрами: цикл закрывает те, у которых есть основание в тексте, и
  помечает `not-in-spec` то, у которого нет (подставные ответы субагентов).
- Остановка без прогресса и лимит элементов проверены тестом; повторный цикл на чистом графе — 0
  действий.
- В `health.json` видно, сколько закрыл цикл за прогон.
