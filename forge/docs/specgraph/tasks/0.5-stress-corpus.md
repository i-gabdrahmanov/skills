# 0.5 — Стресс-корпус: генератор вариантов стиля спеки

**Этап:** 0 · **Зависит от:** 0.4 · **Статус:** todo
**Решения:** D22 (работа вслепую — разнообразие вместо реальных данных)

## Зачем
Реальной спеки не будет никогда. Единственная защита от «на синтетике работает, в окружении нет» —
прогонять правила на многих стилях записи одного и того же содержания. Генератор берёт фикстуру ТЗ
(0.4) и детерминированно переписывает её форму, не трогая смысл. Поэтому эталонный граф у всех
вариантов один.

## Что сделать
- `skills/specgraph/scripts/tools/gen_variants.py` → `fixtures/tz-mini/variants/<имя>/`:
  трансформации — чистые функции, каждую можно включить отдельно:
  - нумерация заголовков `1.2.3`, `1.2.3.`, без нумерации, «Раздел 2.1»;
  - setext-заголовки (`===`/`---`), жирная строка вместо заголовка, заголовок с кодом `[abc_xyz]`;
  - описание API таблицей, прозой, OpenAPI-YAML во фенсе, списком `- METHOD /path`;
  - английские заголовки («Scheduler», «Kafka consumer», «Endpoints»);
  - HTML-таблица вместо Markdown-таблицы; нумерованные списки `1)`; вложенность через табы;
  - CRLF, BOM, неразрывные пробелы, ё/е;
  - незакрытый фенс, проза внутри json-фенса (уроки PROBLEMS.md §F);
  - «раздутый» вариант: 50 сервисов × 40 секций, файлы по 5 тыс. строк — бюджет времени.
- `variants/<имя>/expected.json` — эталон из 0.4 с переименованиями, если трансформация меняет
  текст заголовка (карта имён рядом).
- Тест-матрица `test_variants.py`: для каждого варианта — recall экстракторов (1.2) по видам,
  покрытие нарезки 100 % (1.6), e2e-рёбра (3.6). Варианты, которые правила пока не берут,
  помечаются `known_gap` с причиной. Такой вариант не валит прогон, но виден в отчёте и в
  диагностике (4.3) как известная слепая зона.

## Готово, когда
- Генератор детерминирован: повторный запуск даёт побайтно тот же результат.
- Матрица прогоняется, по каждому варианту записан статус: ok или `known_gap` с причиной.
- «Раздутый» вариант: скан и нарезка укладываются в бюджет из конфига теста (порядок — минуты, не
  часы; урок §G.1 про O(B²)).

## Заметки
- Каждое исправление по обратной связи из окружения (4.4) добавляет сюда трансформацию или
  синтетический блок той же формы — так корпус растёт из реальных находок, не видя реальных данных.
