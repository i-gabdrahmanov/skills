# 2.5 — Карточка бизнес-операции

**Этап:** 2 (graph-link) · **Зависит от:** 2.4 · **Статус:** todo
**ТЗ:** §4 (для чего / когда / что выполнить / результат), §6, §7 · **Решения:** D8

## Зачем
ТЗ хочет у бизнес-операции краткое описание из бизнес-требований. Это единственное место, где
граф пересказывает, а не переносит дословно. Поэтому пересказ привязан к основаниям: каждое
утверждение карточки ссылается на блок исходника, а полный текст лежит рядом дословно.

## Что сделать
- Секция `<!-- graph:card -->` в заметке `operation`: четыре поля ТЗ §4 — «Для чего», «Когда и при
  каких условиях», «Что необходимо выполнить», «Ожидаемый результат». Каждое утверждение
  заканчивается ссылкой на блок (`↗ business/укомплектование.md#3`).
- Единицы работы — очередь `card` (0.6), по одной на операцию.
- Инструмент `graph_card_put(item_id, operation, fields)`: ссылки ведут на source-блоки этой
  заметки; все четыре поля есть — либо заполнены, либо явно «нет в источнике»; не больше N
  предложений на поле.
- Бриф `references/briefs/operation-card.md`: только из блоков этой операции, без домысла.
- Операция без бизнес-текста (заведена по коду типа задачи) → `status: stub`, все поля «нет в
  источнике», вопрос в `_graph/open-questions.md`.
- `related` между операциями предлагается обычным ребром 2.3 с цитатой; здесь только
  проверяется, что у симметричного ребра одно основание на пару.

## Готово, когда
- Ссылка на чужой или несуществующий блок → отказ; пропущенное поле → отказ.
- Фикстура: 4 операции с карточками, «Передача упаковок» ↔ «Укомплектование» через `related`.
- Stub-операция видна в отчёте как дыра, а не как готовая карточка.
