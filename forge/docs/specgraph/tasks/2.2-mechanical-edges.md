# 2.2 — Механические рёбра

**Этап:** 2 (graph-link) · **Зависит от:** 2.1 · **Статус:** done
**ТЗ:** §1.3, §3 · **Решения:** D14

## Зачем
Часть связей видна по форме текста: обработчик топика читает топик, `POST /path` чужого сервиса в
алгоритме — вызов, «отправляет в топик X» — публикация. Такие рёбра ставит скрипт с цитатой-
основанием; модель решает только то, что требует понимания: формирует/закрывает задачу, UI задачи,
бизнес-связи.

## Что сделать
- `sgraph/edges_rules.py`, правило → предложение `{from, edge, to, quote, rule, confidence}`:
  - `kafka-op(consume)` → `consumes` → топик из заголовка или кандидата 1.2;
  - «отправ… / публику… / направля… … в топик `<t>`» → `publishes_to`;
  - `METHOD /path` в теле, который резолвится в эндпойнт другого сервиса, рядом глагол вызова →
    `calls`; тот же сервис → кандидат `invokes` с `confidence: medium`;
  - точное имя или алиас `data`-узла в теле → `uses_data` (`medium`);
  - упоминание в стоп-контекстах — «см. также», оглавление, «связанные документы» (список — конфиг)
    — ребром не становится: ТЗ §3 «реальные взаимодействия, а не упоминания».
- Цитата — строка исходника, на которой сработало правило, дословно из тела заметки.
- Предложения кладутся в ту же очередь, что и предложения модели (2.3), с `origin: rule:<id>`.

## Готово, когда
- На фикстуре precision 100 % и recall 100 % по рёбрам эталона с `mechanical: true`; строка «см.
  также rmoc-service» ребра не даёт.
- Каждое правило — позитивный и негативный тест.

## Результат
- `sgraph/edges.py`: общая проверка предложения `Graph.check` (на правила и модель): ребро и концы по
  онтологии (роль, same_service), цель через резолвер (`ambiguous`/`ghost` — отказ `E-edge-target` с
  кандидатами), цитата ≥ 20 знаков дословно в тексте маркеров `graph:source*` источника или цели
  (`E-edge-quote`), недопустимая пара — `E-edge-kind`. Хранилище `.spec-graph/edges/<id>.json`: тот же
  (ребро, цель) — одна запись, цитаты копятся; отклонённое не воскрешается.
- Правила (`R-edge-consume`, `R-edge-publish`, `R-edge-http`, `R-edge-data`): обработчик → топик своего
  текста; «отправ/публику/направля… топик» → `publishes_to` (только от тех, кому онтология разрешает);
  `METHOD /path` → `calls` (свой сервис — уверенность medium, сам себя — нет); имя/алиас узла данных
  (≥ 8 знаков) → `uses_data` (medium). Строки разделов «См. также» не читаются.
- Онтология: `can_start(edge, node)`, `target_kinds(edge)` — правила не называют видов литералом.
- Инструмент `graph_edges_mechanical` (свободный: механика без решений модели).
- Фикстура: 18 рёбер = ровно рёбра эталона с `mechanical: true` (precision и recall 100 %).
- Тесты `test_mechanical_edges.py` (4); мутанты (цитата не сверяется, «См. также», вызов себя) пойманы.
- **Не проверено данными:** глаголы публикации и порог длины имени данных — по синтетике; в поле видно по
  счётчикам правил (диагностика 4.3).
