# 2.4 — Синк рёбер и guard frontmatter

**Этап:** 2 (graph-link) · **Зависит от:** 2.3, 0.3 · **Статус:** todo
**ТЗ:** §5 («открываю шедулер — вижу все операции»), §8.2 · **Решения:** рычаг 2, D6, D9
**Уроки:** инварианты 2, 20, 23, 25, 26 прототипа; память «except в хуках прячет NameError»

## Зачем
Прямые рёбра записываются у владельца, обратные выводятся из всех прямых. Тогда «ребро с одной
стороны» невозможно по построению, и пропадает весь класс ремонтных проходов прототипа. Чтобы
модель не писала FM мимо синка, правку frontmatter руками закрывает хук.

## Что сделать
- Инструмент `graph_sync(scope)`:
  - принятые прямые рёбра → FM-ключ у источника (отсортированно, ссылки в кавычках) и блок
    `<!-- graph:edges -->` в теле — таблица «связь | цель | основание | источник»;
  - обратные ключи у всех узлов пересчитываются полностью из прямых рёбер всего vault, поэтому
    устаревшие уходят сами; симметричное `related` зеркалится;
  - прямое ребро в FM без предложения (добавил человек в Properties) → в блоке оснований
    «внесено человеком», `origin: manual`;
  - ручная правка обратного ключа перезаписывается, `W-manual-inverse` в отчёт.
- Хук `hooks/graph-guard.py` (PreToolUse, только ветка `specgraph`): `write_file`/`edit`/`replace`
  по `<vault>/**/*.md`, меняющие FM (сравнение разобранного FM до и после) или содержимое маркеров
  `graph:*`, → deny с подсказкой «через graph_*». Проза вне маркеров разрешена. `.spec-graph/**` —
  в `_CP_PATTERNS` state-write-guard.
- `phase_tools` для `graph-link`: `graph_link_put`, `graph_sync`.

## Готово, когда
- Синк идемпотентен (второй прогон — 0 изменений); снятое прямое ребро снимает и обратное.
- Фикстура: у «Шедулера закрытия регулярных задач» три `closes_task`, у каждой из трёх операций
  выведен `closed_by` на него (ТЗ §5).
- Хук: правка FM — deny, правка прозы — allow, правка внутри `graph:edges` — deny. Весь тест-файл
  хука гоняется после правки, плюс проверка «потерянная функция под `except`».
