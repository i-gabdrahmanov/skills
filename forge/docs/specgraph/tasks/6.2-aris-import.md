# 6.2 — Импорт бизнес-процессов из ARIS (без образцов)

**Этап:** 6 (процессы) · **Зависит от:** 6.1, 4.2 · **Статус:** todo
**Решения:** D16, D17 · **ТЗ:** §8.5, §8.6

## Зачем
Бизнес-флоу ведутся в ARIS. Подключив их, мы увидим процесс целиком: шаг ARIS → бизнес-операция →
шедулеры, UI, эндпойнты. Образцов выгрузки не будет, поэтому импортёр опирается на открытые форматы,
а привязка к конкретной выгрузке подбирается в окружении по её профилю и утверждается человеком.

## Что сделать
- Два встроенных адаптера по публичным описаниям форматов, стандартная библиотека
  (`xml.etree`), запуск системным 3.9 (на homebrew-python битый pyexpat):
  - **BPMN 2.0 XML** (стандарт OMG, ARIS умеет его выгружать): `process`, `subProcess`, `task` и
    виды задач, `sequenceFlow`, `exclusiveGateway`/`parallelGateway`, `lane`/`laneSet`,
    `documentation`;
  - **AML** (ARIS Markup Language) по известной структуре: `Group`, `ObjDef` с `TypeNum`, `AttrDef`
    (`AT_NAME`, `AT_DESC`), `CxnDef` с `ToObjDef.IdRef`, `Model`/`ObjOcc`. Это допущение — «не
    проверено данными».
- Декларативная привязка `.spec-graph/import/<имя>.map.json`: какой элемент — процесс, какой —
  шаг, откуда имя и описание, какая связь — последовательность, какая — исполнитель. Встроенные
  адаптеры — это готовые привязки, и любую можно поправить в окружении без кода.
- Незнакомый файл: `graph_profile` (4.2) даёт структуру без значений → модель в окружении
  предлагает привязку по профилю → проверочный импорт в песочницу (`.spec-graph/import/preview/`,
  vault не трогается) со счётчиками «процессов N, шагов M, связей K, нераспознанных элементов L» →
  человек утверждает. Профиль и счётчики идут в диагностику, так мы видим реальную форму выгрузки.
- Онтология: `process-step` (шаг), `role`; рёбра `step_of` (шаг → процесс), `next` (шаг → шаг,
  с условием ветвления в свойстве), `performed_by` (шаг → роль), `realized_by` (шаг → операция |
  экран). `key: aris:<GUID или id элемента>` — повторный импорт стабилен.
- Сопоставление шагов ARIS с операциями графа — только таблицей `_graph/aris-map.md`: кандидатов
  предлагает механика (совпадение имени, код типа задачи), решает человек. Нечёткого
  автосвязывания нет. Неразмеченные шаги — `W-step-unmapped`.
- Описания и атрибуты шагов переносятся в тело дословно.

## Готово, когда
- Синтетические BPMN- и AML-файлы (написаны по описанию форматов, лежат в `fixtures/aris/`)
  импортируются; повторный импорт — 0 изменений.
- Изменённый синтетический файл (другие имена элементов) импортируется после правки только
  `map.json` (тест).
- Песочный импорт не трогает vault; `realized_by` появляется только по утверждённой таблице.
