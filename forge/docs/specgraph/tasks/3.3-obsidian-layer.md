# 3.3 — Obsidian-слой

**Этап:** 3 (graph-check) · **Зависит от:** 3.1 · **Статус:** todo
**ТЗ:** §8.1, §8.2, §8.4, §10 · **Решения:** D12

## Зачем
Аналитик работает в Obsidian. Виды узлов должны различаться цветом, у графа должна быть точка
входа, а таблицы вида «шедулеры и их операции» должны строиться без плагинов. Подписей рёбер в
core graph view нет — их роль берут Properties заметки и Bases-виды.

## Что сделать
- `.obsidian/graph.json`: `colorGroups` по видам через `path:`-запросы (`business/operations`,
  `services/*/schedulers` и т. д.). Слияние, а не перезапись: группы помечены нашим префиксом
  запроса, чужие настройки пользователя сохраняются; файла нет — создаётся. Формат сверить на
  файле, сохранённом локальным Obsidian.
- `_graph/Начало.md` — входы: бизнес-процессы, бизнес-операции (со счётчиками шедулеров и UI),
  сервисы; легенда цветов и ключей рёбер (`title_ru` из онтологии).
- Bases-виды `_graph/views/*.base`: «Бизнес-операции» (`created_by`, `closed_by`, `screens`,
  `related`), «Шедулеры» (`creates_task`, `closes_task`, сервис), «Эндпойнты по сервисам»
  (`called_by`), «Kafka» (топики с издателями и потребителями). Версия Obsidian в окружении
  неизвестна, поэтому слой выбирается по факту: если `.obsidian/core-plugins.json` включает
  `bases` — пишутся `.base`, иначе (или файла нет) — те же таблицы Markdown-заметками в
  `_graph/views/` (их Obsidian покажет в любой версии). Что выбрано — в отчёте и в разделе
  «Окружение» диагностики (4.3).
- Оглавление в заметке сервиса (`generated:toc`) — операции по видам.
- Опционально, по флагу конфига: подсказка для плагина подписей рёбер (если разрешены
  community-плагины).

## Готово, когда
- Слияние `graph.json` сохраняет чужие ключи и группы (тест); повтор — 0 изменений.
- `Начало.md`, виды и оглавления детерминированы.
- Ручная проверка на фикстуре в Obsidian: цвета по видам, переходы ТЗ §10 кликаются — одна строка
  в «Результате» с версией Obsidian.
