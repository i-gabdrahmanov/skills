# 3.3 — Obsidian-слой

**Этап:** 3 (graph-check) · **Зависит от:** 3.1 · **Статус:** done
**ТЗ:** §8.1, §8.2, §8.4, §10 · **Решения:** D12

## Зачем
Аналитик работает в Obsidian. Виды узлов должны различаться цветом, у графа должна быть точка
входа, а таблицы вида «шедулеры и их операции» должны строиться без плагинов. Подписей рёбер в
core graph view нет — их роль берут Properties заметки и Bases-виды.

## Что сделать
- `.obsidian/graph.json`: `colorGroups` по видам через `path:`-запросы (`business/operations`,
  `services/*/schedulers` и т. д.). Слияние, а не перезапись: группы помечены нашим префиксом
  запроса, чужие настройки пользователя сохраняются; файла нет — создаётся. Формат сверить на
  файле, сохранённом локальным Obsidian.
- `_graph/Начало.md` — входы: бизнес-процессы, бизнес-операции (со счётчиками шедулеров и UI),
  сервисы; легенда цветов и ключей рёбер (`title_ru` из онтологии).
- Bases-виды `_graph/views/*.base`: «Бизнес-операции» (`created_by`, `closed_by`, `screens`,
  `related`), «Шедулеры» (`creates_task`, `closes_task`, сервис), «Эндпойнты по сервисам»
  (`called_by`), «Kafka» (топики с издателями и потребителями). Версия Obsidian в окружении
  неизвестна, поэтому слой выбирается по факту: если `.obsidian/core-plugins.json` включает
  `bases` — пишутся `.base`, иначе (или файла нет) — те же таблицы Markdown-заметками в
  `_graph/views/` (их Obsidian покажет в любой версии). Что выбрано — в отчёте и в разделе
  «Окружение» диагностики (4.3).
- Оглавление в заметке сервиса (`generated:toc`) — операции по видам.
- Опционально, по флагу конфига: подсказка для плагина подписей рёбер (если разрешены
  community-плагины).

## Готово, когда
- Слияние `graph.json` сохраняет чужие ключи и группы (тест); повтор — 0 изменений.
- `Начало.md`, виды и оглавления детерминированы.
- Ручная проверка на фикстуре в Obsidian: цвета по видам, переходы ТЗ §10 кликаются — одна строка
  в «Результате» с версией Obsidian.

## Результат
- `sgraph/obsidian.py`, инструмент `graph_obsidian`; что и куда — данными в `references/obsidian.json`
  (палитра, точки входа со счётчиками и подписями, виды-таблицы), сверка с онтологией (`self_check`), битый
  слой — отказ `E-obsidian`.
- `.obsidian/graph.json`: `colorGroups` по видам, запрос `path:` из шаблона пути вида
  (`path:"services/" path:"/schedulers/"`). Узкие запросы идут раньше широких, потому что узел красит первая
  подходящая группа. Слияние: чужие ключи и группы пользователя сохраняются и идут после наших; цвет,
  выбранный пользователем для нашего запроса, остаётся; свои запросы движок помнит в `.spec-graph/obsidian.json`
  и снимает только свои устаревшие. Не-JSON — отказ, файл не трогается. Повтор — 0 записей.
- Режим видов по факту: `bases` включён в `.obsidian/core-plugins.json` (список или объект) — `_graph/views/*.base`
  (`note.kind == "<вид>"`, колонки `note.<ключ>`, `groupBy`), иначе те же таблицы Markdown-заметками с
  разделами по сервису. Виды прежнего режима снимаются. Режим — в ответе инструмента (`mode`).
- `_graph/Начало.md`: процессы, операции (формируют / закрывают / UI), сервисы (операций); легенда цветов и
  ключей рёбер из онтологии; ссылки на виды.
- Оглавление сервиса — маркер `graph:toc` нарезки (1.6), тест закрепляет операции по видам.
- `scripts/tools/demo_vault.py --out <каталог> [--bases]` — vault фикстуры для ручной проверки в Obsidian.
- Тесты `test_obsidian_layer.py` (10); 13 мутантов пойманы.

  - синтаксис `.base` (фильтр `note.kind`, `groupBy`) не проверен в живом Obsidian;
  - ручная проверка цветов и переходов ТЗ §10 не проведена — это GUI. Сделать так: собрать vault командой
    `demo_vault.py` и открыть `<out>/repo/docs/graph` в Obsidian.
