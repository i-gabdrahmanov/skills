# 3.5 — Шаг graph-check и приёмка

**Этап:** 3 (graph-check) · **Зависит от:** 3.2, 3.3, 3.4 · **Статус:** todo
**ТЗ:** §9.7–9.9, §9 «Исходные спецификации не удалять до проверки», §10 · **Решения:** D13

## Зачем
Последнее решение человека — принять граф. После приёмки пользователь сам решает, удалять ли
плоские спеки. Поэтому шаг должен честно ответить, какой исходник перенесён полностью, а какой нет.

## Что сделать
- `graph_gate.py check`:
  - `graph_validate` — 0 `E-*`;
  - отчёт полноты 3.2 и Obsidian-слой 3.3 записаны и свежие (хеши в стейте);
  - смоук обхода без модели: для каждой операции `graph_node` и `graph_impact` отвечают без
    ошибок, для каждого `walk` из конфига (по умолчанию — переходы ТЗ §10 по найденным
    операциям) путь существует;
  - согласие `graph-accept-<KEY>`, привязанное к хешу `_graph/report.md`.
- Раздел «Перенос исходников» в `_graph/report.md`: по каждому файлу — «перенесён полностью»
  (покрытие 100 %, дословность цела, 0 `E-*` в его заметках) или что мешает. Удаляет исходники
  пользователь сам, пайплайн этого не делает.
- После удаления исходника валидатор переводит его блоки в `W-source-missing`. Это не ошибка:
  дословный текст уже в vault.
- Бриф шага в SKILL.md: показать пользователю сводку отчёта (счётчики, дыры по операциям,
  перенос исходников) и спросить о приёмке.

## Готово, когда
- Тесты гейта: `E-*` > 0, устаревший отчёт, нет согласия → блок.
- На фикстуре после 1.7 и 2.6 шаг проходит до exit 0; все исходники фикстуры (кроме исключённого
  черновика) — «перенесён полностью».
