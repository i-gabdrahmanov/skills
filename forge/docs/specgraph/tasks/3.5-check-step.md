# 3.5 — Шаг graph-check и приёмка

**Этап:** 3 (graph-check) · **Зависит от:** 3.2, 3.3, 3.4 · **Статус:** done
**ТЗ:** §9.7–9.9, §9 «Исходные спецификации не удалять до проверки», §10 · **Решения:** D13

## Зачем
Последнее решение человека — принять граф. После приёмки пользователь сам решает, удалять ли
плоские спеки. Поэтому шаг должен честно ответить, какой исходник перенесён полностью, а какой нет.

## Что сделать
- `graph_gate.py check`:
  - `graph_validate` — 0 `E-*`;
  - отчёт полноты 3.2 и Obsidian-слой 3.3 записаны и свежие (хеши в стейте);
  - смоук обхода без модели: для каждой операции `graph_node` и `graph_impact` отвечают без
    ошибок, для каждого `walk` из конфига (по умолчанию — переходы ТЗ §10 по найденным
    операциям) путь существует;
  - согласие `graph-accept-<KEY>`, привязанное к хешу `_graph/report.md`.
- Раздел «Перенос исходников» в `_graph/report.md`: по каждому файлу — «перенесён полностью»
  (покрытие 100 %, дословность цела, 0 `E-*` в его заметках) или что мешает. Удаляет исходники
  пользователь сам, пайплайн этого не делает.
- После удаления исходника валидатор переводит его блоки в `W-source-missing`. Это не ошибка:
  дословный текст уже в vault.
- Бриф шага в SKILL.md: показать пользователю сводку отчёта (счётчики, дыры по операциям,
  перенос исходников) и спросить о приёмке.

## Готово, когда
- Тесты гейта: `E-*` > 0, устаревший отчёт, нет согласия → блок.
- На фикстуре после 1.7 и 2.6 шаг проходит до exit 0; все исходники фикстуры (кроме исключённого
  черновика) — «перенесён полностью».

## Результат
- `sgraph/accept.py`, инструмент `graph_check`. Он пересобирает проверку (ошибки, дыры, перенос исходников) и
  Obsidian-слой, гоняет смоук обхода и отдаёт сводку для пользователя с состоянием согласия
  `graph-accept-<KEY>` на `_graph/report.md`.
- Смоук без модели: по каждой бизнес-операции `graph_node` и `graph_impact` отвечают; путь от операции до
  сервиса каждого её соседа существует; каждый переход `walks` из конфига (новый ключ `walks: [{from, to,
  why?}]`) находит путь.
- Раздел «Перенос исходников» в `_graph/report.md`: по каждому файлу — блоков, заметок, неразмещённых и итог.
  «Перенесён полностью» означает: каждый блок назначен, ошибок E-* в заметках этого файла нет. Иначе — что
  мешает. Удалённый исходник помечается «(исходник удалён)» и даёт W-source-missing, но не ошибку.
- `graph_gate.py check`:
  - валидатор — 0 E-*;
  - отчёт и `_graph/open-questions.md` свежие: пересчёт `validate(write=False)` даёт тот же текст;
  - Obsidian-слой свежий: `build(dry=True)` — 0 изменений;
  - смоук без проблем;
  - согласие привязано к хешу отчёта.
  Гейт ничего не пишет. Нереализованных шагов больше нет: код и тексты не обещают exit 3, и тест это
  закрепляет.
- SKILL.md: раздел «Шаг graph-check — проверка и приёмка», раздел «Статус реализации» снят.
- Фикстура: после map и link шаг проходит до exit 0; все 8 исходников (черновик исключён) — «перенесён
  полностью».
- Тесты `test_check_step.py` (9); 12 мутантов пойманы.
- **Отклонение:** свежесть проверяется пересчётом без записи, а не хешами в стейте. Это строже: хеш поймал бы
  только правку файла, а пересчёт ловит и изменившийся граф.
