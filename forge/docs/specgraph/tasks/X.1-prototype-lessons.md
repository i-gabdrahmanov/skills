# X.1 — Матрица уроков прототипа

**Этап:** сквозная · **Зависит от:** 0.2 · **Статус:** todo
**Вводные:** `граф вводные/spec-graph/SKILL.md` (инварианты 1–27, раздел «Сборка, версии и
качество»), `spec-graph-check/SKILL.md`, `spec-graph-repair/SKILL.md`, `PROBLEMS.md` §G

## Зачем
Прототип дорого заплатил за свои 27 инвариантов и 8 методологических инцидентов. Код не
переносим (D15), но уроки терять нельзя. Каждый урок должен оказаться либо закрытым тестом, либо
снятым архитектурой (и тогда надо сказать чем), либо неприменимым по названной причине. Так же
устроена матрица инвариантов forge-ui (X.1 там).

## Что сделать
- `skills/specgraph/references/lessons.json`: запись на урок — `id` (`P-inv-9`, `P-G-2`, …),
  дословная суть, `status: covered | by-construction | n/a | planned`, `ref` (тест
  `<файл>::<Класс>`, задача или объяснение).
  Примеры классификации (проверить и дополнить):
  - инв. 9 «списки только с кавычками» → `covered` (0.3);
  - инв. 2 «ребро с обеих сторон» → `by-construction` (обратное выводит синк, 2.4);
  - инв. 4 «ничего не теряем» и сверка flat-check → `by-construction` (разбиение блоков, 1.6);
  - инв. 18 «вики-ссылка только на существующий узел» → `covered` (3.1, `E-ghost`);
  - инв. 19 «главы документа не связываются рёбрами» → `covered` (D7 + проверка 3.1);
  - инв. 16 «зеркальные fl/ul-adapter» → `n/a` (доменный хардкод; при нужде — конфиг);
  - §G.2 «сырые обратные слэши ломают JSON отчётов» → `covered` (проверка аргументов
    инструментов, 1.3/1.5/2.3);
  - §G.6 «хардкод даты прогона» → `covered` (каталог прогона из стейта, 0.1);
  - режим C прототипа → `n/a` (D15); `spec-graph-repair` → `by-construction` (дословный перенос) плюс
    цикл самоулучшения 4.6 для дыр связей;
  - режим diff `spec-graph-bench` → `covered` (самопроверка 4.5); `loop-check.json` с историей и
    меткой стабилизации → `covered` (4.1, `health.json`).
- `skills/specgraph/scripts/test_lessons.py`: у каждой записи статус из списка; `covered`
  указывает на существующий тест; `planned` — только на незакрытую задачу из README. Закрытие
  задачи с оставшимся `planned` валит тест.
