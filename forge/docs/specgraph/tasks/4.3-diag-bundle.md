# 4.3 — Диагностический пакет `/graph diag`

**Этап:** 4 (диагностика) · **Зависит от:** 4.1, 4.2, 3.1, 3.2 · **Статус:** done
**Решения:** D17

## Зачем
Это единственный канал, по которому знание из окружения доходит до разработки. Пакет должен быть
безопасным для выноса (без текста спеки), помещаться в одно сообщение и отвечать на вопрос «что
пошло не так и где» без доступа к данным.

## Что сделать
- Режим той же команды: `/graph diag` → инструмент `graph_diag` → `_graph/diag/diag-<дата>-<KEY>.md`,
  не больше ~400 строк. Разделы:
  1. Версии: тег forge, версия онтологии и хеш локального расширения (4.9), рантайм, python.
  2. Окружение (doctor): MCP виден, хуки зарегистрированы, extension включён для workspace,
     core-плагины Obsidian из `.obsidian/core-plugins.json` (есть ли Bases).
  3. Прогоны: шаги, статусы, длительности, число субагентов и вопросов.
  4. Здоровье графа: тренд из `health.json`, `E-*`/`W-*` по кодам, дыры полноты, покрытие.
  5. Где буксовала модель: топ кодов отказа инструментов, секции с наибольшим числом попыток
     (по id и форме блока из профиля), брошенные секции.
  6. Правила: по каждому экстрактору — попадания, промахи (узел вида X в утверждённом каталоге без
     кандидата), ложные срабатывания (кандидат отклонён); рёбра по происхождению и доле
     отклонённых человеком по типу ребра.
  7. Профиль входа (4.2, сжатый), кандидаты в новые виды (4.9), выученные правила (4.7) — хешами.
  8. Самопроверка (4.5) и обратная связь аналитиков (4.8) — счётчики по классам.
  9. Машинный блок: тот же пакет JSON-фенсом в конце, для разбора скриптом (4.4).
- **Самопроверка утечки перед записью:** если любая последовательность ≥ 4 слов или подстрока ≥ 24
  знаков из исходников или заметок vault встречается в пакете → файл не пишется, exit 3, в ответе
  номера строк пакета. Пакет без самопроверки не создаётся (кодом, не брифом).
- Пакет пишется не только по запросу: в конце шага `graph-check` и при любой остановке гейта
  (exit ≠ 0) свежий пакет кладётся в `_graph/diag/` автоматически — у пользователя всегда есть
  что вынести, даже если прогон оборвался. Хранится 10 последних.
- `--level excerpt` — по явному решению пользователя: добавляет выбранные фрагменты с пометкой
  «ПРОВЕРЬ ПЕРЕД ВЫНОСОМ». Самопроверка утечки на них не действует, всё остальное — как обычно.
- Сжатие под лимит: при превышении сначала режутся списки (топ-10 → топ-5), потом разделы 7 и 8.
  Разделы 1–6 не режутся.

## Готово, когда
- Пакет на фикстуре и на каждом варианте 0.5 проходит самопроверку утечки; мутант «вставить
  заголовок исходника» даёт exit 3.
- Пакет укладывается в лимит строк на «раздутом» варианте.
- По пакету с намеренно сломанным правилом (мутант экстрактора шедулеров) видно, какое правило и
  на какой форме заголовка промахивается — проверяется тестом на разделе 6.

## Результат
- `sgraph/diag.py`, инструмент `graph_diag(level?, blocks?)`, CLI `scripts/graph_diag.py` (0 — записан, 2 —
  неверный вызов, 3 — утечка). В `/graph diag` (`commands/graph.md`) и SKILL.md — раздел «Диагностика».
- Пакет `_graph/diag/diag-<дата>-<KEY>.md` из девяти разделов:
  1. версии — `forgeRevision` из манифеста поставки, движок, онтология и хеш локальной, рантайм, python;
  2. окружение — MCP в манифесте, graph-guard в `hooks.json`, поставка в проекте, core-plugins и Bases,
     режим слоя;
  3. прогоны — по ключу: вызовы, минуты, выданные единицы, исходы по инструментам, счётчики; нарушений по
     гейтам сейчас — только числа;
  4. здоровье — коды, покрытие, перенос, тренд из `health.json`;
  5. где буксовала модель — топ кодов отказа, самые трудные единицы (id, попытки, коды, формы заголовков),
     брошенные единицы;
  6. правила — попадания и ложные по каждому экстрактору; промахи — узел вида в утверждённом каталоге без
     кандидата, с формой заголовка и id правил вида; рёбра по происхождению с долей отклонённого;
  7. профиль входа и кандидаты в новые виды хешами;
  8. самопроверка и обратная связь — пока «нет данных» (4.5, 4.8), выученные правила (4.7);
  9. машинный блок JSON.
- Самопроверка утечки кодом до записи. Отпечатки корпуса (все файлы корней спеки, включая исключённые, и
  заметки vault) — 4-словные последовательности и 24-знаковые окна от начала слова. Совпадение — отказ
  `E-diag-leak` с номерами строк, файл не пишется. Раздел фрагментов (`level: excerpt`, только с выбранными
  блоками) помечен «ПРОВЕРЬ ПЕРЕД ВЫНОСОМ» и самопроверке не подлежит.
- Лимит 400 строк: сначала списки 10 → 5, потом разделы 7–8; разделы 1–6 не режутся. Хранятся 10 пакетов.
- Пакет пишется сам: в конце `graph_check` (поле `diag` ответа) и при каждой остановке гейта (строка
  «пакет диагностики: …»). Сбой пакета шаг не роняет.
- `graph_check` теперь пишет снимок здоровья (`record_health` из 4.1 до этого никто не звал): числа и хеши
  находок, поэтому тренд и стабилизация живые.
- Найдено по ходу: разведка (1.3) на «раздутом» корпусе шла 42 с из-за квадрата по именам корпуса.
  Исправлено отдельным коммитом, теперь 1,4 с; выход прежний байт-в-байт.
- Тесты `test_diag_bundle.py` (14):
  - фикстура: пакет из `graph_check`, 9 разделов, ни одного имени узла, тренд;
  - все 16 вариантов проходят самопроверку;
  - вставленный заголовок исходника — exit 3, файл не записан;
  - «раздутый» корпус и переполнение — ≤ 400 строк;
  - сломанное правило шедулеров видно в разделе 6: «scheduler: промахов 4; формы заголовков: h3:N.N: 4;
    правила вида: R-scheduler-heading»;
  - пакет при остановке гейта, 10 последних, excerpt.
  12 мутантов пойманы.
- **Не проверено:** манифест и `hooks.json` в установленной поставке на GigaCode — в источнике их нет, раздел 2
  на фикстуре показывает «нет манифеста».
