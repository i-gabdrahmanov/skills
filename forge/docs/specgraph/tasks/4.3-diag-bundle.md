# 4.3 — Диагностический пакет `/graph diag`

**Этап:** 4 (диагностика) · **Зависит от:** 4.1, 4.2, 3.1, 3.2 · **Статус:** todo
**Решения:** D17

## Зачем
Это единственный канал, по которому знание из окружения доходит до разработки. Пакет должен быть
безопасным для выноса (без текста спеки), помещаться в одно сообщение и отвечать на вопрос «что
пошло не так и где» без доступа к данным.

## Что сделать
- Режим той же команды: `/graph diag` → инструмент `graph_diag` → `_graph/diag/diag-<дата>-<KEY>.md`,
  не больше ~400 строк. Разделы:
  1. Версии: тег forge, версия онтологии и хеш локального расширения (4.9), рантайм, python.
  2. Окружение (doctor): MCP виден, хуки зарегистрированы, extension включён для workspace,
     core-плагины Obsidian из `.obsidian/core-plugins.json` (есть ли Bases).
  3. Прогоны: шаги, статусы, длительности, число субагентов и вопросов.
  4. Здоровье графа: тренд из `health.json`, `E-*`/`W-*` по кодам, дыры полноты, покрытие.
  5. Где буксовала модель: топ кодов отказа инструментов, секции с наибольшим числом попыток
     (по id и форме блока из профиля), брошенные секции.
  6. Правила: по каждому экстрактору — попадания, промахи (узел вида X в утверждённом каталоге без
     кандидата), ложные срабатывания (кандидат отклонён); рёбра по происхождению и доле
     отклонённых человеком по типу ребра.
  7. Профиль входа (4.2, сжатый), кандидаты в новые виды (4.9), выученные правила (4.7) — хешами.
  8. Самопроверка (4.5) и обратная связь аналитиков (4.8) — счётчики по классам.
  9. Машинный блок: тот же пакет JSON-фенсом в конце, для разбора скриптом (4.4).
- **Самопроверка утечки перед записью:** если любая последовательность ≥ 4 слов или подстрока ≥ 24
  знаков из исходников или заметок vault встречается в пакете → файл не пишется, exit 3, в ответе
  номера строк пакета. Пакет без самопроверки не создаётся (кодом, не брифом).
- Пакет пишется не только по запросу: в конце шага `graph-check` и при любой остановке гейта
  (exit ≠ 0) свежий пакет кладётся в `_graph/diag/` автоматически — у пользователя всегда есть
  что вынести, даже если прогон оборвался. Хранится 10 последних.
- `--level excerpt` — по явному решению пользователя: добавляет выбранные фрагменты с пометкой
  «ПРОВЕРЬ ПЕРЕД ВЫНОСОМ». Самопроверка утечки на них не действует, всё остальное — как обычно.
- Сжатие под лимит: при превышении сначала режутся списки (топ-10 → топ-5), потом разделы 7 и 8.
  Разделы 1–6 не режутся.

## Готово, когда
- Пакет на фикстуре и на каждом варианте 0.5 проходит самопроверку утечки; мутант «вставить
  заголовок исходника» даёт exit 3.
- Пакет укладывается в лимит строк на «раздутом» варианте.
- По пакету с намеренно сломанным правилом (мутант экстрактора шедулеров) видно, какое правило и
  на какой форме заголовка промахивается — проверяется тестом на разделе 6.
