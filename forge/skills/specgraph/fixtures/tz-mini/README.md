# tz-mini — синтетическая фикстура по ТЗ аналитика

Маленький корпус, повторяющий ФОРМУ спеки из ТЗ (`docs/specgraph/tz-analytics.md`), и эталонный граф,
который из него должен получиться. Реальной спеки не будет (работа вслепую), поэтому это главная
приёмка этапов 0–3 и база стресс-корпуса (0.5). **Всё содержание выдумано**: коды типов задач,
пути API, топики, атрибуты — правдоподобные, но не из настоящей системы.

## Что в sources/

| файл | что | разделы ТЗ |

Формы, которые проверяют нарезку: JSON- и SQL-фенсы, таблицы, нумерованный алгоритм с фенсом внутри
пункта, якорная ссылка `](#ручная-заявка)` на подраздел, картинка `resources/task-flow.png`, кириллица в
именах файлов.

## Ловушки (что граф обязан сделать правильно)

- **Общий шедулер (ТЗ §5):** «Шедулер закрытия регулярных задач» — один узел с тремя `closes_task`.
- **Похожие, но разные (ТЗ §6):** «Шедулер закрытия задачи передачи упаковок в СЦ-архив» — отдельный
  узел, не склеивается с общим.
- **Упоминание ≠ взаимодействие (ТЗ §3):** раздел «7. См. также» называет rmoc-service и upz-adapter, но
  рёбер не даёт.
- **Публикация отдельным разделом:** шедулер закрытия `invokes` → «Отправка события о закрытии задачи»
  (kafka-op publish), а `publishes_to` идёт уже от неё; у upz-adapter публикация — фраза внутри
  эндпойнта, поэтому `publishes_to` идёт прямо от эндпойнта.
- **Подраздел алгоритма — не узел:** «5.1 Ручная заявка» входит в заметку алгоритма.
- **Черновик** — вне графа; его «22:00» не должно попасть ни в одну заметку.

## expected/graph.json

- `nodes` — kind, name, service (для владельца), role/subkind/key, источник `файл#раздел`.
- `edges` — прямые рёбра; у всех, кроме `belongs_to`, — дословная цитата-основание `quote` из `file`
  (сверка с нормализацией пробелов) и `mechanical`: ставит ли ребро правило 2.2 без модели.
- `walks` — переходы ТЗ §10 путями «узел, ключ ребра, узел, …»; ключ — прямой (`closes_task`) или
  обратный (`closed_by`).
- Позже сюда добавятся «ответы модели» для e2e: `expected/drafts/` (1.3), `expected/plans/` (1.5),
  `expected/edges/` (2.3).
