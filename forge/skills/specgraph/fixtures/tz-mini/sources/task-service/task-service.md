# task-service

## 1. Общее описание

task-service формирует, обрабатывает и закрывает задачи сотрудников ВСП. Задачи хранятся в таблице
`task`, тип задачи задаётся кодом из справочника типов задач.

| код типа | тип задачи |
|---|---|
| KOMPLEKT | Укомплектование |
| REGISTRATION | Регистрация |
| TP_RECEIVE | Приём транспортных упаковок |
| SC_ARCHIVE | Передача упаковок в СЦ-архив |

## 2. Шедулеры

### 2.1 Шедулер формирования задачи укомплектования

Запускается по расписанию `0 0/5 * * * *` (каждые 5 минут).

Алгоритм:

1. Выбрать ВСП, у которых наступил срок укомплектования по графику.
2. Для каждого такого ВСП сформировать задачу с типом `KOMPLEKT` (Укомплектование), если открытой задачи
   этого типа у ВСП ещё нет.
3. Заполнить атрибуты задачи по набору «Динамические атрибуты укомплектования» (раздел 6.1).
4. Создать задачу в УПЗ: вызвать `POST /api/v1/upz/tasks` УПЗ-адаптера с телом:

```json
{
  "taskType": "KOMPLEKT",
  "vspCode": "1234/0567",
  "dueDate": "2026-11-10"
}
```

5. Ответ УПЗ приходит асинхронно (раздел 3.1).

### 2.2 Шедулер закрытия регулярных задач

Запускается ежедневно в 23:00. Закрывает регулярные задачи типов `KOMPLEKT` (Укомплектование),
`REGISTRATION` (Регистрация) и `TP_RECEIVE` (Приём транспортных упаковок), срок которых истёк, и
выполняет санацию задач, оставшихся без исполнителя.

```sql
UPDATE task
   SET status = 'CLOSED', closed_at = now()
 WHERE type IN ('KOMPLEKT', 'REGISTRATION', 'TP_RECEIVE')
   AND status <> 'CLOSED'
   AND due_date < now();
```

Для каждой закрытой задачи запускается отправка события о закрытии задачи (раздел 3.2).

### 2.3 Шедулер формирования задачи передачи упаковок в СЦ-архив

Запускается каждый час. Это системная задача: формирует задачи с типом `SC_ARCHIVE` (Передача упаковок в
СЦ-архив) для ВСП, где накопились упаковки к передаче.

1. Запустить «Алгоритм балансировки упаковок» (раздел 5) и получить набор упаковок по ВСП.
2. Для каждого ВСП с непустым набором сформировать задачу `SC_ARCHIVE` и заполнить атрибуты по набору
   «Динамические атрибуты передачи в СЦ-архив» (раздел 6.2).
3. Создать задачу в УПЗ вызовом `POST /api/v1/upz/tasks` УПЗ-адаптера.

### 2.4 Шедулер закрытия задачи передачи упаковок в СЦ-архив

Запускается каждые 15 минут. Для каждой открытой задачи `SC_ARCHIVE` запрашивает у РМОЦ состояние
упаковок вызовом `GET /rmoc/packages` rmoc-service. Если все упаковки задачи приняты СЦ-архивом,
закрывает задачу передачи упаковок в СЦ-архив и сохраняет дату приёма в атрибут `acceptedAt` набора
«Динамические атрибуты передачи в СЦ-архив».

## 3. Kafka

### 3.1 Обработка ответа УПЗ о создании задачи

Сервис читает топик `pprbkid.upz.task.response.v1`. Сообщение:

```json
{
  "requestId": "c1f0…",
  "upzTaskId": 98765,
  "status": "CREATED"
}
```

При `status = CREATED` сохраняет `upzTaskId` в задаче; при `status = REJECTED` переводит задачу в статус
`ERROR` и пишет причину в журнал задачи.

### 3.2 Отправка события о закрытии задачи

Сообщение публикуется в топик `pprbkid.task.closed.v1` после закрытия задачи:

```json
{
  "taskId": "…",
  "type": "KOMPLEKT",
  "closedAt": "2026-11-05T23:00:12Z"
}
```

## 4. REST API

### 4.1 GET /api/v1/tasks — список задач сотрудника

| параметр | тип | обязательный | описание |
|---|---|---|---|
| employeeId | string | да | табельный номер сотрудника |
| status | string | нет | фильтр по статусу задачи |

Ответ `200` — массив задач `{id, type, status, dueDate}`.

### 4.2 POST /api/v1/tasks/{id}/complete — завершение задачи

Переводит задачу в статус `DONE`. Для задачи типа `SC_ARCHIVE` перед завершением вызывает
`POST /rmoc/packages/transfer` rmoc-service, чтобы зафиксировать передачу упаковок.

Ответ `200` — задача; `409` — задача уже закрыта.

## 5. Алгоритм балансировки упаковок

Упаковки распределяются по ВСП так, чтобы одна задача передачи включала не больше 20 упаковок.

1. Выбрать упаковки со статусом «К передаче в архив».
2. Сгруппировать по ВСП и разбить группы по 20 упаковок.
3. Если упаковка помечена как ручная, [формируем ручную заявку](#ручная-заявка).

### 5.1 Ручная заявка

Ручная заявка создаётся на каждую упаковку с пометкой «ручная» и включается в задачу передачи отдельной
строкой.

## 6. Динамические атрибуты

### 6.1 Динамические атрибуты укомплектования

| атрибут | тип | описание |
|---|---|---|
| vspCode | string | код ВСП |
| scheduleId | string | идентификатор графика укомплектования |
| itemsTotal | integer | число позиций к укомплектованию |

### 6.2 Динамические атрибуты передачи в СЦ-архив

| атрибут | тип | описание |
|---|---|---|
| vspCode | string | код ВСП |
| packages | array | идентификаторы упаковок к передаче |
| acceptedAt | datetime | дата приёма упаковок СЦ-архивом |
