# Руководство аналитика: граф спецификации в Obsidian

Граф собран из плоской спеки: каждый раздел стал небольшой заметкой, а заметки связаны между собой.
Текст спеки перенесён **дословно**, ничего не пересказано, кроме карточки бизнес-операции, и у неё
каждое утверждение ссылается на свой абзац. Связи подтверждены цитатой из спеки.

## 1. Как открыть

1. Obsidian → *Open folder as vault* → каталог графа в репо (по умолчанию `docs/graph`).
2. Начните с заметки **`_graph/Начало`**. Там бизнес-процессы, бизнес-операции (сколько шедулеров их
   формируют и закрывают, есть ли UI), сервисы, легенда цветов и смысл ключей связей.
3. *Graph view* (Ctrl/Cmd+G) — вся сеть. Цвет узла — его вид (легенда в «Начале»): операции, шедулеры,
   UI, эндпойнты, Kafka, топики, данные, сервисы, внешние системы.
4. Виды-таблицы — `_graph/views/`: «Бизнес-операции», «Шедулеры», «Эндпойнты по сервисам», «Kafka». Если
   в Obsidian включён плагин **Bases**, это живые таблицы `.base`, иначе — Markdown-заметки с теми же
   таблицами. Они пересобираются при каждой проверке графа.

## 2. Как устроена заметка

Сверху — **свойства** (Properties): вид узла и его связи. Ссылки кликаются.

| свойство | что значит | у кого |
|---|---|---|
| `created_by` / `closed_by` | кто формирует / закрывает задачу | у бизнес-операции |
| `screens` | экраны (UI) задачи | у бизнес-операции |
| `related` | связанные бизнес-операции | у бизнес-операции |
| `creates_task` / `closes_task` | какие задачи формирует / закрывает | у шедулера, эндпойнта, Kafka-операции |
| `ui_of` | для какой задачи экран | у экрана |
| `calls` / `called_by` | вызывает / кто вызывает | эндпойнты, шедулеры, экраны |
| `publishes_to` / `consumers` / `publishers` | Kafka: кто публикует в топик и кто читает | Kafka-операции, топики |
| `belongs_to` / `operations` | принадлежность сервису | эндпойнты, шедулеры… / сервис |

Полный список ключей — в легенде «Начала».

Ниже — тело:
- **`graph:source`** — текст спеки дословно, с указанием файла;
- **`graph:card`** (у бизнес-операции) — «для чего / когда / что выполнить / результат», у каждого
  утверждения ссылка на абзац (`↗ …#5`);
- **`graph:edges`** — таблица оснований: связь, цель, цитата, откуда (правило, модель или «внесено человеком»);
- **`graph:toc`** (у сервиса) — его операции по видам.

## 3. Три прогулки

Это переходы из постановки задачи. В графе-образце (синтетика) они выглядят так.

**Прогулка 1. Общий шедулер.**
1. Откройте **«Укомплектование»**.
2. Свойство `closed_by` → **«Шедулер закрытия регулярных задач»**.
3. У шедулера `closes_task` — три операции: «Укомплектование», «Регистрация», «Приём транспортных
   упаковок». Это один общий шедулер, а не три копии.
4. Откройте **«Регистрация»** → `screens` → **«UI регистрации»**.
5. У экрана `calls` → эндпойнт **«task-service GET api-v1-tasks»** → `belongs_to` → сервис **task-service**.

**Прогулка 2. Своя цепочка.**
1. Откройте **«Передача упаковок в СЦ-архив»**.
2. `created_by` и `closed_by` ведут к её **собственным** шедулерам: «формирования…» и «закрытия задачи
   передачи…». Они похожи на общий шедулер, но это отдельные узлы.
3. У шедулера формирования `invokes` → технические операции (алгоритм балансировки). У шедулера закрытия
   `calls` → эндпойнт rmoc-service.
4. `related` → **«Укомплектование»**: связь подтверждена цитатой (таблица оснований у «Передачи»).

**Прогулка 3. От сервиса к бизнесу.**
1. Откройте сервис **rmoc-service**: `operations` и оглавление — его эндпойнты.
2. Выберите **«rmoc-service POST rmoc-packages-transfer»** → `called_by` → **«UI передачи упаковок»**.
3. У экрана `ui_of` → бизнес-операция **«Передача упаковок в СЦ-архив»**.

Ту же навигацию без кликов делает агент: «кто закрывает Регистрацию», «как связаны rmoc-service и
Укомплектование», «что затронет изменение эндпойнта» — это вопросы к `/graph` в режиме вопросов.

## 4. Что можно править руками

**Можно:**
- **Прозу вне маркеров** — пояснения, комментарии, ссылки: дописывайте в любом месте заметки вне блоков
  `<!-- graph:… -->`. Граф их не трогает.
- **Прямые связи в Properties** — добавить ссылку в `closes_task`, `calls`, `related` и т. п. При следующей
  синхронизации связь станет «внесено человеком» в таблице оснований, а обратная сторона появится сама.
- **Убрать связь в Properties** — граф поймёт, что вы её отклонили, и больше не предложит.
- **Флаги «так задумано»** — свойства `system: true` (операция без UI), `public: true` (эндпойнт без
  вызывающих внутри), `external_side: true` (другую сторону топика держит внешний контрагент). Снимают
  соответствующую «дыру» из отчёта.

**Нельзя (перезапишется):**
- содержимое блоков `graph:*` — это перенос спеки и вычисленные разделы;
- **обратные** ключи (`closed_by`, `screens`, `called_by`, `operations`…) — они выводятся из прямых. Правьте
  прямую связь у владельца: у шедулера `closes_task`, а не у операции `closed_by`;
- создавать новые заметки-узлы руками — новый узел появляется через каталог при следующем прогоне `/graph`.

## 5. Как читать отчёты (`_graph/`)

- **`catalog.md`** — каталог узлов до нарезки: что станет заметками, пары «это один узел?», противоречия,
  scope. Утверждаете его вы (первый шаг).
- **`edges-review.md`** — связи по бизнес-операциям: кто формирует, закрывает, где UI, межсервисные вызовы,
  сомнительные связи (с цитатой), отклонённое, вопросы, новые узлы раскладки. Утверждаете вы (второй шаг).
- **`report.md`** — проверка графа: ошибки (`E-…`) и предупреждения (`W-…`), раздел **«Дыры графа»** по
  операциям (у операции нет шедулера закрытия, у топика нет читателя…) и раздел **«Перенос исходников»**.
- **`open-questions.md`** — вопросы к вам: чего спека не говорит. Ответ — правка спеки или свойство-флаг;
  следующая проверка уберёт закрытый вопрос сама.
- **`unplaced.md`** — фрагменты спеки, которым не нашлось узла (дословно). Решите, куда они относятся.

## 6. Когда можно удалять плоскую спеку

Только после приёмки графа (третий шаг, `/graph` спросит) и только файлы, у которых в `report.md`, разделе
**«Перенос исходников»** стоит **«перенесён полностью»**. Удаляете вы сами — конвейер исходники не трогает.
После удаления проверка покажет `W-source-missing`. Это не ошибка: текст уже лежит в заметках.
