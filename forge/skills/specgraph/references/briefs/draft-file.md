# Бриф: черновой каталог узлов файла (разведка, единица draft-file)

Ты получаешь ОДИН файл спеки — только его оглавление и кандидатов, найденных правилами. Текста разделов
нет и не нужно. Твоя задача: сказать, какие узлы графа описаны в этом файле. Сдай ответ инструментом
`graph_draft_put` с `item_id` из задания.

## Что такое узел

Одна самостоятельная функциональная операция — один узел. Виды узлов:

- `service` — сервис (общее описание файла сервиса);
- `endpoint` — одна REST-операция: имя `<сервис> <METHOD> <путь-через-дефисы>`, key `http:<METHOD> <путь>`;
- `scheduler` — шедулер, фоновый процесс по расписанию;
- `kafka-op` — Kafka-операция: `role: consume` (обработка сообщения из топика) или `role: publish`
  (отправка в топик отдельным разделом);
- `algorithm` — самостоятельный алгоритм, который запускают другие операции;
- `topic` — Kafka-топик: имя как в спеке, key `kafka:<имя>`;
- `data` — данные: `subkind: attributes` (динамические атрибуты), `table`, `dto`, `enum`;
- `operation` — бизнес-операция (тип задачи), key `task:<КОД>`, если код назван;
- `screen` — экран UI; `external` — внешняя система; `process` — бизнес-процесс.

## Правила

0. «Узлы правил» в задании уже в каталоге (эндпойнты, топики, сервис, операции по коду, таблицы из SQL) —
   не повторяй их и не отклоняй; называй их этими именами, если на них ссылаешься.
1. Каждого кандидата из списка «Кандидаты экстракторов» учти: либо узел в `nodes`, либо в `not_nodes` с
   причиной (`{candidate, reason}`; если это вид, которого нет в списке выше, добавь `suggested_kind`).
2. Кандидат уже правильный — перенеси его как есть: тот же вид, имя, key, сервис.
3. Узел, который есть в «Именах кандидатов всего корпуса», называй ТЕМ ЖЕ именем — это один узел
   (например, общий шедулер, который закрывает задачи нескольких типов). Исключение — общий заголовок
   шаблона спеки («Алгоритм обработки», «UI-UX Описание»): это не имя, назови узел по тому, что он
   описывает в ЭТОМ файле («Алгоритм обработки изъятия ИД», «UI Изъятие документов»).
4. Похожие имена — не повод склеивать: «закрытие регулярных задач» и «закрытие задачи передачи» — два узла.
5. Групповой заголовок («Шедулеры», «REST API», «Kafka») — не узел. Подраздел алгоритма («Ручная заявка»
   внутри «Алгоритма …») — не узел, это часть алгоритма.
6. Если в оглавлении есть самостоятельная операция без кандидата — добавь её узлом и объясни в `why`.
   Крупный раздел без узла движок назовёт отказом `E-draft-uncovered`: добавь узел или запиши раздел в
   `not_nodes` как `{section: "<id раздела>", reason}` (например «описание модели данных», «история
   изменений»).
7. В `sections` перечисли id разделов узла (из оглавления). У видов, принадлежащих сервису (endpoint,
   scheduler, kafka-op, algorithm), обязателен `service`.
8. В строках нет обратных слэшей и управляющих символов. Имена — без `/ \ : # ^ [ ] | " * ? < >`, без точки в конце.

## Формат ответа

```
graph_draft_put(item_id="…", nodes=[
  {"kind": "scheduler", "name": "Шедулер закрытия регулярных задач", "service": "task-service",
   "sections": ["…#17"], "confidence": "high", "why": "заголовок раздела"}
], not_nodes=[
  {"candidate": "…", "reason": "групповой заголовок"}
])
```

Отказ инструмента — исправь названное в ошибке и сдай заново (три отказа — единица уходит человеку).
