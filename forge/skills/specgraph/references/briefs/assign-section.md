# Бриф: раскладка блоков по узлам (единица assign-section)

Ты получаешь кусок ОДНОГО файла спеки: блоки с id и дословным текстом, а также список утверждённых
человеком узлов этого файла. Реши для каждого блока, к какому узлу он относится. Текст не переписывай —
его перенесёт скрипт байт в байт. Сдай ответ инструментом `graph_assign_put` с `item_id` из задания.

## Правила

1. Каждый блок назначь РОВНО один раз: в `assign` (к узлу), в `skip` или в `unplaced`.
2. Раздел операции (заголовок шедулера, эндпойнта, обработчика, алгоритма и всё под ним до следующего
   такого же заголовка) — к узлу этой операции. Подраздел алгоритма — к алгоритму.
3. Общее описание сервиса, групповые заголовки («Шедулеры», «REST API»), «См. также» — к узлу сервиса.
4. Текст про несколько операций сразу — к одному узлу (сервису или общему алгоритму), не дублируй.
5. `skip` — только `reason: toc` (оглавление, заголовок без своего узла), `boilerplate` (шаблонный текст)
   или `duplicate-of` с `of: [id блоков]` — для ДОСЛОВНОГО повтора уже размещённого текста.
6. `unplaced` — блок, которому нет узла; если по смыслу это новый вид (RabbitMQ, файловый обмен…),
   добавь `suggested_kind`.
7. Самостоятельная операция без узла в каталоге — `new_nodes` с видом, именем, сервисом и `why`; её
   блоки назначь на её имя. Человек решит по ней в отчёте связей.
8. В строках нет обратных слэшей и управляющих символов.

## Формат ответа

```
graph_assign_put(item_id="…",
  assign=[{"node": "Шедулер закрытия регулярных задач", "blocks": ["…#17", "…#18"]}],
  skip=[{"blocks": ["…#1"], "reason": "toc"}],
  unplaced=[], new_nodes=[])
```

Отказ инструмента называет блоки и причину — исправь и сдай заново (три отказа — единица уходит
человеку).

## Последняя строка ответа

После того как инструмент принял результат, закончи ответ ОДНОЙ строкой JSON — по ней forge видит, что шаг шёл через субагента (шаг она не закрывает):

```
{"step_id": "graph-map", "status": "unit"}
```
