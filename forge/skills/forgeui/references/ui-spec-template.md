# Шаблон фронт-спеки стори — `ui-spec.md`

Фронт-спека описывает **поведение** экранов фронт-части стори: какие кадры, откуда данные,
какие состояния, события, валидации и сценарии. Как экран **выглядит** (размеры, цвета, отступы,
шрифты) спека не описывает — это берётся из макета движком, числа с картинки не переписываются.

Тот же документ читают ревьюер (утверждает его) и движок forge-ui (`daiver_spec`): кадры → вход
`ui-design`, «Данные» → вход сборки, «Сценарии» → e2e-тесты. Гейт — `check_ui_spec.py`.

## Правила

1. **Кадры и ссылки на макеты не выдумываются.** Только из Jira или от пользователя. Нет ссылки —
   верни вопрос в `pending_questions`, а не пиши правдоподобный URL.
2. **Каждый раздел логики заполнен или явно «нет».** Пустой раздел гейт не пропустит; «нет» —
   законный ответ (презентационный экран без логики — нормальный исход).
3. **«Данные» называют источник:** реальные пути во фронт-репо в бэктиках —
   `types: \`src/shared/api/x.ts\``, `client: \`src/shared/api/x-client.ts\`` — или явно «моки»
   (экран строится на моках, к API подключается позже). Тип и клиент не изобретаются; путь, которого
   ещё нет, — предупреждение гейта: если к сборке не появится, упадёт компиляция.
4. **Сценарии** — Given/When/Then (или Дано/Когда/Тогда), одной строкой или блоком, по одному на
   поведение. Каждый станет e2e-тестом с id `ui-spec#<n>`; формулируй проверяемо — что видно на
   экране, а не «работает корректно».
5. **Бэк-часть:** «нет» или «есть: <KEY>». API, которого нет на бэке, здесь не проектируется — это
   бэк-спека (`sdd.md` §5); фронт-спека ссылается на него.
6. Инструкции шаблона — в HTML-комментариях `<!-- -->`; гейт и движок их не читают. Удаляй их или
   оставляй — на результат не влияет.
