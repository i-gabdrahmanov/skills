Убирает доки ЗАВЕРШЁННОЙ фичи из `docs/feature-pipeline/` в `docs/archive/`, сохраняя путь
(у фикса — `<стори>/fixes/<баг>`). Скрипт сам разбирает подкоманду и аргументы, тебе парсить
их не нужно.

Выполни в корне проекта:

```bash
python3 .gigacode/skills/pipeline-state/scripts/archive.py --project . {{args}}
```

Если аргумент пуст — выполни `status`.

Дальше:
- Покажи вывод скрипта пользователю **как есть**, не пересказывая своими словами.
- Слаг сам не угадывай: `status` показывает, что готово к архивации. Дельту фикса зовут ключом
  бага (`put BUG-512`), хотя лежит она внутри стори — скрипт принимает короткое имя, пока оно
  однозначно, и сам просит полный слаг при совпадении в нескольких стори.
- Обычно архивация происходит сама, по успеху `/forge-merge`. Эта команда нужна, когда у фичи
  нет дельты (мастер выключен, фикс без правки спеки), когда архивируют задним числом или
  когда нужен `restore`.
- Код exit 3 — не ошибка, а «нужно решение»: слаг неоднозначен либо фича есть в нескольких
  namespace. Покажи варианты и спроси, сам не выбирай.
- Код exit 2 — отказ гейта (`[archive] DENY: …`): стройка не завершена, внутри идёт живой
  прогон, или дельта не сведена с мастером. Покажи причину и остановись — гейт снимается только
  явным `--force --reason '<почему>'` по просьбе пользователя, сам его не подставляй.
- Стейт прогона (`ground/statements/…`) архивация не трогает: убираются только доки.
- Ничего не коммить и не пушить: forge пишет только в рабочее дерево, коммит делает пользователь.
