Работа с требованиями-мастером идёт через один скрипт — он сам разбирает подкоманду и аргументы,
тебе парсить их не нужно.

Выполни в корне проекта (`--project-root` — корень репозитория кода):

```bash
python3 .gigacode/skills/system-analyst/scripts/spec_cli.py --project-root . {{args}}
```

Если аргумент пуст — выполни `status`.

**Мастер в отдельном репо** (`docs.master.mode = separate-repo`): вместо shell — MCP-инструменты
`forge-master` (`master_research`, `master_map_edit`, `master_map_confirm`, `master_status`,
`master_diff`, `master_merge`, `master_read`). Рантайм не пускает Edit и shell за пределы
каталога проекта. Инструментов нет или вызов отклонён — стоп и отчёт (чинится
`bash .gigacode/deploy-local.sh` + перезапуск сессии). Обходных путей записи не ищи, своих
обёрток и серверов не собирай.

Дальше:
- Покажи вывод скрипта пользователю **как есть**, не пересказывая своими словами.
- Ничего не коммить и не пушить: forge пишет только в рабочее дерево, коммит мастер-репо делает
  пользователь сам.
- Код exit 3 — не ошибка, а «нужно решение»; отчёт сам печатает варианты. Карта не снята или
  не подтверждена (`no-map`), не выбран сервис дельты (`no-capability`), в мастере нет раздела
  требований (`no-section`), у требования совпало название, но изменилось содержимое (операция
  `~`: `merge <slug> --allow-modify` целиком либо `--modify <ID>` точечно). Покажи варианты и
  спроси. Сам за пользователя не выбирай.
- Флаг `merge <slug> --master-first` переключает команду со слияния на СВЕРКУ: мастер ведёт
  аналитик, `merge` его не дописывает, а сверяет с ним дельту, и exit 3 означает РАСХОЖДЕНИЕ
  (дельту приводят к мастеру, а не наоборот). Настройки проекта у режима нет — только флаг,
  и он ставится на одну команду.
- `merge` печатает отчёт в любом режиме: помнит ли мастер эту задачу (до и после записи), что
  стало с мастером, уехали ли доки. Показывай отчёт как есть.
- По успеху `merge` доки сведённой фичи уезжают в `docs/archive/` (`--no-archive` отключает);
  разбор архива — `/forge-archive`.
- Код exit 2 — ошибка (нет дельты, не резолвится мастер, гейт состава не прошёл): покажи причину
  из вывода и остановись.
- **`research`** — СТРУКТУРА мастера: какие сервисы, где чей файл, какой формы. Результат —
  карта `ground/spec-map.json` (черновик); в мастер скрипт не пишет. Покажи карту как есть и
  спроси пользователя, верна ли она. Правки — по его словам: `--set <сервис>=<путь>` (другой файл
  сервиса), `--ignore <путь>` (не мастер), `--map-module <модуль>=<сервис>` (по модулю кода
  определяется сервис дельты). Подтверждение — `--confirm`, **только после явного «да»**.
  `--refresh` — скан с нуля (ручные правки сбрасываются), `--capability X` — пересканировать один
  сервис.
- Без подтверждённой карты `merge`/`diff` работают только с однозначным мастером (в базе нет
  ничего, кроме настроенного пути). Иначе — exit 3 `no-map`: веди на `research`. Не подкручивай
  вместо этого `docs.master.spec_path` / `spec.grammar.*` через `config.py` — путь и форму каждого
  сервиса держит карта.
- Мастер сервиса — проза без требований (API-дока): карта помечает его `prose`. Требования фич
  пишутся форже-блоками в отдельный раздел в конце файла. Раздела нет — `merge` отвечает
  `no-section` и предлагает `--ensure-sections`. Предложи, сам не применяй.
- Если `merge`/`diff` пишут «формат требований-мастера не описан профилем» (exit 3) — это НЕ
  повод дописывать мастер: движок остановился, чтобы не записать в чужой документ свои блоки.
  Веди на `research`, а при непонятной форме — на субагента-ресерчера
  (`analyze_spec.py --apply-research`).
- Дельта ФИКСА лежит внутри папки своей стори, поэтому её слаг — `<стори>/fixes/<баг>`
  (напр. `STOR-100/fixes/BUG-512`). Короткого ключа бага достаточно, пока он однозначен; при
  совпадении в нескольких стори скрипт попросит полный слаг. В мастере такая правка помечается
  провенансом `[from: <стори> fix/<баг>]` — требование остаётся за стори.
- Мастер не заведён и `docs.master.enabled=false` — скажи, что требования-мастер выключен, и что
  включается он в `ground/policy.json` (`docs.master.enabled`, расположение — `docs.master.*`,
  поведение — блок `spec`). Через CLI: `config.py set master.enabled true`.
